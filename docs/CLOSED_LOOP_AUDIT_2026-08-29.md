目标：普通用户应能在 App 内完成安装、配置、执行、取消、纠错、验证、查看结果和恢复，不依赖 PowerShell、手工编辑 JSON、固定磁盘路径或开发工具。

## 已闭环

- 图片来源添加、索引、取消、进度和失败反馈。
- 浏览、搜索、筛选、标签、相册、重复审阅、安全删除和缺失文件恢复。
- 人脸扫描、候选分组、命名、逐脸纠错、人物合并、人物照片时间/场景分组。
- SFace 阈值标定、按模型保存并应用到人物自动匹配；YuNet 人工真值录入和漏检评估。
- 云端照片分析的授权、凭据、预算、确认、任务状态、失败重试和建议接受/拒绝。
- 自包含发布：.NET 运行时、OpenCV 原生库、YuNet、SFace、Chinese-CLIP、FFmpeg、whisper.cpp 和 Whisper 模型随 win-x64 发布包提供；构建前后执行固定 SHA-256、大小和许可证门禁，App 内可做完整校验和实际加载自检。
- 存储与 WebDAV：App 内配置本地/WebDAV、基础路径、连接测试、缓存目录和 1–1000 GB 容量；保存后立即应用。WebDAV 密码使用 Windows 凭据管理器，旧 JSON 明文密码在启动时自动迁移并清除。
- 中文语义检索：App 内建立/续建并取消本地 Chinese-CLIP 向量索引；按文件大小和修改时间自动复用未变化照片。支持中文 Top-20 查询、结果相似度解释、逐项相关性标注、Precision@20，以及填写已知相关总数后的 Recall@20；评估记录持久化到数据库 v15。
- 数据保护与迁移：App 内创建包含数据库与非敏感设置的一致性备份；恢复前校验格式、版本、路径和 SQLite 完整性，重启后覆盖前自动保留恢复快照。可查看数据库、缩略图、视频/远程缓存及随包模型占用，并将数据复制迁移到用户选择的空目录；原目录保留以便回滚。
- Florence-2 本地推理与运行验证：随包提供固定提交的 `Florence-2-base-ft` INT8 模型、DirectML 运行库和许可证；App 内可取消地验证 CPU/DirectML 的模型加载与视觉编码冷/热态推理。支持选择图片后完全离线执行简短描述、详细描述和 OCR，自回归解码与 BPE 文本均在进程内完成。可录入期望文字与准确度，质量记录只保存图片 SHA-256，不保存敏感路径。
- Florence 批量闭环：App 内对已索引图片分批生成描述/OCR，限制单次数量、显示当前文件、可取消和续跑；结果先保存为待审阅，用户接受后才进入主搜索，拒绝结果在源文件或模型未变化时不会反复生成。数据库升级至 v16。
- 未分类时间场景闭环：目录树右键对一个未分类时间段进行二次时间聚类（最多 5 组），按均值位置从前、中、后最多选 3 组并取各组第一张代表照片；已有单张云端描述直接复用，缺失项才调用 API。用户审核整组总结后写入数据库 v17，覆盖目录树名称并把场景名称、摘要和搜索词关联到组内全部照片的主搜索；单张已有描述同时显示在选中照片信息区。

## 仍需开发

### P1：Florence-2 与 DirectML 验证闭环

- 已完成 INT8 CPU/DirectML 实际加载、首张/热态耗时、工作集变化、自动选择、自回归描述/OCR 和质量标注。
- 已完成多图片批量队列、人工接受/拒绝和主搜索接入。
- FP16/INT4 不随正式包重复携带；如要比较，需先解决额外约 500 MB 模型体积和 INT4/DirectML 算子兼容性，再决定是否成为可选组件。

### P2：报告与诊断

- 从 UI 导出 SFace/YuNet/CLIP/Florence 验证报告（JSON/CSV），不包含原图或敏感路径作为默认行为。
- 提供脱敏诊断包、日志查看、缓存检查/清理和性能基线入口。
- 将当前 CLI 性能工具保留为高级模式，但常用健康检查可由 App 发起并解释结果。

完成状态（2026-08-29）：上述常用能力已集成到 App“诊断中心”。用户可在 UI 中执行运行组件完整性检查、数据库快速检查和汇总统计，导出不含原图路径的 JSON/CSV 报告，或生成经过令牌、密码、授权头与本机路径脱敏的诊断 ZIP。缩略图、人脸缩略图及远程缓存采用明确白名单和二次确认清理；模型与视频关键帧只展示占用，不允许从此入口误删。

## 当前结论

正式发布所需的安装、配置、索引、识别、人工纠错、模型验证、批量推理、结果审核、备份恢复和诊断维护均已有 App UI 闭环，不要求用户运行脚本、安装 Python/.NET/FFmpeg 或手工编辑配置。CLI 仅保留给开发与高级性能分析，不是产品正常运行依赖。

补充发布审计：视频工具定位已移除开发机固定磁盘路径回退，正式运行优先且默认只使用发布目录内的 FFmpeg；`PICER_FFMPEG_PATH` 仅作为显式测试/高级覆盖。仓库已增加本地凭据、数据库、日志、缓存、构建与测试产物的忽略规则，避免机器状态或密钥进入源码提交。

补充首次运行审计：主窗口完成初始化后自动执行随包组件存在性预检，缺失时在状态栏给出数量、组件名称和 UI 修复入口；完整哈希与实际加载仍由用户在“运行组件”或“诊断中心”发起，避免拖慢正常启动。照片、视频及任务中心的系统打开/定位失败均改为可见反馈。

## 推荐顺序

1. Florence-2/DirectML 验证与自动选择，并将选定模型加入自包含运行清单。
2. 报告导出、脱敏诊断包与缓存健康管理。
