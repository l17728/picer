# 分类删除的发布顺序与首次上传

状态：schema80 开发验证通过，协议仍为 9，尚未发布部署。完整目录删除的网络入口、生命周期收尾与冲突交互仍在开发。

## 首次上传期间的删除

旧实现按批次发送时才分配分类、照片及视频的同步身份。用户在首批目录数据上传后删除标签或相册时，后续照片可能还没有身份，删除事务无法捕获其关系。

现在从已经按授权范围过滤的数据库快照中，一次性预留标签、相册、人物、照片和视频身份。预留事务核对实时数据库的媒体与元数据版本；快照准备期间发生变化时丢弃该临时快照并重试，不发送过期快照。预留仅涉及 SQLite 索引，不读取原始媒体，不预留被排除目录的身份。

## 删除发送的版本约束

删除标签、删除相册及人物合并在同一业务事务结尾封存最终元数据版本和捕获的媒体关系数。待发送查询可要求来源已上传版本覆盖这个版本，避免人物的新归属尚未发送就先删除旧归属。后续独立编辑不改变已经封存的等待目标。

旧库记录缺少发布依据时保持空值；迁移不猜测、不自动补造。已执行的关联删除在回执中保存实际生成的解除关联操作 ID，业务关系和回执仍同事务提交。这些 ID 不包含人物姓名、路径或嵌入。
