# 多空间部署备份与离线迁移

2026-10-27。此记录描述待发布源码的升级保护，不代表生产已经更新。

## 修复的问题

旧 Linux 部署脚本只复制根目录 `picer.db`。账号模式实际将控制库放在 `accounts-v2/control/control.db`，每个空间索引位于 `accounts-v2/spaces/<空间 ID>/picer.db`。仅检查公共健康接口也不能证明尚未打开的空间完成了迁移。

新版脚本在停止主服务、健康检查和声明的额外写入服务后，检查所有库的打开句柄并持有文件锁，备份根索引、全部空间索引、控制库及各自 WAL/SHM。快照附逐文件 SHA-256 清单；迁移前检查剩余空间、未完成迁移记录和路径符号链接。

替换程序后先运行 `Picer.IndexService --prepare-index-upgrade`，在账号运行锁保护下迁移全部已有索引并执行 `quick_check`，随后才启动公网监听和版本/健康检查。沿用数据库自身的关闭写入、整文件备份和分阶段迁移机制。命令只输出数量和 schema，不输出账号、媒体或凭据。

## 回滚边界

升级失败时先停止所有声明的写入服务，再校验完整快照。自动恢复全部已有媒体索引及旧可执行程序；控制库保留最新状态，避免回滚改密、设备撤销或注册记录。控制库 schema 改变、空间集合增加/减少、快照哈希不一致时不自动回滚，而是保持服务停止并保留备份以供人工恢复。

外部 RestoreGuard 不进入快照，也不回退删除 epoch。失败迁移的 pending 标记移至快照目录，保留诊断证据。操作索引和部署文件不会修改原始照片或视频。

## 验证

- Windows 严格构建：零警告、零错误。
- 离线升级入口测试 3/3：根库及多个空间、活动账号进程互斥、未完成迁移阻断。
- 真实 Linux 临时目录测试 5/5：多库恢复、保留认证状态及外部 guard、快照损坏拒绝恢复、新增空间拒绝自动回滚、符号链接/越界及打开句柄拒绝。测试不操作生产数据库。
- Linux 脚本语法检查通过；CI 新增独立 Ubuntu 部署安全测试任务。
