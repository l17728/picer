# 缩略图实时诊断与分段日志

## 现场证据

2026-10-30 本地正在运行的 GUI 未被重启。账户空间缓存目录抽样有 896 个 JPG、无残留 part 文件；这不是精确的照片覆盖率。目录预取只处理可视区域及附近项目，附近项目加载完毕即停止，不会自动补齐全部 8603 张照片。

历史日志出现 75 次缩略图 HttpRequestException。三个失败媒体 ID 的只读复测均为 HTTP 200，分别约 8.805、4.811、4.122 秒；这只能证明复测时可读取，不能证明历史失败原因。另一屏 30 张照片抽查均有磁盘缓存；尚不能据此断定实际渲染已经完成。

当天 `OpenThumbnailAsync` 重试日志统计为 HTTP 503 共 303 次、HTTP 429 共 6 次。这是重试事件数，不是独立失败媒体数。现有错误信息不足以进一步判断代理离线、槽位饱和、超时各自占比；不应直接扩大并发。

## 实现

- GUI 先查持久缓存，缓存命中使用独立的 4 槽解码队列，避免排在网络请求后面。
- 以合法 GUID 关联 GUI、HTTP 客户端、账户网关、IndexService、MediaAgent。记录组件、媒体 ID、阶段、累计/分段毫秒、字节数、HTTP 状态、异常类型和 HRESULT，不记录路径、令牌、人物或问题文本。
- 阶段覆盖磁盘命中、排队准入、HTTP 响应头、账户鉴权、空间运行时获取、源路由、服务缓存、代理连接、文件打开和身份验证、解码缩放、落盘以及界面属性通知。
- `display_notified` 仅表示 WPF 属性通知完成，不等于屏幕实际绘制完成。
- 日志复用容量 256 的非阻塞诊断队列；压力过大时允许丢弃，并报告丢弃数量。不能将缺少阶段记录直接判断为程序卡住。
- MediaAgent 新诊断日志位于其 TEMP 下的 `picer-media-agent-diagnostics/picer-日期.log`；GUI 和服务使用已有日志目录。新日志不替代代理原有连接日志。

## 判读与后续验证

按 `trace` 关联各进程，以各组件自身的单调时钟差值判断耗时；不同机器的绝对时间和嵌套阶段耗时不可直接相加。`admitted` 前的差值定位排队；`upstream_headers`/`headers` 对比代理读图和编码阶段定位等待；缓存命中后的解码/通知耗时定位 GUI 工作。

本次未增加全库后台下载，未调整授权，未重启当前 GUI 或服务。新日志必须在更新对应进程后才会生效；未取得新版本的真实跨进程采样前，不宣称已经确定网络与服务端各自占比。全库静默预取仍需独立的带宽、空间、失败重试和前台优先设计。
