# 本地与照片空间元数据双向同步 SDD

状态：定稿，作为实现基线。日期：2026-10-22。

## 1. 目标与边界

远程操作 GUI 和来源设备本地 GUI/索引程序，对同一来源照片或视频的索引元数据应表现为同一逻辑数据：双方修改均最终收敛。照片空间可同时汇总多个来源设备，但每台来源设备只能把属于自身已授权来源的数据同步到本地。同步只涉及索引和元数据，不传输或修改原始媒体。

“双向”指本地来源索引 ↔ 照片空间权威索引，不表示设备 A 与设备 B 互相复制媒体或私有索引。服务端汇总多个来源；设备端只物化其已绑定的来源范围。设备在本地另外加入的来源不因同属一个账户而上传，除非用户明确授权该来源。

## 2. 现状与缺口

1. 账号空间 `SpaceSyncPublisher` 以 publisher/source binding 和稳定实体映射将选定来源发布到远程，但协议目前是发布方向；没有把服务端后续变更按来源回传给 publisher。
2. 上传的 `GatewayMetadata` 不含图片分类断言、拒绝记录、视觉概念旧投影、语义聚类成员和阈值设置。
3. 常规镜像有 media revision 与 metadata revision，但 metadata revision 只是全库计数；没有来源过滤的元数据变更游标。
4. 远程 GUI 对服务端库直接执行分类操作。对这些修改，来源机器没有 publisher-scoped 拉取通道。
5. 旧 IndexSyncClient 的部分镜像同步与账号 SpaceSync 是不同协议，不能将其中一种的镜像完整性推定为账号模式的双向一致性。

因此当前实现不是完全同步；数据库行号、全局 revision 或整库快照都不能单独作为多设备隔离依据。

## 3. 权威性和归属

### 3.1 来源归属

- 每个已绑定 source 由 `(space_id, publisher_id, local_source_id)` 唯一确定，服务端 `sync_source_bindings` 是授权归属依据。
- 每张图片/视频通过 publisher 的稳定 global identity 映射到服务端记录。同步载荷引用稳定实体身份，不用两端 SQLite ID 推断相同对象。
- 服务端只向拥有该 source binding 的 publisher 返回媒体记录和媒体附属元数据。未绑定、撤销、越权 source 一律拒绝。
- 同一文件在不同来源有多条引用时，引用仍各有 owner。若用户确认内容级决定可继承，则按规范化 SHA-256 在该来源的引用范围内传播；不因此向另一个 publisher 的本地库投递。

### 3.2 元数据分类

| 类别 | 同步规则 |
|---|---|
| 描述、媒体分析结果、图片视觉断言/用户确认/拒绝、人工更正、视频标签与分析 | 绑定到所属媒体身份，按 source owner 双向同步 |
| 照片引用的目录路径、源端文件事实 | 仅该来源 publisher 可写；远程人工操作不得更改原文件或源端事实 |
| 用户可编辑的人物、标签、相册及其媒体关联 | 通过 publisher-scoped 身份映射同步；关联只随该 publisher 所拥有的媒体关系投递 |
| 自动视觉聚类 | 聚类成员和生成结果按来源隔离；服务端不得用跨 publisher 混合聚类覆盖单一设备结果。可重算结果标记模型/算法版本 |
| 聚类阈值、分类开关等偏好 | 账号级偏好保存在服务端并同步到授权设备；本地设备特定的资源限制仍为本地设置 |
| 人物嵌入、训练工件、精确位置 | 继续遵循已有显式授权及隐私策略；默认不因本协议扩大共享范围 |
| 扫描游标、队列、缓存、临时文件 | 不同步 |

训练工件的来源归属补充（2026-10-27）：来源上传的工件，其远程应用通过已确认状态指纹与应用回执返回原来源。空间独立训练或混合来源的模型属于空间运行配置，不自动复制给来源电脑；该模型产生的媒体元数据仍按媒体归属同步。这一区分保持“来源之间不复制私有索引或聚合数据”的约束，不把模型运行环境等同于媒体元数据。实现和验证见[训练应用与来源回执](TRAINING_APPLICATION_SYNC_IMPLEMENTATION_2026-10-27.md)。

编辑者、来源设备、时间、操作 ID、版本信息作为审计/冲突所需元数据；不得日志记录凭据、人物姓名、嵌入或问题文本。

## 4. 一致性协议

采用 publisher-scoped、持久化的双向增量日志，不用全量反复比对作为正常同步路径。

客户端启动时执行一次 cold-start pass：第一次建立空间关系时完成完整 baseline；后续启动只续传 checkpoint 后的增量，不重新扫描全库。启动 pass 结束后不运行固定周期轮询。索引/描述/分类/人物等已提交的用户操作触发后台增量同步；另提供统一的“索引巡检、同步与修复”手动入口，用于立即执行一次空间同步、数据库完整性检查和缺失项报告。用户离线时操作先落入 outbox，下一次用户操作、手动巡检或应用启动再重试。

### 4.1 事件与版本

每个元数据变更写入事务性 `space_metadata_changes`（具体表名可在实现中调整）：`space_id, publisher_id, source_id, entity_kind, entity_global_id, field_or_concept, operation, payload, actor_kind, logical_version, operation_id, created_utc`。远程 GUI 修改时，服务端由被编辑实体的来源绑定确定 publisher/source，不接受客户端任意指定 owner。删除、撤销和拒绝使用最小 tombstone，保留足够版本防止旧副本复活；按保留期限压缩。

事件提交和业务行更新在同一数据库事务内。客户端通过 publisher 专属游标分页读取，按 operation id 幂等应用，只有整页事务成功后才推进 checkpoint。首次配对/旧版本升级走显式 baseline；增量期间游标过期返回 `baseline_required`，不得静默跳过。

本地写入也需形成可重试 outbox。远端确认后才推进上传游标。网络失败、进程退出和重复投递不丢更改、不重复造成副作用。

### 4.2 循环抑制

事件携带原始 operation ID、origin publisher 和因果版本。接收端应用远端事件时标记为 remote-apply；触发器不能再将同一事件当作新的本地编辑回推。后续用户编辑会产生新 operation ID。两个端点并发编辑同一字段时依据版本向量/服务端单调序号检测冲突，不用客户端墙钟时间做唯一排序。

### 4.3 冲突合并

- 不同字段可合并。
- 用户确认、纠正、拒绝优先于机器建议；机器重新分析不得复活用户拒绝或撤销。
- 用户对同一媒体同一分类的不同人工决定不可静默覆盖：保留冲突记录，服务端以最后接受的显式人工操作显示当前值，同时将冲突双方交给审核 UI；来源端与远端最终应用同一服务端裁决版本。
- 普通可重建的模型派生数据按 `(model, version, content identity)` 幂等替换；旧版本不会覆盖较新版本或人工决定。
- 分类撤回/删除由显式 tombstone 同步，不能靠“快照里没有该行”推断删除。

## 5. API 与数据模型

增加认证 API：publisher 读取增量变更页、提交本地 outbox 批次、确认游标/请求 baseline。路径延续 `/api/sync/v2` 版本化约定。所有请求验证当前 device grant、space、publisher、source binding 和 `index.read`/`index.write`；权限撤销立即停止后续拉取和推送。下行路由只能使用 grant 所属的 publisher，若 publisher 只允许子集，则服务端从实体映射和 source binding 反查并过滤；客户端不能以查询参数切换到其他 publisher。

分类载荷至少包括：媒体 global identity、内容哈希（可用时）、concept、source kind/version、assertion state、review state、confidence、可安全共享的 evidence fingerprint、创建/更新/审核版本；拒绝记录以稳定内容身份和 scope 表示，并作为独立显式事件同步，即使对应断言行已不存在也不得丢弃。`evidence_ref` 不含私密原文时才可传。聚类采用 publisher-local cluster UUID，成员引用该 publisher 的图片身份。服务端按 publisher/来源持久化，不把本地整数 cluster key 当全局 ID。

Schema 迁移增加按 publisher 的远端变更游标/outbox、水位和索引；`mirror_revision` 继续服务 GUI 缓存，不替代同步日志。迁移遵守现有完整数据库与 WAL/SHM 备份、恢复和 user_version 连续升级要求。

## 6. 删除、移动、撤权和重建

- 来源端媒体缺失先同步缺失状态/墓碑，不自动清理服务端记录；只有既有、明确授权的索引 purge 工作流能永久清理索引。
- 来源移动修复沿用 source binding/global identity，不重新创建不同身份；无法匹配的条目进入“已删除或移动”状态，用户确认后处理。
- 撤销设备后禁止其读写；其数据保留在空间，owner 可另行撤销来源或按现有清理流程 purge。
- baseline 重建按授权 publisher/source 精确替换范围，不能清理其他 publisher 数据。先建立临时快照并验证计数/哈希，再原子切换 checkpoint。

## 7. UX

- 设置/照片空间显示每个来源设备的同步状态：最近成功时间、待上传数、待下载数、冲突数、失败原因和“立即同步/重试”。不展示技术游标。
- 远程对某张照片做的分类确认/拒绝，提示“已保存到照片空间；来源设备将在下次同步时更新”。来源设备离线时显示待同步状态。
- 本地新增目录不会自动向远端上传；目录/来源授权 UI 明确显示将纳入哪个空间及照片/视频范围。
- 冲突审核显示照片预览、分类值、操作来源和时间，用户选择保留项后生成新的显式决议；机器建议冲突不打断浏览。
- 设备只展示其本地授权来源。远程照片空间可跨来源查看；本地库保持自身来源集合，不出现其他设备的目录或媒体。
- 同步故障不阻塞本地索引和 GUI 浏览；分类操作先持久化本端/服务端并进入 outbox，后台重试。

## 8. 性能与可靠性

按页读取，建议默认每页 200 个事件、载荷上限 8 MiB；压缩大 payload，二进制向量/大分析 JSON 遵循已有 opt-in。单 publisher 串行游标、不同 publisher 并发但限流。批次事务短小，UI 不等待整个同步完成。指数退避加抖动，重试只针对暂时错误；401/403 暂停并提示授权，baseline required 明确触发重建。

指标只记录 publisher 匿名 ID、批次条数、延时、重试数、错误码和游标差距，不记录个人内容。远程库高负载时响应 429/503 与 Retry-After，客户端保留队列。

## 9. 实施分段与验收

1. **基线与分类载荷**：确认 schema、身份、来源过滤；分类断言/拒绝/聚类纳入 publisher 初始发布和增量更新。
2. **远端到本地拉取**：按 publisher 提供变更日志/分页 API；本地身份映射应用，并验证媒体所有权。
3. **远程编辑入日志**：所有分类/元数据写 API 在业务事务中产生 owner-scoped 事件；覆盖 GUI 调用路径。
4. **冲突、删除、恢复、UX**：幂等/循环抑制/墓碑/baseline、冲突审阅和状态提示。

必须通过：

- A 本地改分类→远端→A 本地另一实例；远程 GUI 改分类→A 本地；最终状态一致。
- B 的照片/分类编辑对 A 的拉取恒不可见；A 的本地新目录未授权时远端不可见。
- 同内容多引用、相同 SQLite ID、图片移动、重复投递、分页中断、撤权、baseline 重置均不串数据、不丢用户决定。
- 用户拒绝在模型重算、双向重试和服务重启后仍有效。
- API 写入与变更事件原子；断网/崩溃后恢复，增量不扫描原始媒体、不重传不变媒体。
- 单元/集成/E2E 覆盖权限隔离、分类 UI 的待同步/冲突状态；完整 CI 严格构建通过。

## 10. 评审记录与决议

定稿前按六个视角审查：

- **架构**：确认复用 publisher/source binding 与稳定身份；将 publisher-scoped event log 作为双向通道，避免全库复制。
- **数据一致性**：确认事务性 outbox、幂等 operation ID、因果版本、tombstone、baseline 和循环抑制；拒绝用全量快照缺行表示删除。
- **安全/隐私**：每次拉取按设备授权和 publisher/source binding 双重校验；默认不扩大人物嵌入和精确位置共享；事件载荷与日志最小化。
- **可靠性/性能**：有界分页、checkpoint 后置、退避与断点恢复；本地操作不被网络同步阻塞。
- **分类领域**：用户确认/纠正/拒绝不能被机器重算覆盖；自动聚类按 publisher 隔离并可重算。
- **UX**：用户能看见来源授权、同步待办和可操作冲突，但不需要理解内部 revision/publisher 游标。

**定稿结论**：接受上述设计作为实现基线。代码评审必须重点验证 owner 来源由服务端解析、每条下行事件都经过 publisher/source 过滤，以及分类拒绝和用户决定在冲突中优先。实现完成后更新 `docs/SDD.md`、能力表和发布/迁移说明；生产启用前先在备份副本完成旧索引 baseline 与回滚演练。
