# 动态分类模型隔离修复

2026-10-23，开发验证中，未发布部署。

审查发现，动态聚类读取旧成员时没有按模型筛选，保存时又清除全部模型的聚类与断言；新聚类键只取照片 ID，导致另一模型处理相同照片时可能沿用旧键。虽然向量读取已限定模型，这些步骤仍可能混合不同模型的分组身份，或删除另一模型的结果。

修复将旧成员读取、断言清理和分组清理限定到当前模型；新分组键包含模型版本。同模型的已有分组继续沿用旧键，保持既有稳定分类行为。新增测试使用不同维数的两个模型处理同一组照片，验证分组键独立、重建不删除另一模型，以及清空一个模型结果时不影响另一个模型。

验证使用独立的 `artifacts/sync-cluster-build`；此时 `artifacts/sync-paging-build` 正在执行 schema67 视频身份与分页同步版本的整仓回归，二者不能混作同一测试结果。

分组隔离严格构建 0 警告、0 错误，`cluster-model-isolation-schema67.trx` 15/15 通过。

schema68 继续实现阈值配置与推荐缓存的模型隔离（待构建及验证）：每个模型有独立人工字段与因果版本；推荐缓存以模型和样本指纹为键，显式重建只使用指定模型的设置。窗口提交携带加载时的模型与字段版本；模型变更时提示重新加载并确认，不把旧设置应用到新模型。

旧设置只有在历史索引恰好包含一种模型时才复制为该模型的人工设置；零模型或多模型时保留旧字段，不猜测应应用到哪一模型。旧字段不会覆盖以后出现的新模型。服务端没有对应向量时只保存设置并通知来源端，不清空来源上传的已有聚类。
