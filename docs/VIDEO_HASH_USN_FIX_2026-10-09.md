# 视频内容哈希缓存的 USN 身份修复

发布候选的首轮 GitHub CI 通过后，两次独立后续运行在同一测试中失败：视频内容快速替换、长度不变且恢复修改时间后，第二次海报缓存目录仍与第一次相同。不是测试超时，也不能用延迟掩盖。

## 根因与修复

原快路径只比较 NTFS 卷、文件 ID、ChangeTime 和长度。极短间隔改写可能得到相同的时间信息，因而复用过期 SHA-256。

现在复用必须同时满足：可读且有效的 NTFS 日志、日志 ID、同一打开文件句柄读取到的逐文件 USN，以及原有文件身份字段。哈希读取前后再次比较身份；日志重建、USN 改变或身份改变时失效。无法可靠读取日志、权限不足、未知记录格式或无效 USN 时，完整计算哈希，不保留快路径结果。

128 条缓存上限、清除代际以及禁止清除后迟到结果重新填充的约束保持有效。未知或无法信任的信号优先保证内容正确，不能仅为减少读取而保留猜测身份。

## 验证

严格构建通过，零警告、零错误。缓存、海报身份、关键帧和清除定向测试 **27/27** 通过，其中新增：

- 时间、长度、文件 ID 相同但逐文件 USN 改变；日志 ID 改变而其余身份相同。
- 无可信日志时每次完整读取且不保留缓存。
- USN 记录版本、长度、文件身份和数值校验。
- 真实文件连续 32 次同长度改写、恢复同一修改时间，每次内容哈希必须匹配当次字节；没有 sleep。

原快速换内容的测试断言未改。原生快路径测试改为检测真实句柄是否具备完整可信 USN 前提：支持时必须复用，不支持时明确验证完整读取与空缓存，不把“磁盘是 NTFS”当作日志可读的证据。

本机证据：`artifacts/deploy/usn-build.log`、`artifacts/deploy/usn-tests/usn-cache-regression.trx`。原 `v1.1.0` 候选没有公开；修复进入 `v1.1.1` 候选，最终 CI、发布与部署见[发布部署记录](RELEASE_DEPLOYMENT_2026-10-09.md)。
