# 共享缩略图加载机制（2026-10-31）

后续状态：下文保留第一阶段的范围和测试证据。其余图片入口、原图持久缓存、人脸与视频关键帧共享已继续实现，最终验收及部署状态以[收尾记录](MEDIA_EXPERIENCE_COMPLETION_2026-10-31.md)为准。

## 统一原则

所有显示缩略图的功能复用加载机制，而不只是使用同名的缓存目录。跨目录浏览、分类、问答、人物、语义搜索等入口，以空间和内容身份识别同一资源；人脸裁剪、视频帧等派生资源还必须区分类型及版本，不能与照片缩略图混用缓存键。

共享能力包括持久缓存命中、并发请求合并、前台优先调度、离开视口取消订阅、有限并发解码、损坏缓存失效和失败退避。界面只负责提供资源身份和可见生命周期；本地已有文件直接读取。原图持久缓存是另一个尚待完成的工作项。

## 本次落地

新版分类曾用只有照片 ID 的 ImageRecord 请求缓存；目录浏览使用完整记录，优先按内容哈希建键。即使调用同一个 RemoteThumbnailCache，也可能生成不同文件。此外，分类使用独立解码代码，下载只绑定窗口关闭，切换类别不会取消旧下载。

新增 ThumbnailPresenter，将普通 Image 控件接入目录浏览已经使用的 ImageItemViewModel。新版分类复用其队列、缓存、解码器、日志、损坏缓存处理及退避策略；从分类内容身份提取 SHA-256，和目录浏览使用相同缓存键；请求绑定分类查询生命周期。控件卸载、隐藏、复用时取消旧加载，显示时恢复，空白项按原有退避策略重试。

## 验证与范围

新增真实 WPF 测试：目录加载后另一引用通过共享呈现器打开不得再次下载；控件复用应取消阻塞的旧请求，新图片不得被旧结果覆盖。

验证结果：解决方案 Debug 严格编译（--warnaserror）通过，0 警告、0 错误；ViewportThumbnailTests 与 ClassificationV2UiTests 共 7 项通过、0 失败、0 跳过。这是定向回归，不是全量回归。构建输出位于 E:/picer-shared-thumbnails-20261031/bin，测试证据位于同目录 tests/shared-thumbnails.trx。

本次不代表全入口迁移完成。旧分类审核、人物照片列表、独立语义搜索、重复照片及冲突审核等入口还需逐一接入并验证；人脸与视频帧需要保留各自资源身份。服务浏览已经共享 RemoteThumbnailCache 和 ThumbnailBitmapLoader，但仍有独立的界面调度适配。正式发布和正在运行程序的替换未在本次执行。
