## 已实现

- `IndexSyncClient.PushIncrementalAsync` 为本地媒体和元数据计算逻辑指纹，并将成功同步的指纹写入数据根目录检查点。
- 图片、视频、人物、标签、相册、地点、场景、视频分析和人脸工作流均复用现有幂等 `/api/sync/v1/*` upsert 接口；指纹不变时不产生网络写入。
- 远程 GUI 启动时先从 IndexService 拉取镜像，再发布本地镜像变更，避免空镜像覆盖服务端；之后每 5 秒执行“发布→拉取”。
- 本地 GUI 默认保持离线；设置 `PICER_INDEX_SYNC_IP` 与 `PICER_INDEX_SERVICE_TOKEN` 后，会在后台发布本地数据库，并拉取服务端最新镜像回本地数据库。
- 所有失败均保留检查点，下一轮自动重试；临时文件原子替换，进程崩溃不会写入半个检查点。
- 目录场景分类偏好（是否包含子目录）也通过专用同步端点保存和回拉，避免远程场景数量、顺序与本地不一致。
- 场景描述增加跨数据库兼容回退：当历史镜像的 SQLite 图片 ID 不同导致指纹不匹配时，按目录和有效时间范围恢复标题、摘要和代表图描述关联。

## 一致性边界

当前 IndexService 仍是单租户、服务端最终一致的幂等 upsert。远程与本地同时修改同一实体时，以最后一次成功同步到服务端的完整实体状态为准；下一阶段可在此基础上增加实体版本和冲突工作台。

本地同步配置仅在显式设置 `PICER_INDEX_SYNC_IP` 时启用，未设置时不会进行任何远程访问；服务模式则复用已配对的 HTTPS endpoint。
