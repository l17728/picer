# 视频人工决定的来源隔离

日期：2026-10-23。schema63 开发中，未发布部署，正在运行回归。

视频文件内容、摘要、转录及缓存仍按强内容身份共享；本轮把视频标签和人工分类决定按来源归属分别计算。同一 publisher 内的多个路径引用共享决定，不同 publisher 即使内容哈希相同，也不相互投递或覆盖人工决定。

来源归属优先取已绑定来源；远程 GUI 镜像使用服务端生成的来源路径命名空间识别归属；未发布的本地库使用图库身份。来源归属不明确时不扩散决定。字段版本、视频字段合并、引用删除后的记录移交、查询和实体认领使用同一归属规则。

旧共享表作为兼容投影保留。新查询优先使用同一来源的字段决定，包括明确移除和拒绝；旧投影只有来源证据明确时才参与查询。已有多个来源共享同一内容、但旧决定已丢失来源证据的记录保存在 `video_metadata_ownership_reviews`，不默认归给每个来源。旧视频后来取得哈希时，明确归属的旧标签和分类转为该来源的字段记录；归属不明的旧载荷保留待审核，不能因加入已有内容而丢失或泄露给另一来源。

用户入口为“索引巡检、同步与修复 → 处理同步冲突… → 核对旧视频决定…”。选择旧决定后，可多选来源，再点击“应用到所选来源”；或点击“忽略该旧决定”。连接账号空间时处理服务端待审核记录，未连接时可离线审核当前图库。账号接口需编辑权限；服务端检查内容身份、来源、当前字段版本和空间 epoch，整批选择事务提交，重复请求不会重新应用。此入口正在进行真实 HTTPS 和 WPF 测试，尚未发布。

来源授权范围排除某个视频引用时，上传快照先把同来源的内容决定移交给仍获授权的引用；这只修改临时索引快照。真实索引和原始媒体保持不变。
