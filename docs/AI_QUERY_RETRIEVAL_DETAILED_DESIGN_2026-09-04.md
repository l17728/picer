## 1. 目标与验收边界

用户可以使用自然语言查询人物、时间、地点、行为、状态、服装、颜色、场景及媒体类型。系统将自然语言转换为受约束的查询工具调用，检索照片/视频的结构化元数据和文字索引，再由本地 VL/语言模型复核候选并生成可解释的 Markdown 结果。

目标指标：在版本化、人工标注的验收查询集上，召回率达到 100%，精确率达到 90%。其中“100%”定义为验收集中所有已标注相关媒体均进入候选集合；模型不得宣称对未覆盖的自然语言、未建立索引或没有对应元数据的媒体保证 100% 召回。任何召回不足都必须显示原因和扩大查询建议。

## 2. 核心原则

1. LLM 只能调用只读搜索工具，不能写 SQL、修改归属或虚构媒体 ID。
2. 人物、地点、时间、媒体类型和标签 ID 使用程序提供的真实字典；模型只能提交值，不得创建实体。
3. 召回阶段宁可扩大候选集，精确判断放在候选召回之后；禁止先用过窄的关键词把真实结果过滤掉。
4. 所有候选必须通过稳定 ID 反查完整记录，再交给模型判断。模型只能从候选 ID 中选择。
5. 增量索引只处理新增或变更媒体，索引版本、内容指纹和模型版本必须可追溯。
6. 查询和复核默认本地执行；若使用云端模型，必须显示发送的候选数量、字段和授权状态。

## 3. 查询原语

新增统一的 `MediaSearchRequest`：

```json
{
  "mediaType": "photo|video|all",
  "personIds": [12],
  "location": { "areaKey": "CN-SH", "name": "上海" },
  "dateRange": { "start": "2025-01-01", "end": "2025-12-31" },
  "timeOfDay": "any|day|night",
  "timeRange": { "startHour": 6, "endHour": 18 },
  "tagIds": [],
  "visualConceptIds": [],
  "albumIds": [],
  "sceneTerms": [],
  "descriptionTerms": [],
  "transcriptTerms": [],
  "expandedTerms": [],
  "termMode": "any|all",
  "includeUncertain": false,
  "limit": 200,
  "sort": "taken_desc"
}
```

原语分为三类：

- 硬过滤：人物、GPS/行政区、日期、时间段、媒体类型、相册、确认标签。
- 召回过滤：BM25 文字词、同义词、描述词、场景词、转写词和视觉概念。
- 复核参数：候选上限、词项模式、是否包含不确定候选、排序方式。

所有字段均经过服务器端校验。时间按媒体拍摄时间的本地时区解释；缺少拍摄时间的记录只有在用户允许 `includeUncertain` 时才进入时间相关候选。

## 4. BM25 文字索引

### 4.1 索引内容

建立 SQLite FTS5/BM25 索引 `media_text_fts`，每条媒体一条主记录，并保留可反查的字段：

- 文件名和路径；
- 图片一句话描述、场景标题、场景摘要和搜索词；
- 人物确认标签、用户标签、视觉概念；
- 地理行政层级、原始地点文字、GPS 反查结果；
- 视频摘要、语音转写和视频人物标签；
- 来源类型、内容指纹、描述模型版本、索引版本和创建时间。

文字索引不替代结构化字段。人物 ID、时间、GPS 和媒体类型必须同时保留结构化列，避免依赖中文分词造成误召回或漏召回。

### 4.2 分词和权重

采用中文兼容的 Unicode tokenization，并对完整短语、行政区名称、人物姓名、颜色、衣物、行为和场景词建立别名/同义词表。BM25 权重建议：

| 字段 | 权重 |
|---|---:|
| 人物/用户标签 | 8 |
| 地理名称/原始地点 | 7 |
| 场景标题/摘要 | 5 |
| 图片/视频描述 | 4 |
| 语音转写 | 3 |
| 文件名 | 1 |

权重只影响候选排序，不能单独决定最终结果。

### 4.3 增量更新

以下事件触发单媒体重建索引：新媒体入库、文件内容指纹变化、图片描述完成、场景摘要更新、人物标注变化、地点解析完成、标签变化、视频转写/摘要完成。使用 `media_search_documents` 保存当前文档和指纹，使用事务更新 FTS；失败时保留上一版本并记录错误。

## 5. LLM 查询改写与同义扩展

规划器使用结构化输出或工具调用，输出：

- 识别出的实体及其置信度；
- 时间范围/时间段；
- 人物、地点和媒体类型；
- 行为、状态、服装、颜色、场景词；
- 同义词、近义词和中英文变体；
- 每个词的来源和是否必须满足。

扩展规则：

- 只扩展可解释的词族，例如“白天”→ `06:00-18:00`，“红裙子”→ `红色 连衣裙 裙装`；
- 人物和地点不得通过同义扩展替换真实 ID；
- 扩展词用于召回，不得覆盖用户明确的排除条件；
- 记录原始问题、改写结果、扩展词和模型版本，便于复现。

## 6. 工具调用协议

提供只读工具：

```text
search_media(request: MediaSearchRequest)
```

返回：

```json
{
  "queryId": "...",
  "items": [{ "id": 1, "mediaType": "photo", "matchedFields": ["person", "location", "description"], "bm25": 12.3 }],
  "totalCandidates": 127,
  "appliedFilters": {},
  "omittedConditions": [],
  "nextCursor": null
}
```

LLM 不直接调用数据库 API。工具服务负责 ID 白名单、参数范围、分页上限、超时、取消和审计日志。查询结果中的 `matchedFields` 供复核模型解释命中依据。

## 7. 两阶段检索与完整反查

### 阶段 A：高召回召回

1. 解析结构化硬条件。
2. 使用 BM25、别名扩展、结构化条件和可选视觉概念生成候选。
3. 对 `termMode=all` 使用字段内 AND；对自然语言不确定条件先使用 OR 扩大召回。
4. 召回上限默认 200，必要时自动扩大到 1000，但必须显示候选规模。

### 阶段 B：完整反查与 VL 复核

1. 通过稳定 ID 反查完整元数据、描述、场景、标签、人物状态、GPS、时间和缩略图/关键帧。
2. 去除已删除、权限不允许或不满足硬条件的候选。
3. 将候选分批发送给 VL/语言模型，要求只返回候选 ID、满足条件、证据字段和不确定原因。
4. 按硬条件、BM25 分数、模型判断和用户确认状态综合排序。
5. 返回照片和视频分组、Markdown 结论、命中依据、未确认项和可点击稳定 ID。

## 8. 召回保护与自动放宽

当候选为空时按顺序放宽：去除低权重扩展词 → 将行为词从 AND 改为 OR → 扩大地理层级 → 扩大时间范围 → 请求用户澄清。人物、明确地点、明确日期和排除条件不可自动放宽。每次放宽必须记录并显示。

## 9. 质量评测

建立版本化查询验收集：每条自然语言问题包含人工标注相关媒体、硬条件、可接受同义词和排除项。按查询和人物/地点/媒体类型分组计算 Recall@K、Precision@K、FAR、空结果率、改写正确率和复核一致性。

发布门禁：验收集 Recall@候选上限必须 100%，Precision@最终结果至少 90%；任一重要分组下降即阻止应用。训练/调参查询和最终验证查询严格隔离，连拍、同原图衍生物及同一视频关键帧不得跨分区。

## 10. 实施阶段

1. `QRY-001`：统一 `MediaSearchRequest` 和工具 Schema。
2. `QRY-002`：建立媒体文字文档表、FTS5/BM25 索引和增量事件。
3. `QRY-003`：实现 LLM 查询改写、词典、同义扩展和实体白名单。
4. `QRY-004`：实现两阶段召回、完整反查、候选分页和自动放宽。
5. `QRY-005`：接入 VL 复核、证据返回、图片/视频 Markdown 结果。
6. `QRY-006`：建立版本化验收集、指标报告和发布门禁。
7. `QRY-007`：接入 AI 问答、普通搜索和语音 Agent，共用同一工具。

## 11. 风险与禁止事项

- 不得把“LLM 认为相关”当作事实标签写回数据库。
- 不得只依赖图片描述；没有描述的媒体必须通过结构化条件和后续补描述任务可被发现。
- 不得把同义扩展词直接拼接为未经校验的 SQL。
- 不得用同一批查询同时调参与验收，否则 100% 召回指标没有意义。
- 不得把候选截断到过小数量后宣称达到 100% 召回。

## 12. 专家评审修订要求（2026-09-04）

本方案经数据评测和人脸机器学习方向评审，结论为“有条件通过设计评审”，以下要求在正式开发/上线前必须落实：

1. 人脸向量、裁剪图和身份标注属于敏感的生物识别数据，不能以“匿名数据”描述。训练上传、VL 分析和制品应用必须是三个独立的用户授权点，默认仅允许本机 `127.0.0.1`，平台接口需认证、加密、幂等、哈希校验、保留期限和删除机制。
2. 训练/验证/测试切分必须先于原型计算、困难样本挖掘、阈值拟合和 VL 配额调整。相同原图、连拍、近重复文件和同一视频关键帧必须使用泄漏关系图的连通分量作为分组，不能只按单一字段切分。
3. 除 Recall/Precision 外，开放集必须报告 FMR/FNMR、FPIR/FNIR、Rank-1 和每人物错误接受次数，并给出按泄漏组计算的置信区间。观察到零错误不能直接宣称达到目标误认率，样本量不足时必须标记为“不足以验收”。
4. 适配器改变向量空间时，所有原型、阈值、近邻和索引必须统一使用 `effectiveEmbeddingVersion = sfaceModelHash + adapterHash + normalizationVersion`。在后台迁移完成前继续使用旧制品，禁止新旧向量空间混用。
5. 人工标签必须区分 `positive_for(personId)`、`negative_for(personId)` 和 `unknown_to_all_enrolled`；“不是此人”不能作为所有人物的通用负样本，“不分类”也不能自动等同于未知人物。身份冲突必须阻止训练并要求用户解决。
6. 小样本人物不得拟合独立阈值；至少需要多个独立泄漏组和独立未知人物拒识集。低分样本应先区分信息性困难正样本、技术失败和疑似误标，不能按固定百分比盲目混配。
7. 固定测试集只用于里程碑审核，不能每次训练后用于选模型；应增加 validation、滚动隔离集和线上影子回放集。用户预览不得暴露封存测试集成员。
8. VL 只作为可选审计/抽样工具，不能成为训练必要依赖或身份标签来源；必须记录模型哈希、提示词版本和原始 JSON，VL 不可用时流程仍可运行。

修订后的批准顺序为：先实现 `QRY-001`～`QRY-004` 和可复现检索验收集，再实现人脸 `FACE-EVAL-001/002`；只有评测门禁通过后，才允许开放 adapter 训练和自动应用。完整 SFace 主干微调仍需另行评审。
