# 双向同步剩余协议的实现约束

日期：2026-10-22。本文澄清[已定稿 SDD](LOCAL_REMOTE_METADATA_SYNC_SDD_2026-10-22.md)的落地方式，不代表下述协议已经实现。当前能力及验证以[实现进度](LOCAL_REMOTE_METADATA_SYNC_IMPLEMENTATION_2026-10-22.md)为准。

## 1. 已有实现不能替代的门槛

当前 publisher 身份、上传批次、授权来源过滤和部分下行快照可以复用，但仍缺少字段级因果版本、显式删除事件、云端新实体认领和全空间设备协调。不能用空数组推断撤回，不能先上传旧快照、再拉取远端结果来解决并发删除；两者会造成旧值复活或未提交本地决定丢失。

视频摘要/转录的来源时间戳用于兼容旧协议和展示，不作为新协议唯一的冲突裁决依据。新协议以服务端单调版本和操作的已知基线为准。

## 2. 事务事件与删除

每个受同步管理的逻辑字段使用稳定键：`publisher / media global identity / metadata kind / field keys`。分类键至少含 concept、source kind、source version；人脸及帧引用 global identity；账号目录对象另有稳定实体键。

客户端业务变更与 outbox 在同一事务提交。事件至少含 operation ID、origin publisher、base server version、操作类型和最小载荷。删除、撤销、拒绝及恢复均为显式操作；不能仅记录“某媒体发生变化”再从当前行的缺失推断删除。

服务端写业务行、分配版本、更新字段版本、保存事件及幂等回执也须处于同一事务。对同一 operation ID 重试返回原回执。上传旧目录快照不得绕过字段版本或墓碑检查。

合并规则：

- 不同字段独立合并；模型结果按内容身份、模型及提示版本幂等保存。
- 人工确认/纠正/拒绝优先于机器建议。显式恢复产生新的人工操作，空审核快照不等于恢复。
- 同字段人工操作的 base version 过旧时保留双方内容和审计信息，产生待处理冲突；不得静默丢弃本机决定。
- 已撤回键的旧上传不能重新插入。用户在读取新基线后明确重新创建，才能产生晚于墓碑的新版本。
- 接收应用使用独立连接、短事务和 remote-apply 标记；只有整页提交成功才推进该流游标。

来源端永久清除媒体索引仍使用既有、单独授权的 purge 协议和基线围栏。普通 `index.write` 元数据事件不能获得清除媒体索引或原文件的能力。缺失状态不产生永久删除。

## 3. 云端新实体的身份认领

远端新建标签、相册、人物或新检测出人脸/帧时，没有来源机器的 SQLite ID。不能丢弃这些实体，也不能直接把服务端整数 ID 插入本机，更不能按人物姓名合并身份。

采用持久化认领步骤：

1. 服务端返回 publisher 所拥有媒体引用的新实体及稳定远端引用。只有经媒体/source binding 反查属于该 publisher 的实体可返回；目录对象可同时被多个来源引用。
2. 客户端按 global identity 或已存认领映射查找本机记录。首次导入分配本机 ID，将实体、身份和待认领操作原子保存。
3. 客户端提交认领请求；服务端重新检查 grant、space、publisher、关联媒体归属、目标实体及映射冲突，幂等绑定本机身份到既有远端对象。
4. 客户端持久化回执。认领尚未确认时，后续上传必须先续传认领，避免把刚导入的相册/人物当作另一个新对象发布。
5. 目录对象认领后，才能应用引用它的标签/相册关联、人物分配和人工编辑。依赖尚不完整的载荷不能当作空集合清除本机关系，也不能静默推进其待处理事件。

同名人物保持独立；合并需要既有显式人物合并操作。标签名称的现有规范化可用于提示或既有业务去重，不能替代稳定身份。人物别名、目录描述及账号偏好也需列入协议覆盖清单；资源限制和扫描缓存保持设备本地。

## 4. 内容哈希拒绝的来源范围

内容哈希用于同一来源的重复引用继承，不能替代 publisher 授权。拒绝记录若只留下 `image_id=NULL + hash`，会丢失原始归属；须保留 publisher/来源范围，并在分类投影、下行和模型重算时统一校验。

旧内容级拒绝需要迁移来源证据：可从已有媒体身份及被拒绝断言确认的范围恢复；不能确定归属的多来源记录进入保守审核，不能默认扩散到所有 publisher。本地单一图库的旧记录保持其原有来源范围。不同模型版本的向量和阈值继续分离。

## 5. 全空间巡检和操作触发同步

“巡检并同步用户空间”创建一个空间任务，枚举该空间已授权的来源 publisher，为每个来源保存持久目标及回执。来源电脑继续采用自己保存的授权范围；远程按钮不能替它新增本机目录或扩大人物/精确位置权限。

目标状态至少包括：待通知、设备离线等待、执行中、完成、失败、已撤权、已取消。用户取消只停止未完成工作；已提交页保留。设备离线不伪装成全空间同步成功。

源 GUI 建立独立的、经设备证明认证的同步通知通道。现有 `ConnectWebSocketAsync` 只允许 agent 媒体通道，不能直接复用其权限判断给 GUI；新增路径必须明确白名单、验证 GUI grant 和对应 publisher。服务端不能接收客户端任意选择其他 publisher 的订阅。

- 远程用户变更提交后，服务端按 owner 发出版本失效通知；来源端排队执行增量同步。
- 本地用户操作提交后，既有队列触发上传与下行；无固定周期全库同步。
- 连接恢复先恢复持久任务和版本差异；离线期间的通知可以合并为最新水位，业务事件不能丢。
- 心跳、令牌续期和连接退避不扫描索引。设备撤权或 grant/space 变化必须中断通道并停止后续读写。
- 若来源端由驻留程序承担同步，必须增加明确的 publisher 委托；当前仅有 `source.serve` 的 agent 不得借用 GUI 的 `index.read/index.write` 权限。

任务页显示每个来源的结果、待同步数、最近成功时间和可操作错误。离线来源显示等待；完整完成状态必须由目标回执汇总，而不是由发起 GUI 的本机 `quick_check` 推断。

## 6. 基线、游标与保留

首次配对或旧版本升级建立明确的元数据基线。服务端快照、身份及水位须一致；基线期间的新变更保留为后续增量。中断保留页状态，不能重复扫描原媒体。来源移动沿用既有 global identity，不按路径重建其他身份。

不同变更流分别确认游标；publisher、space、grant 和 epoch 绑定不可混用。页读取必须有一致的 WAL 读取事务。失效、回退或已被压缩的游标返回明确的 baseline-required 错误，不得返回空页并继续。

墓碑及事件压缩根据仍有权维护相应对象的来源确认水位执行；离线来源未确认时不得提前删除必要墓碑。需要按保留期压缩时，先持久化最低可续传水位，旧客户端必须走基线。撤权不自动清除其照片空间数据。

## 7. 验收顺序

1. 字段事件/outbox、显式墓碑、因果版本及整页回滚。
2. 新实体认领、依赖续传、重复回执与映射冲突；人物同名不合并。
3. 内容哈希拒绝归属、同内容跨 publisher 隔离、模型重算不能复活拒绝。
4. 全空间任务、在线推送、离线恢复、撤权中断及逐来源回执。
5. 人工冲突与待同步 UX；A/B 两台来源和远程 GUI 的真实双向验收。

每段通过后刷新实现进度与能力表；协议尚未覆盖的类别继续明确列出，不将局部成功写成“所有索引完全一致”。
