## 目标

人物分类页只提供 InsightFace 模型空间；SFace 历史数据保留在索引中作溯源，不再作为可选空间。用户应用的制品是该模型空间当前的实际策略，必须能在重启和远程索引镜像后恢复；只有用户明确应用另一历史制品，或训练门禁通过后应用新制品，才改变当前应用项。显示的模型准确率必须对应当前实际应用制品，而不能仅因为历史制品下拉框选中就改变。

## 实现

- 人物页的模型空间固定为 InsightFace，显示名简化为“InsightFace”；不再从训练平台动态追加 SFace 或其他候选模型空间。
- 历史制品下拉框保留为候选选择，应用后按模型版本更新索引中的 `active` 制品状态。当前模型空间标题和准确率单独读取/维护 active 制品；选择但尚未应用的候选不会被误显示为当前使用项。
- 人脸推荐和视频人脸匹配继续按精确模型版本隔离：正样本、负样本、阈值、adapter 和训练原型只能来自请求的 InsightFace 向量空间。
- 索引同步协议增加训练制品、人物原型、人物策略和阈值设置。远程镜像请求单独授权包含校准元数据，默认普通 metadata 响应仍不返回这些向量类数据；本地已配对 IndexService 时，人物标注、推荐及制品应用等提交后异步排队发布。
- IndexService 在写入检测结果前校验响应模型版本与请求一致。开发用 YuNet+SFace 脚本不再回显任意请求模型名，收到 InsightFace 请求会明确失败，避免把 SFace 向量误登记为 InsightFace。
- 旧视频人物记录标注为模型未知；新分析生成的推荐明确来自 InsightFace 空间，不将未知旧向量混入 Insight 匹配。

## 回归覆盖

- 人物 UI 只暴露 InsightFace，并验证不会显示 SFace 人脸；Insight 历史制品仍可见。
- Gateway 默认 metadata 不带训练制品；显式请求校准元数据后可读到 active 制品、原型和阈值，并验证镜像写回后状态仍为 active。
- 人脸推荐不能借用另一个模型空间的已确认向量。
- 已有“打开人脸原图关闭后不刷新列表”的回归用例及“视频分析状态显示帧数”的回归用例保留，不更改其行为。

## 运行时前提

索引和 UI 现在会严格拒绝模型版本不匹配，但实际运行仍要求已配置的 MediaAgent `face.detect` 服务确实提供 InsightFace/ArcFace 向量。YuNet+SFace 开发脚本不是 InsightFace 实现；若当前环境仍把它配置为唯一人脸服务，扫描会显式报模型不匹配，而不会产生错误标注向量。
