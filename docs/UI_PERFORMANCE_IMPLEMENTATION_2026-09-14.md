# UI 性能与渐进加载优化（2026-09-14）

## 目标

在功能回归全部通过后，优先降低照片墙滚动、目录切换和视频首帧加载对 UI 线程的占用，并保证切换目录时旧任务可立即取消。

## 本轮实现

- 照片墙虚拟布局只在条目、宽度或缩略图尺寸变化时重建；普通滚动复用布局缓存。
- 可见范围由全量线性扫描改为二分定位，滚动复杂度由 `O(N)` 降为 `O(log N + 一屏条目数)`。
- 缩略图的文件存在性检查和位图解码移至受限后台队列，UI 属性读取不再访问磁盘。
- 视频条目不再尝试把 MP4 文件作为位图解码；没有缓存海报时调用首帧生成器。
- 目录首批显示 16 个媒体项，随后每批 64 个；既尽快形成首屏，也避免数千张照片产生数百次 Dispatcher 调度。
- 所有渐进批次继续绑定目录加载取消令牌；切换节点后旧批次和缩略图任务不会写回新页面。

## 回归覆盖

- 10 万条索引的真实 WPF 主窗口启动、照片墙滚动、可视项数量和工作集门禁。
- 虚拟面板快速滚动后连续移除、清空并换组，验证容器生成器不损坏。
- 视频存在但没有海报时必须调用海报生成器，防止白框回归。
- CI 同款构建保持 `--warnaserror`，并运行非 RuntimeComponent 单元测试及 WPF E2E。

## 后续测量

- 在真实图库记录目录点击到首屏、首张缩略图和整页元数据完成的 P50/P95。
- 根据慢操作日志继续优化数据库查询、批量索引写入和人物页面首屏加载。
- 对远程索引和网络媒体分别设置超时、取消和预取预算，避免慢网络占满缩略图后台队列。
