# Picer 云端照片与视频理解设计（国内服务）

日期：2026-08-28

## 决策

- 照片先由本地标签、人脸、EXIF/GPS、重复检测完成初筛。
- 普通复杂照片默认使用阿里云百炼 `qwen3-vl-8b-instruct`。
- 多人关系、OCR、歧义场景和低置信结果升级到 `qwen3-vl-plus`。
- 智谱 `glm-4.6v-flash` 只作为免费试用和降级通道，不承诺生产 SLA。
- 不提供国外服务的产品配置。
- 视频默认不上传原文件：本地镜头切分、关键帧去重、人脸/GPS分析和音频转写后，再对关键帧进行云端融合；只有时序敏感片段由用户确认后调用国内视频理解接口。

## 隐私边界

- 云端分析默认关闭；用户必须显式开启并选择照片或处理范围。
- 上传前最长边缩放到 1280 像素，重新编码 JPEG，并清除 EXIF、ICC 和 XMP。
- GPS先在本地逆地理编码。API获得结构化地点文字，不读取照片原始EXIF。
- 人物只使用匿名编号；本地姓名和亲属称呼不发送给API。
- 模型不得猜人物身份或精确地点。附近地标必须用“附近/周边”等措辞。
- 人工确认的标签优先级最高，云端结果不能覆盖人工结果。

## 缓存与计费保护

缓存键由照片文件大小和修改时间、提供商、模型版本、提示词版本及地点指纹组成。相同输入不重复调用；地点、模型或提示词变化时才重新分析。

云端调用使用持久化状态：`queued → completed/failed`。单次运行默认上限100张，产品层首次启用前为0张。后续增加日/月预算、费用预估、暂停、重试和断点续传。

## 当前实现

- 数据库版本9；云任务包含Token和估算费用，新增视频、关键帧、转写持久化表。
- `ICloudVisionAnalyzer` 提供商无关接口。
- GPS结构化上下文和附近地标。
- 百炼/智谱国内端点预设。
- OpenAI兼容协议适配器（协议兼容不代表使用OpenAI海外服务）。
- 图片内存缩放、元数据清除、固定JSON输出和缓存。
- 本地复杂度路由：多人、无标签、低置信、收藏或用户点选进入增强分析。
- 主界面国内云端分析设置窗口；配置文件不包含API Key。
- API Key使用Windows凭据管理器分别保存百炼和智谱凭据。
- “描述选中照片”入口在上传前显示服务商、数量、图片处理方式和GPS精度，并要求再次确认。
- 照片右键信息显示已有云端描述或任务状态，查看详情本身不会触发上传。
- 精确GPS默认关闭；关闭时请求中的经纬度字段为空，只包含本地逆地理编码文字。
- 云端任务中心显示等待、处理中、完成、失败、服务商、模型、原因、描述/错误和更新时间；刷新不会触发上传。
- 云端返回的场景、活动、物体和检索词进入独立标签建议，只有用户接受后才写入正式标签；拒绝记录继续复用现有的永久屏蔽机制。
- 云设置包含每日/月度人民币预算；达到上限后剩余任务不会调用API。
- 取消正在进行的批次时，当前任务回到等待状态，可供后续断点续传。
- 崩溃日志改为写入 `PICER_DATA_ROOT/logs`，不再固定使用系统盘 AppData。
- 视频索引支持 MP4、MOV、M4V、AVI、MKV、WMV、MTS/M2TS、3GP、WebM，扫描只写数据库，不修改视频。
- 正式发布优先从应用目录的 `runtime/ffmpeg/ffmpeg.exe` 加载；FFmpeg、whisper.cpp 及语音模型随自包含发布包提供并经过固定哈希校验。环境变量与旧 D 盘路径仅作为开发兼容回退。

## 2026-08-28 完成状态

- 任务中心已支持持久化状态、失败重试、取消后续传、Token/费用与日/月预算保护。
- 照片已按本地复杂度在百炼 8B 与 Plus 间自动路由，智谱免费模型可作降级通道。
- 视频已完成本地 FFmpeg 探测、镜头关键帧与 dHash 去重缓存；MOV、MTS/M2TS、HEVC 由 FFmpeg 解码能力统一承载。
- whisper.cpp `base-q5_1` 已从 D 盘运行，转写结果进入视频搜索索引并可复用。
- 视频融合摘要已实现：最多 12 张去元数据关键帧组成时间顺序拼图，可附本地转写和位置文字，上传前必须确认，原视频不上传。
- 融合摘要结果、模型版本、提示词版本、源文件指纹、Token 与估算费用持久化到数据库 v12；视频检索同时覆盖路径、转写和摘要。
- 直接上传视频文件的原生接口不作为默认产品能力：在当前隐私与成本约束下，关键帧融合方案是已交付的高性能低成本路径。

## 2026-09-03 本地语音识别迁移决策

- 后续统一将视频本地音频转写模型从 whisper.cpp `base-q5_1` 替换为 `Qwen3-ASR-1.7B`，不把 Qwen3-VL 用作音频识别模型。
- Whisper 在迁移开发和数据兼容期仅作为旧实现与故障回退；完成验收后，产品默认入口和新转写结果统一使用 Qwen3-ASR-1.7B。
- FFmpeg 提取音轨后必须保留“整段转写”路径。不得因为 VAD 判断为静音、笑声、音乐或低置信噪声而直接跳过整个视频。
- VAD 使用宽松阈值，只负责切分和减少长静音，不负责决定视频是否值得转写。短语音、笑声前后的说话声和低音量片段必须保留上下文重叠窗口。
- 分段结果按原始时间顺序合并并去重；模型无有效结果时，再对整段音频执行一次不经过 VAD 的兜底转写。
- 如需字词级时间戳，配套使用 `Qwen3-ForcedAligner-0.6B`；时间戳、语言、模型版本、音频指纹和 VAD 配置版本随转写结果持久化。
- 已有可用转写不自动覆盖。模型或处理策略升级后以新版本缓存重新生成，成功且通过质量检查后原子切换；失败时继续保留旧结果。
- 验收必须包含普通话、方言、低音量、背景音乐、笑声包围短对白、长静音后讲话和纯无语音视频，并与现有 Whisper 基线做同一批音频的字错率及漏检率对比。
# 本地统一模型平台接入（2026-09-03）

AI 模型设置按功能独立绑定服务商与模型：照片内容分析、视频内容总结、未分类场景描述可选择本机统一模型平台的 Qwen3-VL 8B；视频语音转文字可选择 Qwen3-ASR 1.7B 或内置 Whisper。

- 模型发现与状态：`http://127.0.0.1:8090/api/models`、`/api/status`
- VL 代理：`POST http://127.0.0.1:8090/api/vl/chat`
- ASR 代理：`POST http://127.0.0.1:8090/api/asr/transcriptions`
- 本地代理无需 API Key，配置和确认界面必须明确显示“不上传云端、不产生 API 费用”。
- VL 沿用结构化照片描述协议；视频先生成最多 12 帧的关键帧拼图并结合转写文本。
- ASR 先提取完整 16 kHz 单声道 WAV，以 multipart 字段 `file`、`model`、`language` 调用；缓存必须同时匹配视频和模型版本，切换模型后重新转写。
- 本地请求仍须异步、可取消、有进度/状态，不得阻塞 UI；模型平台负责并发和 GPU 资源调度。
