## 本次实现：视频移动修复

- `PicerDatabase.CurrentSchemaVersion` 升为 **42**；新增 `videos.sha256` 和索引。部署迁移前须关闭所有数据库写入者，整体备份 DB/WAL/SHM；本次开发不启动应用或迁移真实数据库。
- `VideoRecord`、普通视频索引、目录导入、远端同步/镜像保留 SHA-256。扫描已知文件可复用有效哈希；旧视频补齐哈希需读完整文件一次。
- 修复操作增加兼容旧请求的 `IsVideo=false` 默认值。客户端规划、源代理复核、服务端索引前置检查及实际应用均区分照片/视频。
- 按完整内容哈希匹配，恢复原视频 ID，保留转写、描述、关键帧、人脸确认/忽略/拒绝、标签与概念。修改时间变化时更新描述有效性签名；镜像同步相同哈希不再因 mtime 改变而清除证据。
- 相同视频多份副本保留独立位置记录，复制已知派生证据，避免立即重复分析。**当前这是独立记录及派生数据复制，不是视频内容级唯一派生存储，不能与照片已有的内容共享能力混称。**
- **旧视频没有 SHA-256 且原路径已丢失时无法可靠恢复。程序仅标记缺失并保留索引，不用文件名、大小或时间猜测关联。** 在移动前完成一次新版本扫描即可为后续修复建立强身份。
- 修复菜单及窗口改为“照片和视频”。测试新增 `VideoIndexRepairTests`：保留 ID/mtime 变化、多个副本、无旧哈希拒绝弱匹配、目标内容变化拒绝、镜像保留哈希、同哈希保留/异哈希清除证据、人物确认/忽略/拒绝及标签复制。

## 审查发现与后续修复

以下 F-01～F-04 已在后续授权修复中完成代码修改，新增 `AiMediaReviewRegressionTests` 13 个测试用例，等待主审统一构建及执行。下文位置为初审定位，保留问题说明便于追溯。

- F-01/F-03：`PeopleService.FindMentions` 统一解析所有本名/别名，按最长非重叠匹配和明确词边界提取人物；歧义别名不猜测身份。照片/视频均接收完整人物 ID 集合。规划模型的姓名不能重新引入程序未明确识别的身份。
- F-02：JSON null、缺失数组、空 Markdown、字段类型错误统一回退到程序已有候选，明确提示复核未完成。
- F-04：照片和视频都采用 GPS 范围候选加地点文字回退，共享地点别名与同义词。GPS 召回不再要求城市名同时存在于描述文字，复核证据包含视频 GPS。
- 测试包括双别名人物交集（照片＋视频）、姓名前缀/普通词子串/拉丁词边界、复核四种坏响应、规划模型越过人物边界及 GPS/地点别名混合召回。

### F-01（P1）：多个人物使用别名查询时，人物交集约束可能丢失

位置：`src/Picer.Core/Search/AiMediaRetrievalService.cs:47`、`:64`、`:93`。

`FindMention` 仅取一个人物；后续多人物集合只检查 `question.Contains(value.DisplayName)`，没有遍历全部已确认别名。若 A、B 都有别名，用两人的别名询问合影，`explicitPeople` 可能为空，最终只约束第一个匹配人物。复核模型提示还要求保留包含指定人物的候选，会进一步掩盖漏约束。

复现：创建两个有人脸确认记录的人物，分别设置不含本名的别名；准备 A 单人、B 单人、AB 合影三张照片；用两个别名查询。应只返回 AB。建议由 PeopleService 提供全部明确提及人物解析器，使用边界/最长匹配，生成全体人物 ID 并统一作用于照片和视频。

### F-02（P2）：模型返回合法 JSON `null` 时结果复核崩溃

位置：`src/Picer.Core/Search/AiMediaRetrievalService.cs:174` 及后续 `review.PhotoIds` 读取。

`Deserialize<Review>(...)!` 的空值抑制不能防止运行时 null；合法 JSON null 不抛异常，所以不进入候选回退，随后抛 NullReferenceException。规划阶段有空值检查，复核阶段没有。建议将 null、缺失数组及空 Markdown 纳入统一结构化验证，返回有依据的候选回退；测试 HTTP 200/body null、空对象及畸形字段。

### F-03（P2）：人物名子串被强制视为明确身份，易产生错误过滤

位置：`src/Picer.Core/Search/AiMediaRetrievalService.cs:64-67`。

多人物识别直接使用任意子串匹配，短名字出现在另一个姓名或普通词中也会被加入人物交集；这不是模型不确定性，而是程序强约束。建议与 F-01 共用最长匹配解析，同时允许用户看到和纠正人物条件。测试姓名互为前缀及普通词包含单字姓名。

### F-04（P2）：照片、视频地点问答召回契约不对称

位置：`src/Picer.Core/Search/AiMediaRetrievalService.cs:142`、`:252-260`。

照片使用 GPS 范围、地名扩展和描述文字回退；视频仅拼接 `plan.Location` 为文字词项，没有传入已解析 GPS 范围，也没有采用 `LocationTerms` 或同义扩展。视频已有正确 GPS 但描述未写城市名时会被漏掉；这是支持视频问答情况下的功能差异。建议统一结构化地点召回与文字回退，使用相同证据核对规则；加入仅有 GPS 的视频与照片对照测试。

## 目录描述与共享数据库调用后续修复

- 目录计划在 SQL 中按完整子树前缀过滤，正确转义 `%`、`_`，避免读出全库媒体对象后逐条筛选。照片描述状态以每批 500 个 ID 查询，包含共享内容描述且预览不回写物理投影；视频描述状态通过一次关联查询读取。
- 目录树只读取路径，后台构造纯数据，展开时才创建下一层控件并分批让出 UI 调度。切换节点取消旧预览，版本检查同时隔离旧成功/失败结果。预览明确说明“扫描前索引范围”，未发现的文件将在实际扫描后统计。
- 增加照片/视频逐项失败清单以及“仅重试失败项”；用户取消与并行任务协同取消不会计入失败。扫描文件/目录失败也进入清单；重试不把其他未处理项误记为已有描述。
- 视频描述传递实际运行预算至统一费用预留服务，移除窗口旧有的非原子余额预检。
- 人物详情、人脸详情和 Florence 批处理的共享数据库操作统一经过 `UiWork.RunDatabaseAsync`。人脸图片解码和模型加载仍在独立后台任务中，不占数据库门；人物/人脸详情增加事件异常反馈。
- 新增验证：`DirectoryPreviewEscapesWildcardsAndDoesNotWriteSharedDescriptionProjections` 检查 SQL 子树边界、只读共享描述复用及取消；`FailureListIncludesBothMediaKindsButExcludesUserCancellation` 检查两类媒体失败和取消区分；原目录树测试改为验证按展开加载视频子目录。执行结果待主审统一补充。
- 错误项具有独立 `Stage`（扫描/预处理/模型/保存）与 `Retryable` 字段；服务端保留类型、HTTP 状态码或 SQLite 错误码，不保存请求凭据或模型原文。照片按媒体 ID 和提供方读取单条失败记录，视频关键帧准备、模型调用、结果保存分别标记阶段；仅用户真实取消显示取消，网络超时进入失败清单。仅重试按钮过滤不可重试项。
- 目录树 SQL 先对父目录去重，返回数量随目录数增长，不把每个媒体路径传回 UI。新增 `DirectoryTreeQueryReturnsDistinctFoldersInsteadOfEveryMediaPath` 和 `AnalysisStageExceptionTests` 验证目录压缩、错误阶段/状态码/重试性及不泄露原始请求文字。
