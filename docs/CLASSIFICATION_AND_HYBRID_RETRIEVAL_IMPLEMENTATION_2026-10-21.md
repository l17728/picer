# 自动分类与多路召回实现记录（2026-10-21）

## 范围与结论

本轮实现 `SEARCH_AND_AUTO_CLASSIFICATION_SPEC_2026-10-16.md` 的首个可用切片：使用已有照片描述和可核验元数据生成分类投影；提供本地审核工作台；在原有 SQLite FTS5/BM25 文字检索之外提供可选 Chinese-CLIP 视觉召回，并用 RRF 合并排名。AI 问答默认检索仍保持 BM25，CLIP 只有用户在语义检索窗口明确勾选时才参与，符合“先评估、再改变默认行为”的决策。

## 用户流程

从主窗口“AI → 照片分类与审核…”进入。点击“开始后台整理”后任务按 40 张一批推进，窗口关闭后仍继续；暂停、中断和取消都保留已提交结果。页签分别显示待确认、自动归类、用户已确认、无分类和已忽略。用户可确认、拒绝、移除机器分类、恢复建议，也可从受控类别列表选择“改为”并批量更正。

自动生效只用于横向/纵向/方形、是否存在相机字段、是否存在 GPS 字段等可直接验证的事实。来自已有视觉描述的场景、活动、对象和搜索词只生成待确认建议。拒绝记录按已验证内容哈希传播到相同内容的多个路径引用；更正通过单一事务拒绝旧机器建议并写入用户确认。分类过程不枚举文件系统、不解码原图、不访问云服务。

## 多路召回

混合检索先应用来源、人物、时间、地理、类别等硬过滤，再分别取得 BM25 和 CLIP 候选，最后用 Reciprocal Rank Fusion 合并。CLIP 扫描使用固定容量 Top-K 堆，不把全部向量或结果加载到内存；按批检查取消；模型版本或维度不一致的向量不会参与排序，并向用户显示降级原因。分类词仍投影为结构化过滤条件，文字描述继续进入 FTS5 倒排索引。

## 模型部署与边界

GUI 不加载 Chinese-CLIP ONNX。文本向量和图片向量请求由 IndexService 使用 `analysis.run` 权限转发到来源 MediaAgent，再由 MediaAgent 调用同机 ModelServer。图片必须命中已授权来源根目录；代理在源端缩放为 224×224、删除元数据并压缩后才发往回环模型服务。ModelServer 使用 `PICER_CLIP_MODEL_ROOT` 或两个显式模型路径定位模型，`PICER_CLIP_CONCURRENCY` 控制 1–8 个并发推理。模型未部署时 BM25、普通浏览和分类整理继续工作。

远程模式通过照片空间的受权分类 API 在 IndexService 权威数据库运行任务和提交审核；GUI 镜像不再充当分类事实源。逐类质量门槛评估和把 CLIP 纳入 AI 问答默认召回仍需单独验收，不在本轮冒充完成。
