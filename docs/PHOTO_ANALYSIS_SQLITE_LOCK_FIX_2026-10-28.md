# 照片分析 SQLite 写锁冲突修复（2026-10-28）

## 现场与定位

用户在远程模式分析照片时遇到 `SQLite Error 5: database is locked`。现场只有一个 GUI 实例，活动镜像使用 WAL；检查时镜像有 16,568 条元数据编辑、75 条照片分析记录（58 条完成、17 条历史失败），没有分析预算预留。短暂的 `BEGIN IMMEDIATE` / `ROLLBACK` 写锁探针返回 `SQLITE_BUSY`，探针未修改记录。此次报错阶段尚未出现模型调用；此前模型 HTTP 503 是另一问题。

代码中，`IndexSyncClient.PushMetadataEditsAsync` 使用独立连接，将整个远程编辑快照放进单个合并事务；这条写入路径没有经过照片分析使用的 `UiWork` 数据库队列。独立连接避免共用连接上的事务混用，但不能消除 SQLite 单写者竞争。大批量同步因此可能占用写锁，导致照片分析保存失败。

## 修改

- 同步客户端支持注入数据库调度器；GUI 的自动、配对及手动同步入口均接入现有 `UiWork.RunDatabaseAsync`。
- 元数据和人脸复核确认的合并按最多 100 条分批提交，每批结束释放队列。网络等待始终位于数据库队列和事务之外。
- 同一客户端的元数据同步串行执行；取消后释放同步门闩。操作确认集合仅在本轮合并完成后替换，部分提交可按既有操作 ID 与版本规则重试。
- 保留独立连接、既有冲突裁决及单批事务语义；不改数据库版本，不清空索引，不触碰原始照片，不自动重放模型请求。
- 照片分析顶层异常补充技术日志，便于后续区分数据库与模型故障。
