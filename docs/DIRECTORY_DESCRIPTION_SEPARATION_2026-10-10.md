# 目录描述解耦与性能复查

日期：2026-10-10。发布基线为 v1.3.5；本文的描述入口修改属于后续源码维护，尚未发布或替换正在运行的 GUI。既有部署证据不能证明此修改已经生效。

## 目录描述开始慢的原因

原 `DirectoryMediaDescriptionWindow.StartAsync` 在创建描述任务前，无条件等待 `RefreshDirectoryAsync` 完成整个子树扫描及镜像刷新；定向重试也走相同流程。这个等待阶段与是否已有描述无关。

扫描对需要深度读取的文件串行计算 SHA-256、读取元数据；照片的平均哈希和差异哈希分别解码图片。每个扫描响应最多处理 5 个需要深度读取的文件。远端还涉及 GUI、索引服务和源代理往返。NTFS 日志不可用等情况下，保守回退可能扩大深度读取范围。因此模型已经支持并发，也无法缩短它前面的整目录扫描等待。

这些结论来自代码路径，不是对用户“半小时 1400 张”的运行时分阶段计时；尚未确认当次日志状态、磁盘吞吐或网络耗时占比。

## 本次修改

描述入口只负责查询所选子树中已入库的媒体、跳过已有有效结果并执行描述。开始和重试不再调用目录扫描，不持有整个扫描阶段的索引变更锁。移除窗口中的完整内容校验选项和扫描进度、扫描失败混入描述失败的逻辑。

开始时重新读取数据库清单，工作线程处理每一项时仍复核描述状态。照片和视频保留原有本地默认 2 路、可选 1～4 路并发；两个媒体阶段依次执行，云端收费请求串行。照片逐项读取临时快照并核对长度及已有哈希，本地原图还核对修改时间；模型只读取核验后的快照，结束后清理临时文件。原文件读取、传输身份校验和必要的视频抽帧仍属于该项描述所需工作，不能省略。

新增文件通过独立的“增量更新索引”或“扫描视频”入库，下次描述时纳入。当前没有新增自动周期性全目录校验调度器，不能将本次移除前置扫描写成“已实现自动后台完整核验”。独立扫描服务、变更清单和 USN 能力继续保留；后续后台维护应低优先级、可取消、记录安全错误且不弹窗干扰，更不能自动重新导入用户手动清除的记录。

描述准备仍会读取所选范围的数据库清单，并非磁盘递归发现一个就立即处理一个；此次消除的是昂贵的全目录文件读取屏障。正在运行的旧任务未强行停止，安装版本未替换。

## 其他性能优化候选

以下是复查发现，尚未实施，不计为已完成优化：

| 优先级 | 代码位置与现象 | 建议 |
| --- | --- | --- |
| 高 | `PlayableMediaCache.GetAsync` 在单个全局门内执行下载，其他文件的缓存命中也等待 | 按媒体身份合并下载，缩小发布锁，另设总下载和容量上限；保留清除代际与取消排空 |
| 高 | `MediaPreviewCache.GetAsync` 查缓存前进入条带锁，不同键碰撞时热缓存被慢请求阻塞 | 先短锁查询热缓存，再进入按键合并流程并复核 |
| 高 | `ParallelMediaReader.CopyRangeAsync` 顺序流通常只有一个源读取在途 | 有界窗口预读 2～4 块，优先当前播放位置，跳转时取消过时预读 |
| 中 | GUI 将极小 Range 扩展到 1 MiB 块 | 首尾探测采用精确小范围，连续播放再升级块缓存；维持租约身份 |
| 中 | 源代理每个媒体范围请求新建 WebSocket | 测量握手占比后考虑租约内复用；保持令牌、授权、过期和取消隔离 |
| 中 | 远端照片描述先取完整原图到 GUI，再预处理并经服务发送模型 | 考虑源端预处理；必须保留内容身份、位置隐私、授权及预算边界 |
| 中 | 滚动离开后缩略图共享下载仍可能继续 | 视口优先队列与无消费者取消，避免仅提高并发数挤占当前视口 |

隔离机制探针使用生产缓存/读取类、合成源每块 100 ms 延迟，缓存工厂人为挂起 300 ms；没有访问真实图库、网络或模型。结果：无关原文件下载使热缓存命中等待约 343 ms，预览条带碰撞等待约 309 ms；配置 4 路时顺序流的源峰值并发为 1，完整分块下载峰值为 4；1 字节流式范围触发 1 MiB 源读取。8 MiB 合成顺序流约 1061 ms，分块下载约 629 ms。这些数值只证明调度和放大机制，不代表真实网络或显卡提速承诺。
