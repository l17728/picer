## 统一功能边界

“索引巡检、同步与修复”是照片空间级的统一入口，不按 GUI 当前连接到本机还是远程拆成两套用户功能。照片空间服务端汇总所有已授权来源；该入口在任何设备都应让用户对同一空间发起巡检与同步。数据落点仍按来源归属隔离：服务端可见空间内各 publisher 的索引，每台本机只下载并维护自身拥有或明确授权的来源，不把其他本机的目录路径、媒体记录或来源专属索引复制到本机。本机账号 publisher 的安全上行已实现；publisher 范围下行及应用器已覆盖部分元数据类型，但还没有覆盖完整索引，所以当前实现尚不能满足完整需求。

## 未完成的上线门槛

- publisher-scoped 下行目前覆盖分类断言/拒绝/聚类、照片 VLM 描述/位置、人脸及审核状态、视频摘要/转录/关键帧/人脸，以及已有 metadata-edit 记录；尚未覆盖所有目录/媒体元数据表的变更、完整 tombstone、目录/标签/相册等空间级对象的创建与重命名，也没有完整 baseline/reset 协议。因此仍不能宣称所有用户空间索引都已双向收敛。
- 人工冲突选择、完整 tombstone 保留/压缩、publisher cursor baseline 重置、撤权中断及 A/B 设备真实隔离 E2E 尚未完成。
- 手动巡检远程模式能检查远端镜像；本地账号模式检查本机授权来源并发布所选来源，同时拉取已覆盖的 publisher-scoped 元数据类型。完整索引下行仍待完成。
- 统一按钮目前尚不能向空间内每台在线/离线来源设备下发持久同步请求；全空间设备协调、离线待办与逐设备回执仍待开发，当前一次巡检不能宣称所有本机均已完成同步。
- 云端新建标签/相册/人物及新检测照片人脸、视频帧/人脸已接入身份认领；人物别名、账号级聚类偏好等尚未全面纳入双向协议。认领中断同时发生 epoch/范围变化的完整恢复验收仍待完成。
- 因果版本、完整删除墓碑及冲突审核仍是硬缺口：客户端未读到远端撤回却先发布旧快照时，仍需防止旧快照复活远端删除。内容哈希型拒绝也需要补充 publisher 归属和同内容跨设备隔离验收。当前快照修剪不等于这些门槛已完成。
