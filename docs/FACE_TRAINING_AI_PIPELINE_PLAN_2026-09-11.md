# 人脸训练 AI 数据管线开发计划与 TODO

## 目标

用户只需在 Picer GUI 中创建人物并进行已有的人脸归类操作。GUI 将人物、已归类人脸、错误归类动作和必要的向量证据提交到统一 ModelServer。ModelServer 使用配置的 VL/语言模型自动描述、去重、筛选正负样本、构建防泄漏训练/验证集并训练；只有评估不达标或数据不足时，才向 GUI 请求最小补充操作。

## 现状盘点

- 已有：训练快照、基本防泄漏分组、ModelServer jobs/datasets/artifacts、GPU Worker、异步进度、制品哈希和客户端应用。
- 部分已有：人物确认向量、错误归类记录、相似度去重、训练门禁。
- 未完成：操作日志正式协议、VL 属性标注、AI 样本配方器、困难样本平衡、数据不足反馈、真正模型训练适配器、多算法切换验收。

## 分阶段路线

### 阶段 1：数据证据协议（FACE-TRAIN-001）

1. 定义 `SampleEvidence`、`UserActionEvidence`、`MediaGroupEvidence` 和 `VlAttributes`。
2. GUI 仅提交已创建人物及其人工归类/排除动作；不提交未确认候选人物作为正样本。
3. 所有样本带 image/face/videoKeyframe ID、模型版本、哈希、连拍组和原图组标识。
4. 增加协议版本、请求幂等键和制品数据快照哈希。

验收：同一人物、同一原图、连拍组、视频关键帧可追溯且不会泄漏到不同数据集。

### 阶段 2：用户操作日志（FACE-TRAIN-002）

1. 将确认归类、改分类、标记不是此人、不分类、撤销写入不可变事件表。
2. 事件关联 face/image/person，并保留时间、客户端版本和来源。
3. 错误归类自动成为排他负样例候选，必须经过策略器复核。

验收：重复提交幂等；历史事件可重放；不会覆盖用户最终状态。

### 阶段 3：平台 AI 数据配方器（FACE-TRAIN-003）

1. 根据人物、向量、操作日志生成候选集。
2. 按哈希、同名文件、向量距离和连拍时间窗口去重。
3. 自动选择正脸、侧脸、逆光、暗光、眼镜、帽子、微笑、小脸等覆盖样本。
4. 自动构建排他负样本：相似向量但用户明确标记为其他人物的样本优先。
5. 按原图组/连拍组/视频关键帧组拆分训练和验证集。
6. 输出每个样本的选择/排除原因。

验收：生成的配方可复现；正负样本不交叉；每个人物达到最小样本策略或输出数据不足原因。

### 阶段 4：VL 属性标注（FACE-TRAIN-004）

1. 调用统一平台配置的 VL 服务，禁止客户端直接调用模型。
2. 输出固定 JSON：姿态、光照、遮挡、表情、清晰度、脸部大小、是否适合训练。
3. 缓存按图片哈希、模型版本和提示词版本复用。
4. VL 失败可重试，不能阻塞整个训练任务。

验收：属性 JSON 可校验；模型不可用时回退到向量/元数据策略；不改变用户归类。

### 阶段 5：训练、评估与门禁（FACE-TRAIN-005）

1. 先接入 prototype calibration 适配器作为基线。
2. 统一算法适配器接口，支持切换 SFace/其他基模。
3. 计算人物级 Precision、Recall、FAR、FRR、未知拒识率和困难分组指标。
4. 新旧策略自动对比，劣化时阻止应用。
5. 生成签名制品、训练报告和失败分析。

验收：真实 GPU Worker 完成训练；门禁准确阻止劣化；报告可解释。

### 阶段 6：GUI 闭环（FACE-TRAIN-006）

1. 显示训练任务、阶段、进度、日志和结果。
2. 显示自动选样统计、去重统计和 VL 属性摘要。
3. 数据不足时只提示最小补充动作。
4. 三阶段授权：准备、提交、应用制品。
5. 应用成功后刷新人物列表、自动归类和索引。

验收：训练异步，不阻塞 UI；失败可重试；取消后状态一致。

## 测试门禁

- 数据：幂等、防泄漏、去重、正负样本不交叉。
- AI：VL 超时/错误/缓存/版本变更测试。
- 训练：GPU/CPU 回退、取消、恢复、失败分析、制品哈希。
- 评估：人物级指标、困难分组、未知拒识、劣化阻止。
- GUI：异步不卡顿、状态刷新、授权流程、错误可继续使用。
- E2E：GUI 提交 → ModelServer → GPU Worker → 评估 → 签名 → 下载 → 应用 → 索引更新。

## 开发原则

平台负责 AI 和训练决策，GUI 负责证据采集、授权和结果呈现；不引入第三方数据治理，不改变原图；所有模型调用通过统一 ModelServer；所有训练结果可追溯、可复现、可回滚。
