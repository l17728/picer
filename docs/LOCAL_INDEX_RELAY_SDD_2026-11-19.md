# 本机索引服务与云端 Relay 架构设计（2026-11-19）

## 1. 目标

将索引数据库、全文索引、缩略图缓存和原始媒体访问能力保留在用户控制的本机。公网组件只承担设备注册、配对、在线状态和加密长连接转发，不保存索引、原图或缩略图。

本设计替代“本机与服务器双向实时索引同步”作为在线访问前置条件。同步能力降级为可选的备份、迁移和灾备能力。

## 2. 组件边界

| 组件 | 职责 | 持久化内容 |
|---|---|---|
| Picer.App | GUI、来源选择、查询和展示 | 本地配置、用户缓存 |
| 本机 IndexService | SQLite、FTS5、查询、分类、描述状态、缩略图路由 | `picer.db`、WAL/SHM、热缓存 |
| MediaAgent | 授权读取原图/视频和源目录 | 设备凭据、扫描检查点 |
| Relay | 注册、配对、心跳、请求/响应/媒体流转发 | 设备状态和短期连接状态 |

Relay 不执行 SQL、不保存索引快照、不缓存原图和缩略图。IndexService 通过出站长连接连接 Relay，避免开放本机入站端口。

## 3. 索引来源切换

GUI 提供“索引来源”：

- 本机索引：GUI → 本机 IndexService；
- 服务器索引：GUI → Relay → 目标设备 IndexService。

切换来源必须关闭旧查询会话、清空分页游标和来源相关缓存引用，重新加载目录、分类、人物和搜索状态，并在窗口标题显示来源设备和地址。切换不要求重启 GUI 或手动重配 MediaAgent。

当前来源是写入目标：描述、分类、人物编辑和其他索引变更不得静默写入另一来源。

## 4. 连接和安全

1. Relay 使用设备注册和一次性配对码建立设备关系。
2. IndexService 主动建立 TLS 长连接并周期性心跳。
3. GUI、Relay、IndexService 之间使用设备身份密钥和请求绑定，Relay 只转发密文流。
4. 原图、缩略图、人脸裁剪图和视频缩略图不落 Relay 磁盘。
5. 本机 IndexService 保持现有授权检查；Relay 不提升访问权限。
6. 设备撤销后，Relay 拒绝新流，本机服务关闭已有流。

## 5. 数据和缓存

索引数据库主要保存媒体元数据、关系、FTS5、描述状态和缩略图引用；原图和缩略图二进制位于源目录或独立缓存目录。若启用缓存归档，媒体内容采用文件级 AES-256-GCM 加密，目录结构和文件名保持不变，读取前由本机服务解密。

SQLite 只运行在本地磁盘。网盘或 Relay 不承载在线 SQLite、WAL、SHM 或随机事务写入。

## 6. 原同步能力调整

实时双向索引同步不再是 GUI 访问的前置步骤。保留以下可选能力：

- 加密数据库快照导出/导入；
- 灾备恢复；
- 设备迁移；
- 手工复制描述或分类结果。

不同索引来源不自动合并。导入必须经过版本、设备和内容哈希校验。

## 7. 迁移步骤

1. 在本机 IndexService 增加 Relay Connector 和连接状态 API。
2. Relay 增加设备注册、配对、心跳和双向流转发。
3. GUI 增加索引来源选择器和来源切换生命周期。
4. 将 MediaAgent 的连接配置与本机 IndexService 绑定，支持一次配置自动生效。
5. 将旧实时镜像同步改为显式备份/迁移入口。
6. 完成 E2E 验收后再移除旧同步入口，保留兼容读取和回滚开关一个版本周期。

## 8. 非目标

本阶段不迁移 SQLite 到 PostgreSQL/MySQL，不把数据库放到网盘，不实现同态加密或服务端全文索引，不改变原始媒体只读和授权访问不变量。

## 9. 验收指标

- 本机模式无公网时可查询和浏览；
- Relay 模式无需开放本机入站端口；
- Relay 重连后请求可恢复且不重复提交写操作；
- 来源切换后不出现跨来源目录、缩略图或描述结果；
- Relay 进程磁盘无索引和媒体落盘；
- 缩略图和原图仍共享现有缓存语义；
- 现有索引、分类、描述和 MediaAgent 回归用例全部通过。

## 10. 评审补充与定稿决议

评审重点覆盖了安全边界、数据一致性、断线恢复和来源切换。定稿补充如下：

1. Relay 只转发端到端密文；TLS 保护传输，设备会话密钥保护 Relay 不能读取的请求正文和媒体流。
2. 每个请求必须带设备会话 ID、单调序列号、过期时间和幂等键；写入请求在重连后只能提交一次。
3. Relay 只允许有限的并发流和单连接带宽，客户端使用有界队列和背压，防止缩略图预取耗尽本机资源。
4. 配对码为一次性、短时有效；设备撤销、密钥轮换和旧会话失效必须是原子操作。
5. Relay 只记录设备 ID、请求 ID、状态码和耗时，不记录路径、查询文本、人物名、描述文本或媒体内容。
6. 本机服务不可用时，GUI 必须显示离线，不把服务器索引误显示成本机索引，也不自动触发全量同步。
7. 本机写入在断线时明确标记为未提交；恢复后按幂等键重试，不能静默丢失或写入错误来源。

以上决议作为本设计定稿基线，重构必须先实现协议和状态机，再接入 GUI 入口。
