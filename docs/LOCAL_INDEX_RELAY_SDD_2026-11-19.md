# 本机索引服务与云端 Relay 架构设计（2026-11-19）

## 1. 目标

将索引数据库、全文索引、缩略图缓存和原始媒体访问能力保留在用户控制的本机。公网组件只承担设备注册、配对、在线状态和加密长连接转发，不保存索引、原图或缩略图。

本设计支持两种互斥运行模式。模式由 GUI 开关选择，切换不是即时改地址，而是一个有序迁移事务。

## 2. 组件边界

| 组件 | 职责 | 持久化内容 |
|---|---|---|
| Picer.App | GUI、来源选择、查询和展示 | 本地配置、用户缓存 |
| 本机 IndexService | SQLite、FTS5、查询、分类、描述状态、缩略图路由 | `picer.db`、WAL/SHM、热缓存 |
| MediaAgent | 授权读取原图/视频和源目录 | 设备凭据、扫描检查点 |
| Relay | 注册、配对、心跳、请求/响应/媒体流转发 | 设备状态和短期连接状态 |

Relay 不执行 SQL、不保存索引快照、不缓存原图和缩略图。IndexService 通过出站长连接连接 Relay，避免开放本机入站端口。

### 多租户隔离

IndexService 必须支持多租户。每个租户拥有独立的租户 ID、设备命名空间、数据库工作副本、媒体缓存根目录、密钥和任务队列。SQLite 采用“每租户独立数据库文件”方案，避免遗漏 `tenant_id` 条件造成跨租户读取；共享进程只共享代码和连接监听器，不共享数据库连接、缓存路径或授权上下文。

Relay 的每个请求必须绑定 `tenant_id + device_id + session_id`，并在转发前校验租户成员关系、设备授权和请求作用域。租户 A 的 GUI、索引、缩略图、原图流、描述任务和日志不得出现在租户 B 的响应或持久化目录中。管理员操作也必须显式携带租户上下文并写入审计日志。

## 3. 两种索引模式与切换状态机

### 本地索引模式

本机 IndexService 持有权威索引。Relay/网关只负责请求和媒体流转发，不执行索引同步，也不保留远程索引副本。

### 服务索引模式

保持现有服务索引架构。目标 IndexService 持有权威索引，客户端通过现有同步协议同步索引和描述结果；Relay 只增加公网连接能力，不改变同步语义。

服务索引模式采用单一权威源的双向传递：客户端本地镜像中的授权修改通过持久化待提交队列上行，服务器索引变更通过通知/增量读取下行。它不是两个可独立写入主库的无冲突双向合并。断线时保留待办和 revision，不得假报同步完成；在网络恢复、授权有效且冲突可处理时继续重试，最终收敛。GUI 远程浏览直接读取服务器索引，因此不以镜像是否追平作为浏览可用条件。

### 切换顺序

切换必须经过 `Preparing -> Syncing -> Switching -> Cleanup -> Active/Failed`：

1. 停止新写入和分页请求，保留当前任务状态；
2. 对目标模式执行一次完整的索引同步；
3. 执行一致性检测：比较 source/device/revision、媒体数量、内容哈希摘要、描述版本和待提交队列；
4. 使用目标模式执行只读探针（目录、搜索、分类和一张缩略图），全部通过后才允许切换；
5. 原子切换 GUI 的索引来源和写入路由；
6. 切换到本地索引模式时，确认同步和一致性检测成功后删除客户端的远程索引镜像副本和镜像缓存；服务器权威索引不由模式切换隐式删除。
7. 清空旧来源分页、缩略图引用和查询缓存，重新加载界面；
8. 任一步失败都保留原模式，不删除远程数据，并显示可重试状态。

客户端远程镜像清理只能发生在“同步成功、一致性检测通过且已切换到本地模式”之后，不能因同步失败、检测失败、取消或断线触发；服务器权威索引删除必须走独立的确认和管理流程。

GUI 提供“索引来源”：

- 本机索引：GUI → 本机 IndexService；
- 服务器索引：GUI → Relay → 目标设备 IndexService。

切换来源必须关闭旧查询会话、清空分页游标和来源相关缓存引用，重新加载目录、分类、人物和搜索状态，并在窗口标题显示来源设备和地址。切换不要求重启 GUI 或手动重配 MediaAgent。

当前模式是唯一写入目标：描述、分类、人物编辑和其他索引变更不得静默写入另一来源。服务索引模式继续使用既有同步任务；本地索引模式只写本机数据库。进入本地索引模式后，连续同步必须关闭；模式切换事务仍必须执行一次完整同步和一致性门禁，不能把“关闭连续同步”解释为跳过切换同步。

本地索引模式中，云端 Relay 仅转发请求和媒体数据，不启动索引上行、下行、空间变更通知或镜像重试；索引仅写本机权威数据库。服务器索引模式的“最终一致”依赖可恢复网络/授权、可读的持久化待办和无待解决冲突；永久故障或需要人工裁决的冲突不承诺自动收敛。

## 4. 连接和安全

1. Relay 使用设备注册和一次性配对码建立设备关系。
2. IndexService 主动建立 TLS 长连接并周期性心跳。
3. GUI、Relay、IndexService 之间使用设备身份密钥和请求绑定，Relay 只转发密文流。
4. 原图、缩略图、人脸裁剪图和视频缩略图不落 Relay 磁盘；在服务索引模式下，媒体文件内容使用文件级加密，数据库保持现有可查询结构，不对数据库字段做加密。加密算法由程序自动选择高性能安全实现（优先 AES-256-GCM 硬件加速，必要时回退 XChaCha20-Poly1305），用户无需选择算法或填写额外参数。
5. 本机 IndexService 保持现有授权检查；Relay 不提升访问权限。
6. 设备撤销后，Relay 拒绝新流，本机服务关闭已有流。

## 5. 数据和缓存

索引数据库主要保存媒体元数据、关系、FTS5、描述状态和缩略图引用；原图和缩略图二进制位于源目录或独立缓存目录。服务索引模式下只加密媒体文件内容（原图、缩略图、人脸裁剪图、视频缩略图等），数据库保持明文结构和查询能力。媒体内容采用程序自动选择的文件级高性能加密，目录结构和文件名保持不变，读取前由本机服务解密。

SQLite 只运行在本地磁盘。网盘或 Relay 不承载在线 SQLite、WAL、SHM 或随机事务写入。

## 6. 原同步能力调整

实时双向索引同步在本地索引模式不再持续运行，但在切换到服务索引模式或从服务索引模式切到本地索引模式时，必须先执行且仅执行本次切换所需的一次完整同步。切换同步失败、取消或一致性检测不通过时，保留原模式并禁止删除远程副本；同一模式重复保存不属于切换，不得额外触发同步。保留以下能力：

- 加密数据库快照导出/导入；
- 灾备恢复；
- 设备迁移；
- 手工复制描述或分类结果。

不同索引来源不自动合并。导入必须经过版本、设备和内容哈希校验。

## 7. 迁移步骤

1. 在本机 IndexService 增加 Relay Connector 和连接状态 API。
2. Relay 增加设备注册、配对、心跳和双向流转发。
3. GUI 增加索引来源选择器和来源切换生命周期。
4. 将 MediaAgent 的连接配置与本机 IndexService 绑定，支持一次配置自动生效。
5. 将旧实时镜像同步改为显式备份/迁移入口。
6. 完成 E2E 验收后再移除旧同步入口，保留兼容读取、切换回滚和远程副本清理开关一个版本周期。

## 8. 非目标

本阶段不迁移 SQLite 到 PostgreSQL/MySQL，不把数据库放到网盘，不实现同态加密或服务端全文索引，不改变原始媒体只读和授权访问不变量。

## 8.1 删除确认与 Web 管理

所有删除类操作必须经过确认对话框或 Web 二次确认页，禁止通过单次 GET、单次按钮点击或后台同步隐式删除。确认内容必须显示租户、索引来源、对象数量、影响范围和是否涉及远程副本；确认令牌一次性、短时有效并绑定操作摘要。

IndexService 现有账户、设备和来源管理页面不等同于完整索引管理控制台。重构增加租户隔离的 Web 管理入口，提供：

- 手动删除索引记录、远程索引副本和缓存；
- 开启/关闭 Relay 中转及查看连接状态；
- 发起索引上移、迁移、恢复和一致性检测；
- 查看任务、审计日志和失败原因。

Web 管理入口与 GUI 共用授权范围、确认流程、任务状态机和审计记录。删除原始媒体仍必须走现有用户授权文件操作，不允许 Web 管理直接删除原图。

## 9. 验收指标

- 本机模式无公网时可查询和浏览；
- Relay 模式无需开放本机入站端口；
- Relay 重连后请求可恢复且不重复提交写操作；
- 来源切换后不出现跨来源目录、缩略图或描述结果；
- Relay 进程磁盘无索引和媒体落盘；
- 缩略图和原图仍共享现有缓存语义；
- 现有索引、分类、描述和 MediaAgent 回归用例全部通过。

## 10. 评审补充与定稿决议

评审重点覆盖了安全边界、数据一致性、断线恢复和来源切换。定稿补充如下：

1. Relay 只转发端到端密文；TLS 保护传输，设备会话密钥保护 Relay 不能读取的请求正文和媒体流。
2. 每个请求必须带设备会话 ID、单调序列号、过期时间和幂等键；写入请求在重连后只能提交一次。
3. Relay 只允许有限的并发流和单连接带宽，客户端使用有界队列和背压，防止缩略图预取耗尽本机资源。
4. 配对码为一次性、短时有效；设备撤销、密钥轮换和旧会话失效必须是原子操作。
5. Relay 只记录设备 ID、请求 ID、状态码和耗时，不记录路径、查询文本、人物名、描述文本或媒体内容。
6. 本机服务不可用时，GUI 必须显示离线，不把服务器索引误显示成本机索引，也不自动触发全量同步。
7. 本机写入在断线时明确标记为未提交；恢复后按幂等键重试，不能静默丢失或写入错误来源。
8. 多租户请求、缓存、数据库、设备和日志均通过隔离检查；缺失或不匹配租户上下文时拒绝请求。

以上决议作为本设计定稿基线，重构必须先实现协议和状态机，再接入 GUI 入口。模式切换的同步、客户端远程镜像清理和失败回滚是强制步骤；服务器权威索引删除不属于自动切换事务。
