# 人工元数据字段版本与冲突处理

日期：2026-10-23。开发源码 schema62，未发布部署；本节代码仍在回归验证，不能视为完整双向同步已交付。

## 本轮覆盖

人物姓名、描述、别名，以及照片标签、相册照片、视频标签和视频分类人工决定，沿用 `metadata_edits` 的稳定业务字段。请求携带用户已知的字段基线；IndexService 在写业务行、字段版本和操作回执的同一事务内分配单调版本。设备时间戳不再决定这些权威写入的先后。

同字段基线过旧时，保留双方内容，不采用后来到达的旧修改。不同字段独立提交。重复操作返回持久回执；同一操作编号换载荷会被拒绝。旧版没有字段版本的请求不能覆盖已版本化字段。关联移除仍以明确的 `0` 决定持久保存，旧关联快照会被该决定重放纠正。

来源和远程 GUI 合并服务端版本时，先保存尚未提交的本机不同内容为冲突；读取旧基线不会清掉已基于该基线创建的待提交操作。视频字段继续按强内容身份匹配，多个引用不会各自形成独立版本。删除引用时转移剩余引用仍需的回执和冲突；最后一个引用、人物或关联目标被明确清除后，清理其相关历史载荷。

## 用户操作

1. 打开“索引巡检、同步与修复”。
2. 点击“处理同步冲突…”。
3. 选择一项，查看“我的修改”和“当前版本”。
4. 点击“采用我的修改”，生成基于当前字段版本的新操作并排队同步；或点击“保留当前版本”，结束该项本机冲突处理。
5. 如果处理期间收到新版本，刷新后重新查看并选择，不自动覆盖尚未审阅的新内容。

来源巡检存在待处理冲突时返回明确失败原因，不显示整个空间已同步完成。冲突界面最多列出 500 项，处理后可继续刷新。原始照片和视频始终不受影响。

## 尚未覆盖

本轮不是所有元数据的统一字段事件层。分类断言/拒绝、模型描述、检测结果、目录实体删除/改名及账号偏好仍需按后续协议接入；完整事件压缩、基线重置及 A/B 来源加远程 GUI 的整体验收尚未完成。服务器保留冲突历史，当前界面处理本机合并发现的冲突，不宣称已提供服务器所有来源冲突的集中管理。
