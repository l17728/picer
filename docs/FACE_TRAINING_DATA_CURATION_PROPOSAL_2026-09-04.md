状态：第一阶段已批准（2026-09-09），实施中——泄漏组/不可变快照/确定性切分核心已落地（见 FACE_TRAINING_DATA_CURATION_IMPLEMENTATION_2026-09-09.md）；三阶段授权 UI、安全提交协议、VL 辅助分层为后续增量
范围：只设计，不授权开发
基础模型：YuNet 检测 + SFace 向量；人工确认身份是唯一真值

## 1. 目标

从用户已经确认/否定的人脸中，构造覆盖充分、困难样本适量、无内容泄漏、可复现的数据快照，提交统一模型平台训练人物决策策略或轻量度量适配器。目标不是挑选“最好看”的照片，而是在身份可靠的前提下覆盖真实变化，并用独立验证集证明新制品没有提高误认风险。

VL 只描述可见条件和辅助分层，不确认身份、不改变标签、不直接决定样本去留。人物姓名不发给 VL；VL 仅接收随机样本 ID 和裁剪后的人脸/必要的低分辨率上下文。

## 2. 输入与可信度

| 数据 | 用途 | 是否可作为身份真值 |
|---|---|---|
| 用户点击“是”、主动移动到人物 | 正样本 | 是 |
| 用户点击“不是”、从错误人物移出 | 困难负样本 | 是 |
| 自动推荐、候选组 | 候选池/待审阅 | 否 |
| SFace 相似度、检测置信度 | 难度与质量分层 | 否 |
| 姿态、模糊、脸面积、遮挡 | 覆盖度与质量控制 | 否 |
| VL 外观描述 | 辅助分层与审计 | 否 |
| 时间、地点、场景、共同出现人物 | 防泄漏分组及抽样多样性 | 否 |

## 3. 处理流水线

```text
人工标注快照
 → 内容去重与泄漏组构建
 → 基础质量/姿态/向量难度计算
 → VL 辅助属性描述（可选、缓存、无姓名）
 → 人物内分层和配额抽样
 → 按泄漏组切分 train/validation/test
 → 训练前审计与用户预览
 → 脱敏提交统一平台
 → 影子评测、门禁、批准应用或回滚
```

每次提交形成不可变快照，记录规则版本、随机种子、基础模型哈希、成员和排除原因。相同输入重复运行必须得到相同结果。

## 4. 防泄漏分组

以下内容必须作为不可拆分的 `leakage_group`，整体进入同一个数据分区：

1. 相同 SHA-256 的原图及其所有人脸裁剪。
2. 同一原图中的全部衍生缩略图、人脸裁剪和增强版本。
3. 感知哈希高度相似且拍摄时间接近的连拍/近重复照片。
4. 同一视频及其全部关键帧、人脸轨迹和音视频衍生物。
5. 无可靠哈希时，以来源文件 ID 为最低保障分组，禁止按单个人脸随机切分。

优先按时间段/事件做组级切分，使验证集包含训练阶段未出现的拍摄条件，而不是同一连拍的另一帧。

## 5. 样本特征与分层

### 5.1 确定性视觉指标

- 人脸框像素面积及相对画面面积。
- 检测置信度、关键点完整性和关键点几何姿态。
- yaw/pitch/roll 或正面、轻侧、重侧分桶。
- 清晰度、曝光、动态模糊、遮挡比例。
- SFace 向量到本人物原型的距离、到最近其他人物原型的距离及二者 margin。
- 是否来自视频、连拍、旧照片或低分辨率来源。

### 5.2 VL 辅助属性

VL 只输出严格 JSON，不输出姓名、身份、关系、性别或敏感属性推断：

```json
{
  "pose": "frontal|slight_side|profile|unknown",
  "occlusion": ["glasses", "sunglasses", "hat", "mask", "hair", "hand", "other"],
  "lighting": "daylight|indoor|backlit|low_light|mixed|unknown",
  "expression": "neutral|smile|eyes_closed|other|unknown",
  "imageQuality": "high|medium|low|unusable",
  "context": "portrait|group|activity|video_frame|unknown",
  "visibleNotes": ["不超过三个简短、可见、非身份属性"],
  "uncertainty": 0.0
}
```

提示词要求：仅描述画面可见条件；不得依据分类目录猜测人物；不确定时输出 `unknown`；不得把服装、背景或共同出现者作为身份依据。VL 结果与几何姿态冲突时，以确定性指标为主并标记冲突，不静默覆盖。

## 6. 训练数据配方

配方按人物独立执行，再做全局平衡。默认目标值必须通过冻结验证集调优，不能作为永恒常数。

### 6.1 正样本建议配比

| 层 | 建议比例 | 说明 |
|---|---:|---|
| 典型高质量样本 | 35% | 清晰、脸面积足够、接近人物原型，稳定主身份中心 |
| 姿态多样样本 | 20% | 正脸、轻侧脸和可用侧脸按覆盖缺口抽取 |
| 光照/遮挡多样样本 | 15% | 眼镜、帽子、低光、逆光等真实变化 |
| 跨时间/设备/场景样本 | 15% | 优先不同事件和时间段，抑制背景记忆 |
| 低分困难正样本 | 15% | 必须人工确认且仍可辨认；按难度分桶，不能全部丢弃 |

低分正样本不是越多越好：它能提高召回，但过量会扩大人物边界并提高误接受率。首版将低分正样本限制在约 10%–20%，其中极低质量或人脸不可辨认样本排除训练，仅进入审计集。若某人物样本不足，宁可提示覆盖不足，不复制样本制造数量。

### 6.2 负样本建议配比

| 层 | 建议比例 | 说明 |
|---|---:|---|
| 用户明确否定的困难负样本 | 45% | 最高价值，尤其是曾被推荐为该人物的脸 |
| 最近邻其他人物 | 30% | 依据 SFace 距离选容易混淆者，身份必须已确认 |
| 普通随机负样本 | 15% | 保持全局边界，不让训练只关注少数近邻 |
| 同场景/同时间负样本 | 10% | 防止模型利用背景、服装或共同出现关系 |

每个正样本可配置 1:2 至 1:4 的负对/三元组，但按人物和泄漏组去重。同一负样本不能因重复抽样无限放大权重。

### 6.3 样本上限与人物不平衡

- 每人物设置最小有效泄漏组数量，而非只看人脸张数。
- 人物样本过多时优先保留覆盖不同分桶的代表样本和困难样本。
- 训练批次采用人物均衡采样，避免照片最多的人物支配梯度。
- 样本极少人物只训练原型/阈值，不进入适配器正式指标，也不自动扩大阈值。

## 7. 数据切分

建议首版 `70% train / 15% validation / 15% test`，按泄漏组和人物分层。正式 test 在制品选择前保持封存；阈值与超参数只看 validation。若数据较少，使用按泄漏组的 K 折交叉验证，但最终仍保留一次未参与选择的封存测试。

训练与验证必须包含未知人物拒识集合。负样本不能只从已命名人物内部产生，还需包含用户标记“不分类”的真实路人，但这些样本只能作为未知负例，不能推断其身份。

## 8. 训练类型与开放条件

1. `prototype-calibration`：当前可用；多原型和每人物阈值，无权重训练。
2. `embedding-adapter`：建议下一阶段开放；冻结 SFace，训练小型归一化投影/度量适配器。
3. `sface-finetune`：暂不开放；只有数据规模、授权、独立测试、算力与回滚全部达标后评审。

适配器不得覆盖基础 SFace 文件。制品必须带基础模型哈希、输入维度、归一化约定、数据快照、指标、训练代码版本和 SHA-256。

## 9. 评测与自动应用门禁

至少报告：宏平均 precision/recall、FAR、FRR、未知拒识率、top-1/top-k、每人物指标及正脸/侧脸/低光/遮挡/小脸/视频等分组指标。

建议默认门禁：

- 高置信自动建议 precision ≥ 99%。
- FAR 不高于当前制品超过 0.1 个百分点。
- 宏平均 recall 不下降超过 1 个百分点。
- 任一有足够样本的重点困难分组不得显著退化。
- 训练/验证/test 泄漏组交集必须为零。

未满足门禁时只保存候选报告，不自动应用。任何制品应用只重算自动建议，不改变人工确认、不分类、标签、目录或原文件。

## 10. 提交协议与隐私

Picer 向统一平台提交：匿名人物 ID、匿名样本 ID、正负标签、向量/经用户允许的人脸裁剪、质量指标、VL 分桶、泄漏组、分区和版本信息。默认不提交姓名、原图路径、GPS、相册、场景文字或亲属关系。

如果训练类型只需要向量，禁止上传人脸像素。需要裁剪图训练适配器时，UI 必须单独说明数据范围、目标地址、本地/远程性质和保留期限，并由用户确认。

## 11. UI 工作流（待批准后开发）

```text
人物 → 人脸精度验证 → 准备训练数据
  1. 扫描与分层（可取消，显示进度）
  2. 数据配方预览：每人物/每分桶数量、排除原因、泄漏检查
  3. 可调整低分正样本比例与是否启用 VL 辅助描述
  4. 冻结快照并提交
  5. 查看训练/验证/test 指标和相对当前版本变化
  6. 门禁通过后应用；否则仅保留报告
```

预览界面必须允许从每个分桶抽查原图，显示“为什么选入/排除”，但不得让用户通过逐张勾选破坏封存测试集的独立性。

## 12. 日志与回归

- 日志记录任务、匿名样本数、分桶、阶段、耗时、规则/模型版本和错误，不记录姓名、路径、向量或图片内容。
- 测试覆盖确定性抽样、零泄漏、低分比例边界、人物不平衡、VL 无效 JSON/离线/冲突、取消恢复、平台失败、门禁拒绝、回滚和人工标注不变。
- 性能测试覆盖 1 万和 10 万人脸；筛选及上传均在后台，前台人物/目录切换保持响应。

## 13. 待专家重点评审

1. 低分困难正样本 10%–20% 是否合理，是否应按人物动态确定。
2. 负样本配比及同场景负样本是否会引入新的偏差。
3. VL 属性集合是否足够且避免敏感属性与身份泄漏。
4. 小数据条件下 K 折、封存测试及自动应用门禁是否科学。
5. 轻量适配器的损失函数、采样策略和制品兼容约束。

## 14. 独立专家评审结论

人脸识别/度量学习专家与数据治理/MLOps 专家均给出“方案方向正确、有条件通过设计，但修订前不应批准开发”。下列修订条款优先于前文中与其冲突的初始建议。

### 14.1 身份标签语义

训练标签必须区分：

- `positive_for(personId)`：人工确认属于该人物。
- `negative_for(personId)`：人工确认不属于这个特定人物，不能推导为其他人物的负例。
- `unknown_to_all_enrolled`：用户明确确认不属于任何已命名人物，才可进入开放集未知集合。

普通“不分类”不自动等于未知人物。同一 FaceId 出现多个正身份或正负冲突时阻断提交并要求修正。快照保存标签来源、操作时间、冲突状态和同意状态；用户纠正、删除或撤回同意时，相关快照和制品可被定位并标记失效。

### 14.2 正确的快照、切分与挖掘顺序

```text
冻结原始人工标注和数据库一致性高水位
 → 建立跨人物的全局素材关系图
 → 取连通分量作为 leakage_group
 → 先冻结 train / validation / test manifest
 → 仅用 train 计算原型、归一化、难度并挖掘负例
 → 仅用 validation 选配方、阈值与超参数
 → test 只在规定发布节点对冻结管线评测
```

强制关系包括相同文件、近重复、明确连拍、同一视频/轨迹和派生裁剪。普通同日、同地点或共同出现只用于分层，避免生成巨型组。切分后执行跨分区 pHash 和人脸向量近邻审计；发现疑似泄漏时合并整个连通分量并重新切分。验证/test 人脸不得参与原型、困难负例、人物阈值、VL 配额或模型选择。

### 14.3 测试集治理

同一个封存 test 不能在每轮训练后反复查看并用于决定调参，否则它会退化成 validation：

- 固定基准 test 只在明确里程碑解封，并记录评测次数。
- 日常候选使用 validation、滚动未来时间/事件隔离集和只读影子回放。
- 报告默认不暴露封存 test 的逐样本反馈；用户若纠正其成员标签，该切分立即废弃并整体重建。
- 小数据使用 nested group CV；若不能保留足够独立组，禁止自动应用。

### 14.4 样本配方修订

正样本类别可重叠，不能机械相加成 100%。改用多标签覆盖约束：典型高质量最低量、姿态/光照/遮挡各自最低独立组数、跨时间/事件最低覆盖，以及困难样本总权重上限。一张样本可以满足多个覆盖目标，但训练权重只计一次，单个泄漏组贡献封顶。

低分正样本先分为：

- `informative_hard_positive`：人工可辨认、代表真实姿态/年龄跨度/光照变化，可以进入训练。
- `technical_failure`：错裁、严重模糊、脸不可辨认，排除训练。
- `label_suspect`：与所有独立组严重偏离，要求再次确认。

10%–20% 只作为困难正样本的初始权重上限，最终按人物有效组数和 train 内 margin 动态确定。负样本采用“覆盖性随机负例 + train 内 hard-negative mining”；每个 face、人物对和泄漏组设权重上限。同场景只作抽样属性，适配器默认只训练对齐后的紧人脸裁剪，不让背景进入模型。

### 14.5 开放集评测与统计门禁

明确区分 1:1 验证与 1:N 开放集识别，固定候选库规模、工作点和阈值规则。报告 FMR/FNMR、FPIR/FNIR、Rank-1、TPIR@固定 FPIR、拒识 ROC/DET、宏/微指标、每人物错误接受数、最差人物分位数、校准误差、分组指标、样本量和组级 bootstrap 置信区间。

门禁采用同一冻结集上的新旧制品配对比较：候选 FPIR 置信区间上界不得高于当前正式制品，FNIR 不得超过退化容忍值，人工确认样本不得身份翻转，困难分组不得显著退化。零次错误不代表零风险；证明约 0.1% 误匹配率通常需要约 3000 个独立负例量级，最终按置信区间计算。统计功效不足只生成报告，不自动应用。

### 14.6 VL 的受限角色

VL 是可选审计和覆盖分层工具，不是训练必要依赖：

- 不提供人物名、目录名、人物组名或同组批次上下文。
- 输出仅允许枚举 schema；删除自由文本 `visibleNotes`，降低敏感属性生成风险。
- 不确认身份、不修改标签、不决定 `unusable`，不以表情等弱相关属性设置训练权重。
- 姿态以关键点几何为主，清晰度/曝光/脸面积使用确定性算法；冲突时记录而不覆盖。
- 保留“无 VL”基线，只有在 validation 上证明增益才采用；VL 离线、换模型或无效 JSON 不改变冻结快照。
- 固化 prompt/schema、供应商、精确模型版本、温度、原始响应和规范化结果哈希；外部模型调用不宣称位级可复现。

### 14.7 生物信息、提交安全与生命周期

人脸裁剪和可复识的 embedding 都是高敏生物识别信息。随机人物 ID 只是“假名化”，不能称为匿名化。默认仅向 loopback 本机平台提交向量；远程提交 embedding 和远程提交裁剪图均需逐任务明确同意，裁剪图另设更强授权。

非 loopback 强制 HTTPS 和证书校验。协议补充认证、租户隔离、请求大小上限、manifest 哈希/签名、幂等键、分块校验、服务端落盘加密、审计、保留期限、删除 API、取消后的清理保证，并禁止平台凭样本 ID 回查本地照片。界面显示处理目的、目标主机、本地/远程、数据类别、数量、估算大小、保留期和快照哈希。

### 14.8 适配器与索引兼容

有效向量版本定义为：

```text
effectiveEmbeddingVersion = sfaceModelHash + adapterHash + normalizationVersion
```

适配器采用接近恒等映射的低秩残差结构，并加入保持原始余弦结构的蒸馏约束。应用新适配器时必须选择：保留基础向量并在查询/建库统一变换，或者后台重算全部向量、原型和近邻索引后原子切换。禁止新查询使用适配向量而旧索引仍使用原始向量。

建议最低资格：至少 8 个充分标注人物、每人物至少 5 个独立泄漏组、覆盖至少两个时间或场景条件、有目标特定负例和独立未知拒识集，并满足目标 FPIR 的统计功效。不足时自动降级为 `prototype-calibration`。

### 14.9 三阶段用户授权

“准备/预览”“冻结并提交”“应用制品”是三个独立权限点；VL 使用授权与训练平台上传授权也相互独立。默认不自动上传、不自动应用。提交后新增或修改标注不能静默改变快照；应用前再次展示基线差异并确认，采用事务或版本指针原子切换，保留旧制品、阈值和索引以一键回滚。

train 可逐样本预览；validation/test 只显示聚合覆盖，不能针对封存 test 挑选成员。应用和回滚必须验证人工归属、不分类状态、标签、目录树、索引语义和原文件逐项不变。

### 14.10 可复现、失败恢复与性能验收

快照 manifest 还需固化输入内容哈希、裁剪坐标/预处理、去重和连拍算法/阈值、split、VL 缓存版本、代码 commit、运行环境和排序规则。测试增加重复/断点提交、乱序进度、平台超时、伪造制品、取消竞态、应用中崩溃、标签变化、模型哈希不匹配、磁盘不足及远程删除失败。

扫描、哈希、VL 和上传全部后台限流。建议 UI 验收目标：输入响应低于 100ms、首个可见进度低于 500ms、进度心跳不超过 1 秒；1 万/10 万人脸记录延迟、内存和取消时间。

## 15. 提请批准的开发边界

本次只提请批准第一阶段：全局泄漏组、不可变快照、配方预览、三阶段授权、安全提交协议和强化后的 `prototype-calibration`。第一阶段用真实数据验证后，`embedding-adapter` 另行提交批准。完整 SFace 权重微调继续保持关闭。

获得用户明确批准前，不实现本方案中的训练数据筛选、VL 选样或适配器训练功能。

## 16. 面向用户的极简流程

技术安全边界必须严格，但默认 UI 不暴露泄漏组、困难负例、向量 margin、FPIR、置信区间、适配器版本或数据切分等实现术语。普通用户只经历三个动作：

```text
开始优化人物识别
  → 确认本次使用的数据范围与处理位置
  → 获得“可用的新模型”或清晰的未应用结论
```

### 16.1 第一步：开始

人物页只提供主操作“优化人物识别”。点击后程序自动完成数据检查、冲突检测、全局泄漏分组、分区、确定性质量计算、可选 VL 辅助分层和训练配方生成。界面显示自然语言阶段与进度，例如“正在整理你确认过的人物”“正在检查新标准是否更可靠”，不要求用户配置比例和算法参数。

### 16.2 第二步：一次确认

默认本机训练时，确认页只显示用户真正需要理解的信息：

- 将使用多少位已命名人物、多少组已确认样本。
- 数据仅在本机处理，或将发送到哪个远程服务。
- 使用人脸向量还是人脸裁剪；远程裁剪必须突出提示。
- 预计时间和磁盘空间。
- “开始优化”与“取消”。

VL 分层、训练平台提交和制品应用不应连续弹出多个技术确认框。它们组合为一次有意义的授权，但底层仍分别记录授权状态。只要处理目的、接收方或数据类别发生实质变化，才重新确认。

### 16.3 第三步：结果

训练与验证成功且安全门禁通过时，默认直接得到新的人物识别模型，并以普通语言展示：

- “人物识别已优化，可以用于新照片和重新自动归类。”
- 相比当前版本，误认风险是否降低、能否识别更多困难照片。
- “使用新模型”“暂不使用”和“恢复上一版”。

如果用户已在开始页勾选“验证通过后自动使用”，则门禁通过后可以自动切换，但必须保留通知、版本记录和一键恢复。人工确认的人物归属永远不被重新训练覆盖。

若门禁未通过，不向用户展示半成品模型，也不要求用户理解指标表，只说明“新模型没有比当前版本更可靠，已继续使用原模型”，并提供可选的“查看专业报告”。

### 16.4 AI 自动化原则

能可靠自动化的工作默认自动执行：

- VL 辅助识别正脸/侧脸、帽子、眼镜、遮挡、光照和场景差异。
- 自动发现重复、连拍、视频帧和异常裁剪。
- 自动区分典型样本、有效困难样本、技术失败和疑似错标。
- 自动平衡人物、时间、姿态、光照与困难负例。
- 自动选择适合当前数据量的训练方式；数据不足时退回原型/阈值优化。
- 自动运行独立验证、影子比较、安全门禁、制品登记和可回滚切换。

AI 的自动化不改变身份真值：它可以推荐“这张可能标错，需要确认”，但不能自行把一张脸从“牟”改成“二丫”。只有检测到少量身份冲突或疑似严重错标时，才弹出低门槛确认页，让用户回答“是这个人 / 不是 / 暂时跳过”。

### 16.5 高级设置

配方、分区统计、VL 模型、质量阈值、负样本策略、指标和日志全部收进折叠的“专业设置/查看技术报告”。默认设置由程序根据数据规模与当前正式模型自动决定。高级设置不是完成训练的必经步骤，也不能允许用户直接破坏封存测试集或关闭关键安全门禁。
