# 远程镜像首屏加载与人脸选择器修复（2026-11-25）

## 根因

Service 模式的 `remote-mirror.db` 是 GUI 侧的可写投影库：它承载 IndexService 已同步的镜像数据，也保存尚未确认同步的本机描述和元数据编辑。服务器 IndexService 是已提交索引的权威端；当前主界面的目录、搜索、视频和人物列表主要查询本地投影库，不是每次都直接向服务器发查询。此模式与本机索引模式不同，也还不是 Relay 目标架构。

2026-11-25 运行日志证实本地投影中有 8,603 张照片、529 个视频、8 个人物及 28,925 条人脸。冷启动时完整远程镜像同步与首屏查询并发争用 SQLite：目录树读取耗时约 14–40 秒，人脸模型选项读取耗时 227 秒；视频目录最终加载 529 项。人物页先等待大批人脸刷新，再查询训练历史，日志显示该查询直到约 9 分钟后才完成。数据库内容存在，空白来自加载时序和资源竞争。

## 修复

- 冷启动完整同步移动到目录与视频首屏加载之后开始。
- 首屏视频读取改为等待完成，不在首屏完成事件之后继续后台争用。
- 人脸模型和训练历史选择器作为小型元数据在首屏同步之前预加载；大型人脸列表仍延迟到进入人物页。
- 冷启动镜像同步完成后重新读取人物选择器和已打开的人物列表，以吸收首次同步带来的模型/训练历史。
- `PeopleModelSpaceRegressionTests` 将模型历史制品下拉框验收移到人脸列表验收之前。

## 远程目录数据源修正（进行中）

- 远程模式目录树的相册成员与位置层级改为取自 IndexService 新增的轻量 `browser-metadata` 读接口，不再从 `remote-mirror.db` 构造这两类目录。
- 服务端搜索新增 `ImageIds` 条件，目录浏览点击相册/位置/场景节点后按服务端索引分页取图片记录；不逐张发请求。
- 搜索筛选标签、相机值及人物列表也改由网关读端获取。远程“按人物名搜索”使用服务端人物目录 ID。
- 视频详情的人脸裁剪缩略图直接引用当前视频的远程关键帧共享缓存，不再用镜像数据库寻找服务器帧记录。
- HTTP、named-pipe 和本地 gateway 契约测试及 `ImageIds` 搜索测试已补充；当前全量 `Picer.Tests` 仍在执行，以上新增测试尚未运行。构建、Release/部署和 UI 验收均待全量测试结束后执行。
- 人物页脸记录、模型覆盖率、训练历史等仍存在镜像读取，未列为本次已解决。
