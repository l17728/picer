# 分类入口与网页登录配对恢复修复

状态：源码修复及专项验证完成，候选 `1.6.5-local-pairing.20261030` 位于 `E:/picer-pairing-fix-20261030/bin/`；尚未替换正在进行设备配对的 GUI，也未部署这一追加修复的 IndexService 包。正式 Release 未发布。

## 现场根因

2026-10-31 更新：本修复已随 `1.6.5-local-viewport.20261031` 部署到 GUI、本机及远程 IndexService。新 GUI 已打开，未代用户登录。详见[部署记录](VIEWPORT_DEPLOYMENT_2026-10-31.md)，本页此前的候选未部署状态保留为历史记录。

1. 用户忘记旧设备连接、尚未导入新认证文件期间，分类窗口的字段初始化立即创建 HTTP 客户端，抛出“照片空间尚未配对”。异常进入 DispatcherUnhandledException，窗口未创建，表现为菜单点击无反应。现场 crash.log 中 23:14、23:26、23:28 的调用栈一致。
2. 网页登录失败提示中的“返回登录”链接丢失 `request` 参数。用户随后成功登录只到账号首页，无法继续当前设备的审批流程。
3. 保存的旧口令通过只读验证与当前账号密码匹配。登录失败计数达到 5 时临时锁定 15 分钟；锁定到期后用保存的密码进行一次正常 HTTPS 登录，返回 `/account`、HTTP 200。未重置密码、修改账号状态或绕过设备审批。密码未写入聊天或日志。

## 修改

- 分类客户端缺少配对时使用授权异常；主窗口分类入口捕获该异常，打开现有设备连接对话框，完成后明确提示重启。未将未配对误作本地模式。
- 登录失败后的重试链接保留经过白名单校验及 HTML 编码的配对请求 ID。通过正常 CSRF/账户登录/审批流程恢复，不自动扩权。
- 当前运行版已用“文件 → 连接索引服务… → 登录照片空间 / 导入设备认证文件…”绕过分类入口异常，并从 GUI 重新发起配对。等待用户导入新认证文件后切换修复版及复验。
