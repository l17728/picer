# Picer 用户指南

## 离线自包含运行

正式 win-x64 发布包已经包含 .NET 运行时、OpenCV、人脸模型、Chinese-CLIP 中文语义模型、FFmpeg、whisper.cpp 和本地语音模型，不需要另行安装 Python、.NET、模型或视频工具，也不会在首次运行时联网下载依赖。

主窗口的“运行组件”可检查每个组件的许可证、发布路径和状态。“完整校验”会核对固定 SHA-256；“运行自检”会实际加载人脸模型并启动 FFmpeg 与 whisper.cpp。任何组件缺失或损坏时，请重新安装完整发布包，不要从不明来源替换文件。

程序首次显示主窗口时会执行不读取大模型内容的轻量预检；若发布包缺少组件，状态栏会立即显示缺失数量和部分组件名称，并引导打开“运行组件”。打开照片、视频或在资源管理器中定位失败时，状态栏或对话框会说明原文件缺失或系统打开失败，不会静默忽略。

## 存储与 WebDAV

主窗口点击“存储设置”，可在本地文件和 WebDAV 间切换。WebDAV 模式需填写服务器地址、基础路径和用户名；密码保存在 Windows 凭据管理器，不会写入配置文件、数据库或日志。保存前可执行 20 秒连接测试。

远程缓存可设置目录及 1–1000 GB 容量。保存后配置立即生效；再点击“添加文件夹”会直接添加已配置的 WebDAV 基础路径并开始索引，无需输入本地路径或重启程序。

Picer 默认只读取照片并建立索引，不主动移动、重命名或删除任何原文件。识别、问答、打标、重复检测和保留建议都不会产生文件操作。

## 中文语义检索

主窗口点击“中文语义检索”。首次使用选择“建立/继续语义索引”，App 会完全离线地为照片生成 512 维语义向量；可随时取消，下次会跳过未变化的照片继续处理。输入“海边看日落”等中文描述后，可查看 Top 20 结果及余弦相似度解释。

验证模型效果时，逐项勾选“相关”，再保存标注。App 会计算 Precision@20；如果已知图库中相关照片的总数，填写后同时计算 Recall@20。标注和指标保存在本机数据库，不上传图片、查询或路径。

## 备份、恢复与数据目录迁移

主窗口点击“备份与恢复”。“创建备份”会使用 SQLite 一致性快照保存数据库以及本地设置；人物确认、标签、人工真值和语义检索评估均包含在数据库中。原照片、Windows 凭据管理器中的密码及可重新生成的缓存不会进入备份。

恢复时，App 会先验证备份格式、数据库版本、归档路径和 SQLite 完整性。确认后程序自动重启，等待旧进程完全退出，再应用恢复；覆盖前会在当前数据目录创建 `recovery-before-restore-日期时间.zip` 快照。

“迁移数据目录”只接受空目标目录。Picer 重启后复制全部数据、验证数据库，再切换数据根目录；原目录不会自动删除，可在确认新目录运行正常后自行归档。窗口下方同时显示数据库、缩略图、视频缓存、远程缓存和随包模型的空间占用。

## 索引服务（进阶）

默认情况下，索引在本机 Picer 进程内完成，无需任何设置。进阶用户可将索引迁移到独立的服务进程：扫描、哈希、缩略图与识别全部由服务完成，关闭窗口后任务继续运行，同一图库还可供多台电脑访问。

启用方式：在 `%LOCALAPPDATA%\Picer\bootstrap\backend.json` 写入 `{"mode":"service"}`。同机场景下 Picer 会自动发现本机索引服务（`service-endpoint.json`，命名管道，免证书免端口）；跨机器访问需手动填写服务地址并确认证书指纹。主窗口“文件 → 索引服务状态”可查看当前模式、测试连接；service 模式下可从同一窗口进入“浏览图库”。数据目录迁移建议使用“迁移数据目录”完成切换，避免两份索引并存。

服务端独立部署与运维（数据根目录、端口、令牌、证书轮换、备份）见仓库 `server/Picer.IndexService` 与 `docs/INDEX_SERVICE_CS_DESIGN_2026-09-08.md`。

## Florence-2 CPU/GPU 验证

主窗口点击“Florence 运行验证”。程序会依次验证随包 INT8 视觉编码器、文本编码器、词嵌入和自回归解码器，并在 CPU 与 DirectML 上执行真实加载；视觉编码器额外执行冷态和热态推理。DirectML 只有在四个模型全部兼容且热态至少比 CPU 快 10% 时才会被推荐，否则保持 CPU。点击“保存推荐选择”会把设备、模型版本、时间和完整结果写入本机设置。

同一窗口可选择图片并执行“简短描述”“详细描述”或“OCR 文字识别”。图像预处理、多模态编码、自回归生成和 BPE 解码全部在本机完成；任务可取消。结果下方可填写期望文字并选择准确、部分准确或不准确，质量记录只保存图片 SHA-256，不保存原图路径。

主窗口“本地描述任务”用于批量处理已索引图片。可选择简短描述、详细描述或 OCR，并设置本次处理 1–500 张；默认 20 张。任务可取消，已经完成的结果会保留，下次只继续未处理或源文件发生变化的图片。

批量结果默认是“待审阅”，不会立即影响搜索。勾选“接受并进入搜索”并保存后，描述/OCR 文字才会加入主搜索；不接受的结果会记为拒绝，源文件和模型均未变化时不会重复生成。

## 未分类时间场景描述

目录树会按照片时间形成场景锚点。右键“未分类场景”并选择“描述此未分类场景…”后，程序会在该时间段内部按最大的相邻时间差最多细分为 5 组，再按照前、中、后均匀位置最多选择 3 组，并使用每组第一张照片作为代表照片。

代表照片已有云端描述时直接复用；只有缺少描述的代表照片才调用已配置的视觉 API。每张上传副本仍会缩放并清除 EXIF。程序根据代表照片的结构化场景、活动、物体和搜索词生成整组总结，用户确认后才写入数据库 v17、替换目录树中的“未分类场景”，并让整组照片可通过场景名称、摘要和搜索词检索。

选中已有云端描述的照片时，照片网格信息区会同时显示拍摄时间、地点和描述。照片内容或代表集合变化后，原场景指纹自动失效，不会错误套用到新的一组照片。

## 诊断中心与安全缓存清理

主窗口点击“诊断中心”即可完成日常维护，无需命令行。点击“运行健康检查”会校验随包组件、许可证和固定哈希，执行 SQLite `quick_check`，并显示图片、人物、人脸、语义向量、Florence 结果和视频等汇总数量。

JSON/CSV 报告默认只包含组件状态、数据库状态、数量、存储类型和非敏感设置，不包含原图路径。诊断 ZIP 会额外收集近期日志，并自动遮蔽访问令牌、密码、Authorization 请求头和本机路径；发送前仍建议用户自行查看报告内容。

缓存列表区只允许清理由 Picer 生成且可重建的缩略图、人脸缩略图和已配置的远程文件缓存。模型和视频关键帧仅显示占用，不提供删除操作。每次清理都要求选择项目并再次确认，不会删除原始照片。

## 术语

- **完全重复**：文件内容的 SHA-256 完全一致，即使文件名或目录不同。
- **视觉相似**：aHash/dHash 感知哈希接近，可能是连拍、裁剪或压缩版本，并不代表内容完全相同。
- **从索引移除**：只删除 Picer 数据库记录和生成的缩略图，原文件不变。
- **移到回收站**：仅在用户逐项决定、查看不可变方案并再次确认后执行；成功项可从 Windows 回收站恢复。
- **重新定位**：原路径失效后，以 SHA-256 验证新位置，内容不同则拒绝绑定。

## 首次使用

点击“添加文件夹”。Picer 会展示扫描阶段、数量和取消入口。添加新来源只扫描该来源；“重建索引”是独立维护操作。

## 重复与相似审阅

“查找重复”会分别显示完全重复和视觉相似、算法及相似度。保留规则只生成建议。只有明确标记至少一个“保留”和一个或多个“移到回收站”，再检查并确认删除方案后，Picer 才会请求 Windows 回收站操作。取消、关闭或“稍后”均不修改文件。

## 缺失文件

“缺失”表示索引路径当前不可访问，不代表文件已删除。选择新根目录可预览 SHA-256 匹配、冲突和未匹配项；确认后只更新匹配成功的索引路径。

## 标签与本地建议

选择图片后可添加用户标签。建议区只根据已索引的尺寸、时间、GPS 等本地元数据生成，不外发图片；拒绝的建议会被记录且不再自动出现。

## 键盘

- `Ctrl+F`：聚焦搜索框。
- `Esc`：搜索框有焦点时清空搜索。
- `Enter`：打开网格中选中的图片。
- 方向键与 `Ctrl/Shift`：导航和多选。
