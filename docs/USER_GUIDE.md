# Picer 用户指南

当前维护版为 [v1.5.6](https://github.com/l17728/picer/releases/tag/v1.5.6)，schema 47；私有仓库下载需要访问权限。GUI、Agent、IndexService、ModelServer 的安装器和组件包由 Release 流水线生成。账号门户/多租户模式已启用；跨电脑登录和设备授权见[远程 GUI 登录指南](LOCAL_ACCOUNT_REMOTE_GUI_GUIDE.md)。照片/视频源端功能应配套升级驻留程序和 IndexService；正式发布不等于生产服务已自动部署。

下载 [v1.5.1 正式 Release](https://github.com/l17728/picer/releases/tag/v1.5.1) 的 GUI 或独立驻留程序一键安装器，详见[安装说明](RELEASE_GUIDE.md)。GUI 安装器为 326,183,841 字节（约 326.2 MB）；发布包含 15 项资产和 SHA256SUMS。断网部署可使用 `Picer-v1.5.1-win-x64-full.zip` 与同版本 runtime 包，见[离线安装说明](OFFLINE_INSTALL.md)。

v1.5.1 发布包、当前部署和真实服务验收证据见[v1.5.1 部署记录](DEPLOYMENT_V1_5_1_2026-10-14.md)。

## 远程预览与视频播放

远程媒体读取新功能的实施与发布状态见[实施记录](MEDIA_STREAMING_IMPLEMENTATION_2026-10-10.md)。服务浏览器双击照片先显示适中尺寸预览，点击“下载并打开原图”获取完整照片。“工具 → 视频播放器与读取方式…”可选择已安装的播放器、自动/优先流式/下载方式和 2–4 路下载并发。自动模式识别 VLC/mpv 后尝试流式，不确定时先下载；播放窗口可切换下载，关闭窗口会断开流式连接。原视频编码不被转换；保持播放期间源文件为只读共享，编辑或移动前先关闭播放。

纯远程电脑启动 GUI 即可，本机代理默认关闭；原始媒体所在电脑需要保持其源代理在线。GUI 同包代理只有既有配置启用、服务地址已配置且解析出本机源目录/修复授权根时才尝试自动启动，切换到远程模式不会自动停止已有代理。独立代理的登录自启另行管理，详细入口见[安装指南](RELEASE_GUIDE.md)。

## 描述一个目录中的照片和视频

打开“AI 功能 → 描述目录中的照片和视频…”，选择目录树节点。范围包括该节点及所有子目录中已入库的照片和视频；已有有效描述自动跳过。开始和定向重试只更新索引中的待描述清单，不枚举原目录、不预先计算全目录哈希，也不等待一致性检查。

尚未入库的文件通过独立的“增量更新索引”或“扫描视频”任务发现，入库后再次开始描述即可处理。索引扫描、移动修复及完整性维护不由描述按钮触发；文件的实际读取、身份核验与视频缺失关键帧提取仍在处理该项时执行。最新源码另提供独立后台一致性检查，在来源空闲时分批核对已有照片和视频，确认缺失时保留索引并标记，不重新导入用户手动清除的记录。旧服务需升级才能启用这些行为，发布和验证状态见[七项性能与后台维护改造](PERFORMANCE_FOLLOWUP_IMPLEMENTATION_2026-10-10.md)。

本地照片和视频描述默认 2 路并发，可选 1～4。v1.5.1 按页流式发现待处理项并立即排队，照片和视频共用有界工作池，不累加两类并发数；不会先执行耗时的全量待描述检查，进度持续更新已发现和已处理数量。实现与验证见[实施记录](DESCRIPTION_STREAMING_RELIABILITY_2026-10-13.md)。显存紧张时可选 1，实际速度还取决于模型服务的并发能力。各类云端收费请求保持最多 1 路。开始后会跳过已有有效描述；视频没有关键帧时先通过服务生成，再使用视频总结模型分析拼图，并结合已有语音转写。照片分析和视频总结分别使用“AI 模型设置”中的配置。AI 请求经过已配置的索引服务中转，远程索引服务也会接收中转数据；“本地模型”不等于数据绝不经过远程服务器。云端处理需在界面确认范围；费用预算仍生效。

可以取消任务。已成功生成的描述会保存，再次运行自动继续；失败项保留为待处理。展开“失败清单”可查看照片或视频的预处理、模型、保存阶段及错误码；“仅重试失败项”处理标记为可重试的项目，取消不计为失败。查询描述使用中文字符索引及 BM25 候选排序，并结合人物、日期等条件，再由 AI 复核。

照片分析任务中心同时显示本地和云端模型记录。双击本地任务在资源管理器中定位，双击远程任务通过索引服务打开照片，不再以本机是否存在原路径判断远程照片已删除。

云端请求的估算费用按请求累计，重新描述不会覆盖此前费用；正在执行的请求会预留预算。界面费用不是服务商最终账单。索引升级会先备份数据库，再在副本上升级；若提示索引仍被使用，请关闭同库的其他窗口或服务后重新启动。

视频页的单个视频摘要同样遵守 AI 设置中的启用状态、数量限制和费用预算。只有允许提供精确位置时，视频 GPS 才进入模型请求；关键帧中本身可见的地点仍可能被模型识别。

## 修复移动后的照片和视频

移动后的索引可从“工具 → 修复移动后的照片和视频索引…”添加多个新根目录进行恢复。程序按 SHA-256 关联原记录并保留描述和人物标记；未找到的位置保持“已删除或移动”。旧视频如果尚未记录哈希且原路径已丢失，无法可靠匹配；应在大规模移动前完成一次新版扫描。相同内容的视频保留多个位置引用，共享一份描述、转录、关键帧和人物信息；跨窗口同时描述同一内容也会复用有效结果。

## 手动清除视频索引

在视频页选中视频，点击“彻底清除视频索引”，阅读并确认清除范围。程序会等待相关任务停止，再删除所选位置的索引、任务结果和缓存，保留原视频文件。相同内容仍有其他位置引用时，其他引用及共享分析保留；删除最后一个引用时一并清除共享信息。之后再次明确扫描原文件所在目录，可以重新建立索引。

远程视频清除需要源电脑的驻留程序在线，以便清除源端关键帧缓存。清理失败会保留索引供重试；批量操作已成功项会移出待处理范围，仅重试剩余项。清除也会失效扫描清单与内容哈希缓存，避免旧任务回填。文件仅仅丢失或移动不会自动执行这项操作。

## 安装和首次连接

GUI 与独立 Agent 安装器提供中文当前用户安装，包含自包含 .NET、app-local MSVC CRT；GUI 包含 media-agent，GUI 内代理和独立代理的 tools/ffmpeg 目录均带 ffmpeg.exe、ffprobe.exe 及许可证，程序自动发现，普通用户无需另外下载视频工具。具体资产见正式 Release。

纯远程 GUI 不需要 Python、CUDA 或模型/runtime 包，也不会检查本地 runtime 并误报组件缺失。从“文件 → 连接索引服务…”选择远程模式，填写管理员提供的 HTTPS 地址和令牌，点击验证：程序先无凭据获取证书，显示指纹供可信渠道核对，确认后固定公钥验证访问，再以当前用户 DPAPI 加密保存并重启。无需编辑 JSON 或设置环境变量，未确认时不发送令牌或启动扫描。

账户网页登录、下载设备认证文件、上传时联动注册/登录，以及多电脑共享空间的客户端流程已随 v1.5.1 发布。当前生产 IndexService 仍使用旧令牌兼容模式，网页登录和多租户开户尚未启用；当前可用连接方式和服务端切换门槛见[部署记录](DEPLOYMENT_V1_5_1_2026-10-14.md)及[账户系统实施记录](ACCOUNT_SPACE_DEVICE_AUTH_IMPLEMENTATION_2026-10-13.md)。

源电脑的代理通过托盘设置连接和一个或多个允许目录，视频工具随包提供。模型 worker 的 Python 和模型属于服务端依赖，CUDA 可选；模型端环境准备脚本的 CPU 路径已实际验收，详见安装指南。GUI 与代理在同机运行不表示 GUI 自身需要模型执行环境。

明确选择本地执行相关模型功能时，仍需对应模型资产。“运行组件”可校验固定 SHA-256 和许可证；模型、Qwen/ASR/TTS 及其它独立服务不因安装 GUI 自动具备。原文件不可访问或系统打开失败时，界面会说明失败原因。

## 存储与 WebDAV

主窗口点击“存储设置”，可在本地文件和 WebDAV 间切换。WebDAV 模式需填写服务器地址、基础路径和用户名；密码保存在 Windows 凭据管理器，不会写入配置文件、数据库或日志。保存前可执行 20 秒连接测试。

远程缓存可设置目录及 1–1000 GB 容量。保存后配置立即生效；再点击“添加文件夹”会直接添加已配置的 WebDAV 基础路径并开始索引，无需输入本地路径或重启程序。

Picer 默认只读取照片并建立索引，不主动移动、重命名或删除任何原文件。识别、问答、打标、重复检测和保留建议都不会产生文件操作。

## AI 问答结果怎么看

问答固定显示“程序确认结果”和匹配条件；下面的“AI 解释（非检索证据）”是模型生成文字，流式更新不能改写已确认的候选。解释可能出错，应以媒体及程序列出的依据核对；无候选时不会请求模型编造命中。当前复核有候选数量和转录摘要长度限制，不保证穷尽所有相关媒体。

## 中文语义检索

主窗口点击“中文语义检索”。首次使用选择“建立/继续语义索引”，App 会完全离线地为照片生成 512 维语义向量；可随时取消，下次会跳过未变化的照片继续处理。输入“海边看日落”等中文描述后，可查看 Top 20 结果及余弦相似度解释。

验证模型效果时，逐项勾选“相关”，再保存标注。App 会计算 Precision@20；如果已知图库中相关照片的总数，填写后同时计算 Recall@20。标注和指标保存在本机数据库，不上传图片、查询或路径。

## 备份、恢复与数据目录迁移

主窗口点击“备份与恢复”。“创建备份”会使用 SQLite 一致性快照保存数据库以及本地设置；人物确认、标签、人工真值和语义检索评估均包含在数据库中。原照片、Windows 凭据管理器中的密码及可重新生成的缓存不会进入备份。

恢复时，App 会先验证备份格式、数据库版本、归档路径和 SQLite 完整性。确认后程序自动重启，等待旧进程完全退出，再应用恢复；覆盖前会在当前数据目录创建 `recovery-before-restore-日期时间.zip` 快照。

“迁移数据目录”只接受空目标目录。Picer 重启后复制全部数据、验证数据库，再切换数据根目录；原目录不会自动删除，可在确认新目录运行正常后自行归档。窗口下方同时显示数据库、缩略图、视频缓存、远程缓存和随包模型的空间占用。

## 索引服务（进阶）

默认情况下，索引在本机 Picer 进程内完成，无需任何设置。进阶用户可将索引迁移到独立的服务进程：服务管理索引和已接受的服务任务，源电脑代理负责源媒体读取、扫描和抽帧等，同一图库可供多台电脑访问。部分批次仍由 GUI 编排，关闭窗口不保证所有描述任务继续；重新打开后可继续未完成项。

启用方式：打开“文件 → 连接索引服务…”完成中文连接与证书确认流程，保存后重启。已有同机命名管道配置仍兼容；新远程用户无需自行创建 backend.json 或 service-endpoint.json。“索引服务状态”可检查模式、测试连接和浏览图库。数据目录迁移请使用独立迁移入口，避免复制出两份活动索引。

服务端独立部署与运维（数据根目录、端口、令牌、证书轮换、备份）见仓库 `server/Picer.IndexService` 与 `docs/INDEX_SERVICE_CS_DESIGN_2026-09-08.md`。

## 人脸训练与制品应用

训练入口位于“人物 → 人脸精度验证”。流程分为三步：先准备并预览不可变快照，再单独授权提交到 ModelServer，训练完成后查看评估指标并单独授权应用制品。应用只替换对应模型版本的人物原型和阈值，不修改原图；失败或拒绝应用时保持旧制品不变，可使用回滚功能恢复上一版本。

远端 LAN 服务默认关闭。启用前请确认目标主机、HTTPS 证书指纹、访问令牌和上传数据类型；非本机地址必须使用 HTTPS。关闭授权后客户端停止访问远端服务，回退到本地索引/缓存模式。

## Florence-2 CPU/GPU 验证

主窗口点击“Florence 运行验证”。程序会依次验证随包 INT8 视觉编码器、文本编码器、词嵌入和自回归解码器，并在 CPU 与 DirectML 上执行真实加载；视觉编码器额外执行冷态和热态推理。DirectML 只有在四个模型全部兼容且热态至少比 CPU 快 10% 时才会被推荐，否则保持 CPU。点击“保存推荐选择”会把设备、模型版本、时间和完整结果写入本机设置。

同一窗口可选择图片并执行“简短描述”“详细描述”或“OCR 文字识别”。图像预处理、多模态编码、自回归生成和 BPE 解码全部在本机完成；任务可取消。结果下方可填写期望文字并选择准确、部分准确或不准确，质量记录只保存图片 SHA-256，不保存原图路径。

主窗口“继续目录描述任务…”使用同一目录媒体描述窗口，同时支持照片和视频。任务可取消，已经完成的结果会保留，再次选择该目录会继续未完成项。模型类型由“AI 模型设置”决定。

Florence 验证窗口中需要审阅接受的结果不会立即影响搜索。目录媒体描述是独立流程，成功描述直接保存并参与相应检索，不能把 Florence 的接受步骤套用到全部批次。对于需要审阅的 Florence 结果，勾选“接受并进入搜索”并保存后，描述/OCR 文字才会加入主搜索；不接受的结果会记为拒绝，源文件和模型均未变化时不会重复生成。

## 未分类时间场景描述

目录树会按照片时间形成场景锚点。右键“未分类场景”并选择“描述此未分类场景…”后，程序会在该时间段内部按最大的相邻时间差最多细分为 5 组，再按照前、中、后均匀位置最多选择 3 组，并使用每组第一张照片作为代表照片。

代表照片已有云端描述时直接复用；只有缺少描述的代表照片才调用已配置的视觉 API。每张上传副本仍会缩放并清除 EXIF。程序根据代表照片的结构化场景、活动、物体和搜索词生成整组总结，用户确认后才写入当前数据库（此功能最初在 v17 引入）、替换目录树中的“未分类场景”，并让整组照片可通过场景名称、摘要和搜索词检索。

选中已有云端描述的照片时，照片网格信息区会同时显示拍摄时间、地点和描述。照片内容或代表集合变化后，原场景指纹自动失效，不会错误套用到新的一组照片。

## 诊断中心与安全缓存清理

主窗口点击“诊断中心”即可完成日常维护，无需命令行。点击“运行健康检查”会校验随包组件、许可证和固定哈希，执行 SQLite `quick_check`，并显示图片、人物、人脸、语义向量、Florence 结果和视频等汇总数量。

JSON/CSV 报告默认只包含组件状态、数据库状态、数量、存储类型和非敏感设置，不包含原图路径。诊断 ZIP 会额外收集近期日志，并自动遮蔽访问令牌、密码、Authorization 请求头和本机路径；发送前仍建议用户自行查看报告内容。

缓存列表区只允许清理由 Picer 生成且可重建的缩略图、人脸缩略图和已配置的远程文件缓存。此诊断列表中的模型和视频关键帧仅显示占用，不提供通用删除操作；视频页另有上文所述的彻底清除索引流程。每次清理都要求选择项目并再次确认，不会删除原始照片。

## 术语

- **完全重复**：文件内容的 SHA-256 完全一致，即使文件名或目录不同。
- **视觉相似**：aHash/dHash 感知哈希接近，可能是连拍、裁剪或压缩版本，并不代表内容完全相同。
- **从索引移除**：只删除 Picer 数据库记录和生成的缩略图，原文件不变。
- **移到回收站**：仅在用户逐项决定、查看不可变方案并再次确认后执行；成功项可从 Windows 回收站恢复。
- **重新定位**：原路径失效后，以 SHA-256 验证新位置，内容不同则拒绝绑定。

## 首次使用

点击“添加文件夹”。Picer 会展示扫描阶段、数量和取消入口。添加新来源只扫描该来源；“重建索引”是独立维护操作。

## 重复与相似审阅

“查找重复”会分别显示完全重复和视觉相似、算法及相似度。保留规则只生成建议。只有明确标记至少一个“保留”和一个或多个“移到回收站”，再检查并确认删除方案后，Picer 才会请求 Windows 回收站操作。取消、关闭或“稍后”均不修改文件。

## 缺失文件

“缺失”表示索引路径当前不可访问，不代表文件已删除。程序保留索引及已有缩略图并标注“已删除或移动”，不会自动删掉描述。用户手动彻底清除索引后，所选引用的索引、相关记录和所属缓存不再保留；有其他相同内容引用时保留其共享信息，末引用才删除共享内容。最小同步删除标记不包含路径、哈希或描述，也不参与检索。选择新根目录可预览 SHA-256 匹配、冲突和未匹配项；确认后只更新匹配成功的索引路径。

## 标签与本地建议

选择图片后可添加用户标签。建议区只根据已索引的尺寸、时间、GPS 等本地元数据生成，不外发图片；拒绝的建议会被记录且不再自动出现。

## 常见问题与反馈

| 现象 | 核对方法 |
| --- | --- |
| 可以看到索引，但原图/视频打不开 | 索引和缓存可独立存在；检查源电脑代理在线、授权根与原文件是否可访问。不要先删除索引 |
| 描述开始前长时间检查目录 | v1.5.1 按页从索引流式读取并排队处理待描述项；新文件仍由独立索引任务发现 |
| 描述返回 502 或某几项失败 | 在任务中心/失败清单查看阶段与错误码，核对服务和模型能力；仅重试可重试失败项，不能仅由 502 认定是 GUI 或模型本身故障 |
| 流式打开后没有画面 | 在播放窗口选择下载后播放；若文件仍不能解码，检查所选播放器对该编码的支持。程序不会自动转码 |
| 增加并发后没有更快 | 源磁盘、上行带宽、服务线路和模型排队都有影响，可降回默认 2 路；视频下载并发与目录模型描述并发是不同设置 |
| 想移走大量照片/视频 | 移动前完成新版扫描，保留内容哈希；移动后用工具菜单指定多个新根目录修复，旧视频缺少哈希且旧路径失效时无法安全猜测 |
| 配对公钥变化 | 先向服务管理员核实证书更新，再重新验证配对；不要关闭证书检查或发送凭据截图 |

报告问题时提供版本、使用本地还是远程模式、GUI/源代理/服务分别在哪台电脑、操作步骤、时间和脱敏错误码。诊断日志可能涉及使用信息，提交前核对内容；不要附服务令牌、人物特征或私人媒体。当前进入维护阶段不代表已完成全部模型质量或硬件验收。
