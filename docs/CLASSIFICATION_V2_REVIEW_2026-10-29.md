# 家庭照片多维分类 V2：评审与决议

M0 开发后追加代码复核：架构代理发现深度上限与维度注册表缺项，AI 代理发现历史海边/沙滩和建筑关系边界问题，均已修正并获对应代理最终只读确认关闭。UX/QA 代理未发现纯集合筛选阻塞，建议的父子组合及排除用例已补充。代理不代替实际执行测试，最终执行结果见[实施记录](CLASSIFICATION_V2_IMPLEMENTATION_2026-10-29.md)。

状态：v1.0 已定稿；三领域独立评审及修订复核通过，批准启动隔离 M0。评审由本次用户明确授权的领域评审代理执行，不代表已经邀请外部真人专家或完成真实用户质量评测。

评审包：SPEC、SDD、UX、TAXONOMY、ACCEPTANCE（同日 CLASSIFICATION_V2 文档）。初稿 v0.1。

实际独立评审：`classification_arch_review`（架构/数据/同步）、`classification_ai_review`（视觉LLM/证据/质量）、`classification_ux_qa_review`（UX/测试/可访问性）。三位均只读核对当前实现与初稿，未调用模型、改动数据或操作 GUI。初轮结论均为有条件放行 M0，要求先补齐契约。

## 逐项处理

| 编号 | 问题 | 决议及落实位置 |
| --- | --- | --- |
| ARCH-01 | merge/定义变化绕过人工拒绝 | 仅等义redirect；保留旧因果操作，冲突暂停机器生效；SDD §11.2，M1/M4硬门禁 |
| ARCH-02 / A1 | 新类别漏掉已有粗分类 | discovery_revision与持久影响水位，召回不能永久截断；SDD §11.1，M0指纹测试 |
| ARCH-03 | 动态名称/计数泄露、结构权限未定义 | provenance scope、taxonomy capability和显式空间共享；SDD §11.2/12.3 |
| ARCH-04 / A4 | 历史描述等同当前事实、同义去重不可重现 | 当前证据选择器与历史分离，精确去重/冲突保留/同源证据；SDD §11.3/12.1 |
| ARCH-05 | 指纹编码不完整 | UTF-8严格编码、长度前缀、Ordinal排序、重复ID冲突、黄金向量；SDD §12.1，M0测试 |
| ARCH-06 | 旧快照删除未知V2状态 | 独立能力协商通道、缺字段不清空、依赖暂存与有界诊断；SDD §12.3 |
| ARCH-07 / Q1 | 旧结果/更新失败/在途变化状态冲突 | 任务与内容覆盖两轴、desired/dirty后继项；SDD §11.4/12.3，UX §4 |
| ARCH-08 | 缓存/制品/tombstone生命周期 | 撤权立刻禁访问，诊断正文默认不留，7天上限，消费者水位/旧客户端重建；SDD §12.3 |
| A2 | 旧人物/合影/徒步ID语义被缩窄 | 保留宽义，细类新ID和明确排除定义，歧义别名不自动归并；TAXONOMY §2 |
| A3 | 合法空输出可能其实漏答 | 冻结evaluated_label_ids，逐类完整状态，局部范围发布，机器负证据非人工拒绝；SDD §12.2 |
| A5 | 同维度向量不一定同空间 | EmbeddingSpaceId与提示集合缓存键，未知/不匹配拒绝；SDD §12.2 |
| A6 / Q8 | 质量分母及性能实验不明确 | precision预测正例与recall真值样本分开、Wilson约定、硬件/30次样本；ACCEPTANCE §3/4 |
| A7 | 聚类被迫命名、中心代表图偏差 | 边界/离群代表、允许无共同主题、未验证成员不继承；SDD §12.2 |
| Q2 | 多父三态与父子条件语义不完整 | 显式条件集合、半选点击选整类、父子独立、排除分开；UX §2，M0筛选契约 |
| Q3 | 点击原图与多选审核冲突 | 独立照片选择模式、键盘/跨页/切换筛选策略；UX §7 |
| Q4 | 扫描可能直接开始计费调用 | 扫描只产计划，独立开始处理，配置变化使计划失效；UX §7 |
| Q5 | 旧相似滑块被当分类置信阈值 | 重命名相似照片候选设置，旧群组不升级语义类；UX §2 |
| Q6 | 分页不等于虚拟化、DAG路径爆炸 | 懒加载occurrence、500路径上限、回收容器/128MB缓存、批量聚合；UX §7 |
| Q7 | 视觉树RaiseEvent不等于真实UIA | 独立进程模式/键盘/焦点验收；ACCEPTANCE §4 |
| Q8补充 | 全局ALL/ANY无法表达常用组合 | 组内all/any、组间AND、全局排除，最多8组；SDD §12.4、UX §7 |

所有意见均采纳或合并，没有把数据安全问题以“以后考虑”关闭。后续阶段的迁移、同步、真实模型质量、UIA及性能要求是退出门禁，不是本次已通过的实测。M0 只放行无生产接入的领域实现；不据此解除原暂停的外部验收。

## 定稿复核与启动决定

2026-10-29，三位评审分别复核修订包并同意进入 M0：架构确认 ARCH-01/02/04/05 阻塞已解除；AI 确认 A1/A2 及推理/评估契约已补齐；UX-QA 确认 Q1/Q2 及后续门禁闭合。复核追加的分批空结果不能覆盖媒体级状态，以及“拒绝旧类/恢复目标类”策略冲突，已写入 SDD §10/11.2。

决定：设计 v1.0 定稿，启动 M0 领域基础实现及针对性测试。当前不发布、不迁移生产数据库、不调用生产模型、不替换用户正在测试的 GUI。M1～M5 继续受上述退出条件约束。用户无需再次批准已经授权的开发步骤；实际新云端用途仍按产品授权机制处理。
