# 一键配置新服务 SDD

## 目标

用户只输入服务地址、照片空间用户名、密码和来源目录，GUI 自动完成服务发现、登录、创建设备申请、认证保存、驻留程序启动/重连和端到端验收。密码只在内存和 HTTPS 登录请求中存在，不写入配置文件或日志。设备最终批准仍由用户在已登录空间确认，不通过 API 绕过 MFA、验证码或用户确认。

## 边界

IndexService 负责账户登录、设备申请和一次性认证文件；GUI 负责编排和展示；MediaAgent 负责保存设备配置并自动建立 WebSocket。原有手动登录、认证导入和令牌模式继续保留。

## 状态机

`输入 -> 发现服务 -> 校验证书 -> 登录 -> 创建设备申请 -> 用户批准/策略批准 -> 导入认证 -> 保存配置 -> 启动或重连 MediaAgent -> 验证代理注册 -> 完成`

任一步失败都保留旧配置，删除未完成的临时认证，不影响当前有效连接。保存前备份 account-device、agent settings；新 WebSocket 注册和能力验证成功后才原子替换。

## 用例

### UC-01 首次配置

用户输入地址、账号、密码和目录。系统发现服务并显示 SPKI 指纹，登录成功后创建设备申请，完成批准后保存账户和代理凭据，自动启动驻留程序并等待注册成功。

### UC-02 切换服务

系统先验证新服务和新设备连接，再原子替换配置；新连接失败时恢复旧配置和旧连接。

### UC-03 已运行驻留程序

配置保存后向现有 MediaAgent 发送重载；地址或设备身份变化时自动退出旧实例并启动新实例，无需用户手动启动。

### UC-04 失败恢复

网络、证书、登录、批准、导入或 WebSocket 失败时显示具体阶段和原因，旧配置保持可用。

## 安全要求

- 仅 HTTPS；服务发现证书必须匹配 SPKI。
- 密码不落盘、不写日志、不传给 MediaAgent。
- 认证文件一次性使用并校验 ServiceId、Origin、SPKI 和 ClientKind。
- enrollment token 短期、一次性、绑定 ServiceId、Origin、SPKI 和设备公钥；登录与申请接口限流。
- 登录和设备申请限流；服务端审计只记录请求 ID、结果和时间。
- 原始媒体目录权限和索引只读约束保持不变。

## 验收标准

- 新安装 GUI 可在一次向导内完成配置，MediaAgent 自动出现“已连接”。
- 切换服务成功后 GUI、MediaAgent、IndexService 三方 Origin/ServiceId/SPKI 一致。
- 任一阶段失败，旧配置仍可连接，且无密码、令牌或认证文件进入日志。
- GUI 重启和 MediaAgent 崩溃后能自动恢复连接。
- E2E 覆盖首次配置、切换、证书不匹配、旧凭据、网络超时和回滚。
- 验收必须验证 health、service discovery、agent WebSocket 三层连接；自动生效不超过 10 秒，重启恢复不超过 30 秒。
- 必测失败场景包括错误地址、TLS 指纹不匹配、密码错误、批准超时、无效认证、断网、目录无权限、重复点击和 GUI 崩溃恢复。
