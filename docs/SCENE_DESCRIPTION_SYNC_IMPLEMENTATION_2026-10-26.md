# 场景描述双向同步实现

状态：开发验证中，数据库 schema89、元数据协议 13；尚未提交、发布或部署。

## 修复的问题

远程 GUI 的“编辑场景”原先只更新本机镜像。来源电脑再次上传时，服务端场景描述也可能被旧快照覆盖。远程“描述未分类场景”还错误地要求服务端照片路径在 GUI 电脑上存在。

本次将远程编辑接入 `POST /api/service/v1/scenes/edit`，要求 `index.write` 权限，保存到照片空间后刷新镜像。远程模式不再用本机文件存在性判定服务端照片是否可描述。保存失败时编辑窗口保持打开并保留输入。

## 身份、范围与冲突

- 来源场景指纹和服务端指纹通过 `sync_scene_bindings` 关联。整数照片 ID 分别转换，不能把镜像 ID 当作来源 ID。
- 场景中所有照片必须属于同一个来源，并全部落在本次授权范围内。跨来源或部分授权场景不向来源电脑下发。
- 接受的标题、摘要、搜索词及模型标记作为 `scene-description` 因果字段同步。来源快照写入后重放人工编辑，防止旧结果覆盖新决定。
- 两端并发修改进入现有冲突审核。界面先显示服务端版本，离线提案持久保留；用户选择后生成新决定并回传。
- 远程编辑检查空间 epoch 和打开编辑器时的内容。重复提交相同结果幂等；过期空间或被另一端修改的基线不能直接覆盖。
- 远程新建场景也建立来源映射；只向其所属来源回传，不把其他电脑的数据复制到本机。

## 迁移与清除

schema89 增加场景映射、变更通知和清除触发器，将合法的旧已接受描述播种为因果字段。自动时间分组布局不播种为人工描述。用户清除相关照片索引时，同时清理场景及其编辑、冲突、回执和映射；不修改原始媒体。

人物候选聚类的删除与回传见[模型派生删除同步](DERIVED_METADATA_DELETION_IMPLEMENTATION_2026-10-26.md)。训练工件、人物向量和精确位置仍遵循原有独立授权，不因场景同步扩大共享范围。
