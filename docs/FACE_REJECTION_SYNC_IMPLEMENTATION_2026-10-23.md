# 人物拒绝记录双向同步

2026-10-23，schema70 / 元数据协议 6，开发验证中，未发布部署。

照片人脸的确认、忽略和撤回归属已由 schema69 覆盖，但“这不是此人”的拒绝关系仍只存在本机。仅同步撤回归属不能阻止另一端重新给出同一个人物建议。

新增 `face-rejection / face identity / person identity` 人工字段，值包含是否拒绝及人脸模型版本。不同人物的拒绝独立合并；同一个人物的并发拒绝/撤回使用已有基线版本和冲突保留。重新人工确认曾被拒绝的人物时，在同一事务清除拒绝并记录显式撤回，防止旧拒绝回传后复活。

上传、分页下传、操作回执、人物授权范围、冲突中文显示、来源通知和永久清除均接入该字段。人物 ID 必须通过各 publisher 的身份映射转换；只出现在拒绝记录或拒绝撤回字段中的人物也需要依赖认领，不能通过姓名合并。子树上传快照保留这些依赖，其余来源的照片仍不进入本机。

迁移保留历史拒绝，并绑定对应人脸模型；照片人脸清除同时移除字段、回执及冲突。人物合并保留目标人物的拒绝投影，但人物实体删除/合并的完整跨端墓碑仍是独立未完成项，不能把本次改造视为已覆盖。

验证项目：拒绝后另一端不再推荐、重新确认后拒绝撤回、旧结果重放不复活、不同人物字段独立、模型与来源映射、人物授权恢复、永久清除、真实 HTTPS 往返及既有人物操作回归。测试结果完成后补录。

初轮严格构建零警告、零错误。`face-rejection-initial-schema70.trx` 39/40 通过；失败来自模拟旧库降级夹具未移除新版触发器，SQLite 因引用待删除列而拒绝操作。已修正夹具，结果不视为整体验收通过。随后补充合并时撤回对已确认目标的拒绝、人工字段通知与仅有拒绝/撤回的人物依赖认领回归，等待复测。

本记录不表示视频人物的跨来源归属隔离已经完成。整体交付边界以 DEVELOPMENT_PLAN.md 为准。
