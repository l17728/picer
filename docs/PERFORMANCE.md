# Picer 性能测量与实现边界

更新：2026-10-10；适用于 schema 45 源码。以下区分测量方法和当前优化机制，不给未测硬件承诺延迟。

## 基准运行

在同一台机器、相同电源模式和空闲负载下运行：

```powershell
dotnet run --project tools/Picer.Benchmarks -c Release -- 1000 30
dotnet run --project tools/Picer.Benchmarks -c Release -- 100000 30
dotnet run --project tools/Picer.Benchmarks -c Release -- 1000000 30
```

第三个参数可指定数据卷，例如 `-- 100000 30 D:\bench-root`；工具只创建和清理其自己的 picer-benchmark-* 子目录。合成 SQLite 清单生成吞吐不代表真实媒体解码、模型推理或网络扫描吞吐。

搜索分别报告约 1% 选择性的查询和全库匹配压力查询，不把两者混成典型 p95。至少重复三次，记录每次结果和中位数、p50/p95/max、工作集、分配量与 GC。UI 另测首屏、持续滚动 60 秒的掉帧及峰值内存。

## 测量条件

记录日期、提交、Windows/.NET、CPU、GPU/显存、内存、存储、媒体数量、唯一内容数、引用数、参数和缓存状态。首次完整扫描、有效增量清单、变更目录增量和日志失效回退应分别测量。数据库/源文件/缓存所在磁盘分别记录；远端记录网络 RTT、模型排队和代理状态。

WebDAV 对照包括 0/100 ms RTT、HTTP 500、超时和无权限。测试目录须隔离，不能在真实图库上运行故障或清理实验。历史性能报告只适用于其记录的版本和机器。

## 当前扫描与查询优化

目录描述预览使用 SQL 子树过滤、批量描述状态及去重父目录，避免全库逐项查询。目录树后台构造，过时选择取消；预览仅统计扫描前索引，不等同于磁盘实时总数。

持久扫描清单和 NTFS USN 水位减少重复枚举。首次、日志断档、不可信事件、非 NTFS 或网络盘回退完整核验；已知元信息和根可用性仍需检查，因此不承诺每次启动 O(1)。取消或不完整扫描不进行缺失对账。

本地视频哈希缓存最多 128 项，除卷、文件 ID、ChangeTime 和长度外，还须核验有效 NTFS 日志 ID 及同一打开句柄取得的逐文件 USN。仅靠 ChangeTime 在快速改写时不足以证明未变；无可信日志或签名时完整读取且不保留缓存。清除会失效内存、持久清单和在途发布，清除后的首次扫描可能变慢是预期行为。详见[实际失败及 USN 修复](VIDEO_HASH_USN_FIX_2026-10-09.md)。

主照片列表使用 keyset 和虚拟化；其他接口按其分页契约处理，不声称所有字典和列表均不全量读取。UI 共享连接任务串行调度，独立长查询使用独立连接。

## 模型并发和缓存

目录本地描述默认 2 路、最多 4 路，照片阶段完成后处理视频；云端收费请求串行。并发增加不保证显卡满载或更快，需同时测预处理、传输、模型排队、显存峰值和失败率。

相同视频内容在同库内共享分析，摘要锁内复核有效结果。预算按在途请求预留、实际请求记账，缓存命中不能重复计费。视频帧写入独立生成目录并在成功后发布，海报按内容身份复用，保留仍被其他引用使用的旧代际。

## 同步与清理

服务镜像按变更水位分页，未变化时跳过媒体与元数据传输。重置必须完成稳定范围核对再清理所属镜像；取消和变动中的分页不触发全库删除。媒体数量相同不能代替变化检测。

手动清除先停止写入者再清缓存，等待时间应与任务取消延迟分开测量。末引用清除共享资产，非末引用只清理所属位置及独立副本；清除耗时不能作为“释放了原文件空间”的证据。
