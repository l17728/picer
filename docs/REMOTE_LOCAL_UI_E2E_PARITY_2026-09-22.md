## 目标

本地模式是标准答案；远程模式只替换索引网关和原图代理，目录树、计数、筛选和操作结果必须一致。测试禁止用“远程简版页面”作为通过标准。

## 用例

| 编号 | 场景 | 本地基准 | 远程验收 |
|---|---|---|---|
| REMOTE-PARITY-001 | 启动并同步 | 来源数、图片数、视频数 | 镜像同步后相同；无重复 source |
| REMOTE-PARITY-002 | 目录树 | 来源、我的相册、光锥之内、地理根节点及子节点 | 节点名称、层级、计数和选中行为与本地一致；根节点仅增加“远程 · ”标识 |
| REMOTE-PARITY-003 | 时间相册 | 年/月相册及锚点，最新在上 | 相同年月节点、图片数、时间锚点和翻页结果 |
| REMOTE-PARITY-004 | 临时/手工相册 | 相册名称、成员图片、删除相册不删原图 | 相同成员和删除语义；同步后双端一致 |
| REMOTE-PARITY-005 | 地理树 | 国家→省→市→区县层级及计数 | 相同层级和计数，不能把 Linux 服务路径当作照片目录 |
| REMOTE-PARITY-006 | 人物/人脸 | 人物、脸、人工归类关系和模型向量 | 元数据同步后数量、归类和搜索结果一致 |
| REMOTE-PARITY-007 | 视频 | 视频节点、关键帧、转写/摘要和人物 | 远程显示与本地相同，原视频由在线本地代理中转 |
| REMOTE-PARITY-008 | 原图缓存 | 首次双击从代理获取；再次打开命中本地缓存 | 两次内容哈希一致，第二次不产生网络请求 |
| REMOTE-PARITY-009 | 远程变更轮询 | 本地新增/修改后同步服务 | 远程客户端 30 秒内刷新目录树和搜索，不阻塞 UI |
| REMOTE-PARITY-010 | 断线恢复 | 网关暂时不可用时本地 UI 可继续浏览已有镜像 | 恢复网络后增量补齐，不重复图片/相册/人脸 |

## 自动化覆盖

- `Picer.Tests/Gateway/GatewayContractTests.cs`：Local、HTTP、Named Pipe 三种网关共享同一断言；覆盖分页、缩略图、原图代理和人脸关系元数据。
- `Picer.E2E/UnitTest1.cs`：真实 WPF 目录树、来源/相册/时间线节点和图片网格。
- 真实跨机验收：先在本地 GUI 执行“同步本地索引”，再用空数据目录启动同一 GUI 的远程模式，按 REMOTE-PARITY-001～010 执行；每次验收保存本地/远程目录树快照日志。

## 通过门槛

除网络断线用例外，远程与本地的结构化快照必须逐项相等；任何 0 计数、重复来源、少于本地的相册成员、人脸关系缺失或时间节点缺失均视为失败，不允许用 UI 延迟解释。
