# 目录描述流式发现与媒体通道可靠性修复

状态：2026-10-13 源码修改、严格构建、全量单元与桌面 E2E 已完成，尚未发布或替换现有程序。当前正式版仍为 v1.4.0。本文记录此次故障证据与候选代码，不替代正式发布验收。

## 启动慢的定位

v1.4.0 已移除描述前的磁盘扫描，但仍在目录选择预览和点击开始时分别构建完整 `DirectoryMediaDescriptionPlan`。该操作读取所选子树的全部照片、视频及描述状态，再生成待处理数组，之后才开始模型请求。因此“不扫描磁盘”不等于“立即开始描述”。这些查询还与后台镜像同步共用 `UiWork` 数据库队列，同步批次会延长等待。

新实现取消选择时的全量统计及开始时的完整计划构建。目录树加载使用独立连接；开始后，照片和视频分别通过独立数据库连接逐页发现，通道容量为 8，每页 32 项。每页查询结束即关闭 reader，然后才等待队列空间，不跨模型请求持有数据库读事务。处理方按设定并发消费，已经保存的有效结果跳过，成功结果逐项保存。进度显示已发现、已处理、成功、失败和跳过数量，发现结束前不显示虚假的最终总数。

分页采用规范化路径与 ID 游标，并显式设置索引的起止范围。仅添加元组游标但保留 `LIKE` 起点，在 SQLite 上仍可能从目录开头遍历。10 万条合成记录的只读查询验证中，读取第 9 万条之后的 32 项，原查询约执行 153 万条虚拟机指令；显式游标起点约 1200 条。此结果说明查询工作量的变化，不是用户整批描述速度或 GPU 吞吐的承诺。

本地描述默认 2 路、可选 1～4 路；照片和视频共用有界工作池，不累加两类并发上限。各类云端模型调用保持最多 1 路。取消会停止发现并等待在途处理退出。每类发现开始时固定最大记录 ID，随后新增的索引记录下次运行纳入，避免持续导入导致任务永不结束。已有记录的有效描述状态在读取小页和实际处理时复核；不进行整库一致性检查。

目录描述只消费索引。新文件发现、移动修复与后台一致性检查仍为独立功能。实际处理一项时的源内容核验、输入准备、视频缺失关键帧提取，以及保存时的短数据库操作仍然需要执行。

## 全部失败的故障证据

本地历史失败记录以预处理阶段 HTTP 500 为主；抽查的三个失败照片请求在重启前均超时。服务器日志显示分析输入请求等待媒体槽位超过两分钟；另有驻留程序重连期间访问已释放 `SemaphoreSlim` 的异常。现有代码在连接取消、发送阻塞和清理异常场景下存在资源未及时归还的风险。

本机模型健康检查及一次合成红色图片真实推理均成功，推理约 10.95 秒；没有证据把此次整批失败归因于 GPU 显存耗尽。重启原版本 IndexService 后，三个原失败 ID 均返回经源端核验的 JPEG 输入，耗时约 8.5～17.6 秒。该操作恢复了当时的服务，但不是永久修复已部署的证据，也不能据此认定所有历史失败都只有同一原因。

源码加固包括：媒体分类准入上限、槽位等待期限、控制发送和数据读取期限；Agent 断开取消旧会话请求；清理异常时仍归还容量；资源繁忙及内部超时返回带 `Retry-After` 的 503；只读照片输入获取有限重试。网关重试遵守服务端冷却时间并加入短随机退避；超过 30 秒的冷却直接向上层返回繁忙，不提前重试或无限等待。持续服务异常达到阈值后暂停目录描述，不继续把剩余整库标记失败；鉴权或模型未配置错误立即暂停。模型推理本身不因此被自动重复调用。

## 验证与边界

- 已验证发现尚未结束时首张照片开始处理、已有结果跳过、照片与视频并发上限、取消等待任务退出。
- 已验证媒体发送超时释放容量、异常清理只释放一次、驻留程序替换后旧请求退出且新请求恢复。
- 媒体与目录流式定向单元回归 35/35；随后新增错误传播与退避测试后的定向复测 12/12，两次范围部分重叠，不相加。桌面目录描述回归 12/12。
- 路径边界、中文与通配字符、UNC/盘符根、大小写相同游标、发现开始后的新增 ID 边界均通过验证。现有镜像只读查询确认使用目录表达式索引；同路径的 ID 次级排序仍可能使用临时排序，不声称完全没有排序。
- 解决方案严格构建通过，0 警告、0 错误；全量单元测试 715/715、桌面 E2E 94/94 通过；最终构建后快照回归 3/3 通过；依赖还原及 `git diff --check` 通过。完整本地验证不代表 GitHub CI、安装包、真实公网账户流程或正式发布已验收。
- 这是单实例的超时、隔离和恢复加固，尚不等同于跨机器故障转移。现有运行程序尚未包含本次修复。
