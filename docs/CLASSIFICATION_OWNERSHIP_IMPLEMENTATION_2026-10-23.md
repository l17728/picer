# 分类决定来源归属与历史审核

日期：2026-10-23。开发源码 schema60，尚未发布部署。

## 行为

内容级人工拒绝保留 `owner_key`：本机图库使用稳定 library identity，空间服务使用媒体来源 publisher identity。同一图库内相同内容的多个引用仍共享决定，不同 publisher 的同哈希照片不继承对方决定。确认、纠正、拒绝、恢复、模型重算、分类列表及搜索使用同一归属规则。

追加复查发现，远程 GUI 镜像不复制服务端来源绑定表，不能直接把未绑定照片归入同一本机图库。schema63 中照片归属视图已与视频一致：优先取绑定信息，无绑定时识别服务端发布路径中的 publisher 命名空间，普通本地路径仍使用图库身份。此修正正在验证；不扩大设备的目录授权范围，也不根据内容哈希推断来源。

服务端内容级拒绝增删会为本方匹配媒体生成变更通知；读取及上行将决定转换为本方媒体引用，不将没有来源证据的历史 hash 记录广播给全部来源。

模型语义投影现在遵守人工拒绝。重新确认或更正为曾拒绝的分类时，清除本方旧拒绝，使用户确认能在搜索中生效；其他 publisher 的拒绝保留。

## 迁移与审核

继续使用既有整库备份、staged migration 和可恢复发布。旧 hash 若只有一个 owner 可确定则补上归属；多 owner 时可以从已有被拒绝断言恢复明确的本方决定。无法确定的原记录保留为空 owner，暂停自动应用。

“照片分类与审核 → 历史拒绝待核对”按内容及来源列出待审核照片。选择照片后，点击“不是此类”保留该来源拒绝，或点击“恢复为待确认”允许重新建议；也可以确认或更正分类。每个来源的审核记录与决定原子保存，处理一方不会处理其他来源；重复打开不再要求审核已经处理的来源。

手动永久清除最后一个本方引用时清除其拒绝、审核记录及相关行日志。同内容还有其他 publisher 引用时，保留其他方决定。未知归属的记录在仍有同内容引用时保留，最后一个引用清除后移除。原媒体不改动。

## 验证与边界

首轮归属、模型重算、迁移和同步回归 44/44 通过。随后补充历史审核界面、确认覆盖旧拒绝及服务端 hash 拒绝变更隔离测试，最终验证待补记。
