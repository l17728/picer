## 结论

远程 GUI 现在使用 `RemoteThumbnailCache` 将缩略图保存到配置数据目录的
`remote-thumbs` 下。缓存键优先使用原图 `content_sha256`，其次使用 `sha256`，没有哈希时使用经过 SHA-256 规范化的媒体 ID。相同原图在目录、搜索、场景和时间线等多个 UI 视图中只对应一个缓存文件。

## 行为

- 文件采用 `v1-{identity}.jpg` 内容身份键，不覆盖已存在的完整文件。
- 写入使用随机 `.part` 临时文件，完成后原子移动；进程启动时清理残留临时文件。
- 同一进程内相同键使用 single-flight，多个卡片同时请求只产生一次网络下载。
- 进入远程页面、滚动或改变窗口大小后等待约 750ms；用户无操作时，后台按批次预取当前 UI 集合中的媒体项。优先级使用虚拟化面板根据滚动偏移计算的当前视口，而不是可能滞后的回收容器，因此拖动滚动条或调整窗口后会从新视口开始。滚动只重排尚未派发的批次，已经进入下载槽的任务继续完成；页面切换/控件卸载才停止后续派发。
- 当前视图切换、目录刷新和搜索通过页面取消令牌停止旧卡片的后续加载；缓存文件保留，之后重新进入直接复用。缩略图调度会记录集合大小、视口范围和待处理批次，异常只记录内部媒体 ID 与异常类型，不记录路径、人物名或问题文本。
- 原图仍使用独立的 `RemoteAssetCache`，缩略图不会与原图缓存混用。
- 远程服务浏览窗口也复用同一 `RemoteThumbnailCache`，并使用相同的 750ms 空闲批处理、视口优先和页面切换取消策略；视频仍由视频适配器提供首帧/关键帧，人脸裁剪图使用独立的人脸缓存。
