# 关键帧转发与元数据差量传输

## 实现范围

关键帧 ID 和按视频序号回退接口均接入已有二进制媒体流协议。服务端取得媒体元数据后即可返回响应头并流式传输，不再必须通过控制 WebSocket 接收完整 Base64 图片。旧 Agent 不支持该协议时仍走原资产接口。

关键帧使用独立配额：服务端最多 2 个工作通道、4 个准入请求，源端最多 2 个关键帧读取。视频播放连接池不因加载关键帧被驱逐；旧 Agent 会忽略新增的通道提示。路径仍由已授权索引记录解析，账号空间仍执行来源路由、设备权限与撤销检查，源端仍校验允许访问的目录。取消和断连释放原有媒体流租约。

元数据沿用 `/api/gateway/v1/metadata`，通过请求头协商集合级差量协议。服务端为当前授权快照各 JSON 字段计算 SHA-256，仅返回与客户端摘要不同的字段。客户端将差量合入基线，逐字段校验后反序列化为完整 `GatewayMetadata`，业务层继续使用完整快照，避免把省略集合误当删除。

- 空集合明确表示删除，null 仍保留旧协议的“未提供”语义。
- 基线按网关实例及向量/模型选项隔离，驻留内存，不新建磁盘缓存或 schema。
- 请求串行维护基线；失败或取消不提交半份缓存。校验失败丢弃基线，通过既有有界读重试重新请求完整数据。
- 普通服务、账号代理和账号一致性快照入口均支持协商；旧客户端继续接收完整 JSON，旧服务的完整响应也能被新客户端读取。
- 响应禁止共享缓存；摘要不绕过任何鉴权，不在日志记录人物、向量、描述正文或凭据。

`Server-Timing` 增加 `media_prepare` 和 `metadata_diff`，账号代理透传。这两项分别覆盖媒体准备和差量构建，不等同于网络 RTT，也不代表已经细分全部鉴权与数据库执行时间。

## 效果边界

集合未变化时不再重复传输其内容；所有集合均未变化时响应只含校验摘要与空变更对象。首次连接、进程重启、基线失效，以及实际变化的集合仍需完整传输。该方案是集合级差量，不是每条人脸记录的网络增量。服务端仍需读取并序列化当前元数据以计算摘要；本次不承诺减少这一阶段的全部 CPU/SQL 成本。

二进制关键帧需要服务端更新后启用，源端独立配额需要新 Agent；客户端的差量接收需要新 GUI。当前程序未替换、未发布，实际公网延迟需切换候选后手工复测。
