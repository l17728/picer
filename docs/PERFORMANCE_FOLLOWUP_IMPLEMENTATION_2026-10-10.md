## 一致性检查与兼容边界

调度器只查询现有索引，按 ID 游标分批检查，不遍历目录树或发现新文件；新增文件仍通过独立索引功能导入。每批快速核对大小和修改时间，另用独立游标轮转一条 SHA-256 审计；变化文件读取元数据，单文件内容检查设 30 秒取消期限，整批设 45 秒预算并返回部分进度，服务端 90 秒兜底取消，避免慢文件导致后台任务遗留。前台媒体读取、分析、扫描开始后取消后台工作，空闲 2 秒才允许下一次后台检查。超时、授权不足和离线来源保留原记录；确认文件缺失才标记“已删除或移动”，不删除索引。取消期限依赖文件系统及解码器响应取消，不承诺原生阻塞调用的硬实时中断。

写回使用独立数据库连接和事务，重新比较原记录的 ID、来源、路径、大小、时间和哈希。用户已清除、移动或更新的记录不接受旧结果，不会被后台重新导入。检查点只持久化数字游标。只有一个在线且支持 `directory.verify.v1` 的 Agent 时执行，多个源 Agent 未明确路由时跳过；旧 Agent 不会被强制执行新任务。`PICER_BACKGROUND_INDEX_CHECK=0` 可在 IndexService 启动时关闭调度。

源端照片预处理有已知 SHA-256 时核验完整内容；历史记录没有哈希时仍以大小和修改时间核对。源端最多 2 路预处理，与缩略图和原媒体通道分开。旧服务/旧 Agent 返回不支持时，GUI 回退原图下载及本地身份核验。完整媒体缓存的 20 GiB 是已发布文件容量，最多 4 个在途下载还需临时磁盘空间。

## 受控性能复测

同一合成探针使用 8 MiB 数据、每次源读取延迟 100 ms，故意阻塞缓存工厂 300 ms；不访问真实网络、照片或模型。顺序流实际在途请求从 1 提升到 4，耗时从约 1061 ms 到 258 ms；1 字节探测的源读取量从 1 MiB 降为 1 字节。热缓存访问在其他下载/旧分段锁冲突期间均立即完成。探针总时长包含人为等待，不作为热缓存延迟。结果证明并发及请求放大问题已修复，不代表公网或 GPU 的固定加速倍数。
