# 人工元数据分页增量同步

日期：2026-10-23。schema66 开发验证中，未发布部署。

来源端原来一次性读取全部人工字段，超过 2 万项会拒绝同步。新实现每页最多接收 500 项，并将字段版本和操作 ID 组成的进度单独保存在 publisher 下；业务合并和进度推进同事务提交。读取范围变化或空间重新建立基线时重置该进度，不因之前跳过某个目录而永久漏收。

每轮固定服务端版本上界。分页过程中被再次修改的字段进入后续版本段；最后一页若观察到更高版本，来源端继续追赶。服务端在短事务中为尚无权威版本的当前有效决定分配版本并读取页面，避免中间插入的未编号决定被漏掉。视频的旧覆盖记录、歧义记录不参与版本提升，不能因为迁移而重新生效。

分页只返回该 publisher 已映射的实体和空间级设置；其他来源的媒体不返回。客户端复核 publisher、epoch、页边界、版本及授权范围。每页只重放涉及的字段，不重新重放整个元数据库。取消或失败保留已提交页；未提交页下次重新接收。

仅按新版本接收不足以反馈冲突：若上传被拒绝，当前值可能没有新增版本。新增按来源操作查询当前处理结果的接口，要求本来源操作证明、设备授权和 epoch；未知或其他来源的操作不返回结果。其后继续接收冲突处理回执。

注册响应声明人工元数据协议版本。新版来源程序在上传或执行基线恢复前检查服务支持，旧服务会得到明确升级提示，不把不支持的协议当作空数据。此记录不表示旧版 GUI 已支持新字段；部署仍需配套升级。

本次改造针对来源端人工字段下行。远程 GUI 的旧镜像读取路径、其他元数据类别的统一字段事件、完整删除墓碑以及事件保留/压缩确认水位仍需继续完成，不能据此声称整个双向协议已经完成。

验证中：2 万多项字段分页、分页期间修改、来源隔离、操作结果查询、旧视频决定不复活、取消恢复和授权范围变化。独立构建目录为 `artifacts/sync-paging-build`，避免改动仍在运行的 schema65 整仓测试产物。
