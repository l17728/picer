# 本地与照片空间元数据双向同步设计评审

评审对象：[SDD](LOCAL_REMOTE_METADATA_SYNC_SDD_2026-10-22.md)。日期：2026-10-22。

## 评审范围

从架构、数据一致性、安全/隐私、可靠性/性能、分类语义和用户体验六个角度逐项检查设计边界。评审结果用于修订定稿基线，不代表代码已经实现或生产验收完成。

## 发现与处理

### A1 — 下行事件不能由客户端选择来源

**风险**：如果 pull API 接受未验证的 source/publisher 参数，设备可尝试读取空间内其他设备来源。仅靠客户端过滤无法构成隔离。

**决议**：每次请求绑定已认证 device grant；服务端从 publisher registration、source binding 和实体 global identity 反查 owner。游标也按 `(space, grant, publisher)` 绑定。客户端请求中的来源列表只允许进一步缩小授权范围，不能扩大范围。已加入 SDD 的安全和 API 章节。

### A2 — 分类拒绝/撤销不能由当前行快照推断

**风险**：机器断言被删除或撤销后，接收端若只做 upsert 或按缺行删除，就可能在重放、模型重算或局部快照中复活标签。

**决议**：用户拒绝、确认、纠正、撤回分别作为显式事件/tombstone；更新必须保留 source kind/version、审核状态、逻辑版本和 operation ID。人工决定优先，旧机器事件不能覆盖。已加入 SDD 的事件、冲突与验收章节。

### A3 — SQLite ID 和路径不是跨端身份

**风险**：本地、远端、另一台设备的整数 ID 会碰撞；移动文件也会改变路径。按 ID/路径合并会污染照片或串设备。

**决议**：只用 publisher 的稳定 global identity 及服务端 source binding 定位对象；路径是来源属性而非 identity。内容哈希只用于同来源重复引用的内容级继承，不能授权跨 publisher 下发。已加入 SDD。

### A4 — 全局计数水位不足以提供增量一致性

**风险**：仅有 metadata_revision 无法分页、过滤或确认按来源元数据变更；失败时容易跳页，快照重试也容易遗漏撤销。

**决议**：增加事务性 publisher-scoped change log 与 outbox；客户端以 operation ID 幂等应用，整页提交后才推进 cursor；游标过期明确要求 baseline。已加入 SDD。

### A5 — 远程分类的生成边界可能把多台设备混在一起

**风险**：在汇总库上跨来源聚类再把单个聚类名/成员下发给来源设备，会违反本地数据隔离，也会造成分类漂移。

**决议**：远端计算结果须带来源范围和算法版本；自动聚类按 publisher/source 隔离，跨来源空间视图只能作为服务端聚合视图，不回写为任一设备的本地分类。用户确认仅对所选媒体 owner 产生事件。已加入 SDD。

### A6 — 同步失败不能阻塞本地交互

**风险**：同步依赖在线服务会导致离线时不能标注/浏览，或 UI 长时间等待远端确认。

**决议**：本地变更先持久化在事务 outbox，后台重试；远程变更服务端持久化后由客户端后台拉取。界面展示待同步/冲突/授权错误，不暴露游标细节。已加入 SDD。

## 最终评审结论

六个视角未发现需要推翻整体方案的未解决问题。上述约束已经写入 SDD，设计**通过并定稿，可作为开发基线**。代码验收仍需逐项验证 A1–A6，尤其是服务端 owner 解析、publisher 游标隔离、用户拒绝持久性和远端聚类不跨来源回写。

## 未纳入本设计的事项

- 账号账单、容量配额和分享链接。
- 让一台来源设备直接向另一台来源设备传输媒体。
- 默认跨 publisher 合并人物身份或分类簇。
- 为追求立即一致而阻塞 GUI 操作。同步目标是可恢复的最终一致；在线时尽快传播。

## 定稿签署

产品需求边界、架构和 UX 以 SDD 第 1、3、7 节为准；安全和冲突的强制规则以第 4、5、6 节为准。若实现需要改变这些边界，应先修订并复评 SDD，不能由实现细节悄然改变数据归属。
