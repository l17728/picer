# 账号、空间与设备授权设计评审：体验、部署恢复和性能并发

日期：2026-10-12。评审对象：[账号、照片空间、设备授权与跨电脑接入 SDD](ACCOUNT_SPACE_DEVICE_AUTH_SDD_2026-10-12.md) 初稿 0.9。本文是设计评审，不是功能验收、性能实测或上线批准；没有读取生产配置、连接生产服务或修改产品代码。

评审角色：用户体验与桌面接入、安装部署与恢复、性能并发与运行维护。采用独立审查，问题交由主设计作者修订后复核。P1 表示必须在设计定稿前消除的流程或容量歧义；P2 表示需纳入实现契约与验收的细化项，本报告中的 P2 不代表恢复此前暂停的其他工作。

## 基线与总体判断

已检查主设计，以及 [ServiceConnectionSetup](../src/Picer.App/ServiceConnectionSetup.cs)、[AppServices](../src/Picer.App/AppServices.cs) 的连接保存、模式初始化、镜像与缓存路径。现有连接设置确实依赖地址、令牌和公钥，远程镜像及多类缓存仍使用单套固定名称。目标设计正确要求独立空间上下文、分区缓存、后台加载和原媒体来源明确；实现时必须替换这组既有服务对象的生命周期，不能只增加登录窗口。

初稿涵盖了两台电脑、原媒体离线、撤权不可收回已下载内容、独立 Agent 授权和闭库迁移等主要情形。以下问题解决前，不宜宣称跨电脑接入流程与容量设计已经闭环。

## 需要保留的设计约束

- 纯本地无账号、无远程注册；本机读取授权不能自动变为云同步或 AI 上传同意。
- B 默认只运行远程 GUI；Agent 的安装存在与自动启动必须区分。升级不能因已有包中带 Agent 就自动启用来源。
- 来源电脑离线只影响原媒体可达性，不产生“已删除”或自动清除；视频与照片一致。
- 重装是新设备；不可把 Windows DPAPI 配置复制到另一台电脑解释为授权迁移。
- 不因压力测试失败而扩大权限缓存 TTL；首屏、撤销、后台公平和资源容量需同时满足。
- 备份恢复、迁移和空间删除必须分阶段、可重入；已有实际部署和当前 schema 45 不能被本文误写为已完成账号改造。

## 补充验收建议

体验脚本应从下载 Release、干净 Windows 安装和无历史配置起步，分别验证个人自建、家庭成员、托管邀请三种方式。脚本记录用户所需外部材料（服务地址/可信连接配置、账号或 B 的申请文件）、每个页面动作、拒绝授权后的可用功能，确保没有隐藏的开发者操作。

容量验收在第12节同一参考机上同时混合活动媒体、缩略图、首次镜像、背景检查和登录撤销；分别记录冷/热空间库的首屏、等待队列长度、峰值内存、磁盘余量和撤销延迟。单测 semaphore 数值正确不能替代这类混合负载试验。当前文档参数均为设计预算，不能作为已实测性能对用户宣传。
