# 家庭照片多维分类 V2：预设体系与动态扩展

状态：v1.0 设计定稿，架构/AI/UX-QA 独立代理评审及修订复核通过，允许启动隔离 M0。2026-10-29。生产仍为 schema92；功能实现和验收状态另行记录。

## 1. 维度与种子范围

稳定 ID 使用 ASCII 语义键，中文名称独立。初版约 100～200 个常用细类；实施的机器可读种子是精确节点数和 ID 的唯一来源，文档不维护第二份容易漂移的计数。以下为必须覆盖的分支，逗号分隔的类别可继续按证据细化：

| 维度 | 分支及细类 |
| --- | --- |
| 主体 | 人物（单人、双人、多人合影、自拍、肖像、人物与环境）；动物（猫、狗、鸟、鱼、昆虫、家畜、野生动物）；植物（树木、花卉、盆栽、农作物） |
| 自然环境 | 草地、树林、森林（竹林、针叶林、阔叶林）、山地（山峰、山谷、丘陵、岩石）、水域（河流、湖泊、池塘、瀑布、海洋）、海岸（沙滩、礁石、港湾）、湿地、沙漠、雪地、冰川、田野、天空（云、星空、彩虹） |
| 场所 | 家居（客厅、卧室、厨房、餐厅、浴室、书房、阳台、庭院）；餐饮（餐馆、咖啡馆、茶馆）；教育（教室、操场、图书馆）；办公；商业（商场、超市、集市）；医疗；住宿（酒店、民宿）；交通（车站、机场、车厢、机舱）；休闲（公园、动物园、博物馆、展馆、游乐园、剧院、体育场） |
| 建筑设施 | 住宅、高楼、古建筑、宗教建筑、桥梁、道路、街道、广场、园林、城墙、隧道、水坝、码头、雕塑、纪念碑、游乐设施 |
| 活动 | 用餐（聚餐、野餐、烧烤）、烹饪、学习、工作、购物、运动（跑步、骑行、游泳、球类、滑雪、攀岩）、户外活动（徒步、登山、露营、钓鱼、划船）、文艺（演出、舞蹈、乐器、绘画）、园艺、手工、游戏、休息 |
| 事件 | 生日、婚礼、毕业、家庭聚会、节庆（春节、中秋、端午、圣诞）、旅行、搬家、日常记录；事件须额外证据，不能凭蛋糕断言生日或凭白裙断言婚礼 |
| 物体 | 食物（饭菜、水果、甜点、饮品）、车辆（汽车、公交车、火车、飞机、船、自行车、摩托车）、家具、玩具、书籍、电子设备、衣物、运动用品、工具、艺术品 |
| 环境条件 | 室内、户外、白天、夜景、日出日落、晴天、阴天、雨、雪、雾；拍摄小时/GPS 存在不能独立推出视觉场景 |
| 资料 | 文档、票据、证件、截图、屏幕翻拍、旧照片翻拍；屏幕显示/截图需可靠来源或画面证据，不能靠尺寸比推断 |

人工确认身份作为独立人物 facet，不把具体姓名写入公共预设词表，不由模型生成人物身份标签。元数据方向、相机字段、GPS 存在等独立 facet，不作为内容分类覆盖。

## 2. 关系与边界

- 允许多标签：森林+河流+人物+徒步，而非必建“森林河流人物徒步”组合类。
- 允许多个父级：同一规范 ID 可在合理的多个浏览入口出现，使用 typed edge 区分语义上位与导航展示；related 不参与后代展开。
- 室内/户外作为环境维度，与森林/活动并列；窗内看向森林、室内植物等允许不确定或多证据，不强行二选一。
- 树林/森林先有定义与样例；“深森林”规范化为候选“密林”或已有森林下的描述特征，不能仅靠字面自动合并。
- “人像”不等同于所有有人照片；“多人合影”需要构图/参与关系证据，不能把画面中路人数量直接视作合影。
- 旧 `subject.people` 中“人像”和旧 `subject.group` 中“合影”曾作宽泛别名；保留旧 ID 的历史宽泛定义，新“肖像构图”“有意合影”使用新 ID。歧义旧别名可返回多个候选供选择，不能自动把旧标签数据变成新细义。旧 `document.general` 同样保留文档/文字材料宽义，不靠改名缩窄历史结果。
- 旧 `activity.hiking` 保留徒步/登山宽义，新登山或步道徒步细类使用独立ID。所有新增可推理节点须有正向纳入定义和排除/不确定边界；没有定义的导航节点不能成为模型返回标签。种子中不设置“天然通过automatic”标记，质量门禁另行登记。
- 旧 `subject.people`、`scene.indoor`、`scene.outdoor` 等有效概念 ID 优先保留。旧聚类 `cluster.semantic.*` 映射到相似群组而非直接升级为语义类别。其他旧词汇通过显式迁移映射，不因为显示名相似就重写历史含义。

## 3. 动态扩展规则

LLM 提议前检索既有 ID/定义/别名和临近候选；语义重复合并为同一候选，歧义保持待审核。每个新类需有定义、维度、上下位/导航/相关关系、支持证据、反例/边界和代表图引用。默认候选池有界，每次评审可拒绝/合并/接受，拒绝不破坏已有人工照片标签。

新增、合并、退役和关系变化有版本历史。改名不重跑图片；定义改变生成受影响重评计划；结构合并重定向旧筛选，不删除旧人工审计。将候选结构变为 active 与其成员自动生效分别审批/校验，不能捆绑。
