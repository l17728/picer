# Picer 软件设计说明（SDD）

版本：1.5；更新：2026-10-10；SQLite schema 45。GUI 与驻留代理采用自包含安装和首次连接配对，远程 GUI 按服务模式跳过本地模型预检。本机五处程序、ModelServer 和远端 IndexService 已更新，三数据库完整性与升级前数量已核验。当前 v1.3.5 发布、安装和部署证据统一见[媒体实施记录](MEDIA_STREAMING_IMPLEMENTATION_2026-10-10.md)；旧版本记录保留为历史。

本文描述已实现架构。产品交互见 [产品设计](PRODUCT_DESIGN.md)，操作见 [用户指南](USER_GUIDE.md)，当前验证与暂停事项见 [开发计划](DEVELOPMENT_PLAN.md)。早期方案和历史验收保存在带日期的实施报告中，不作为当前表结构或运行状态。

远程媒体新通道采用独立认证 WebSocket、1 MiB 二进制拉取、源端 256/1600 预览、读取租约和端到端 Range。GUI 通过只监听 loopback 的 Kestrel 代理向所选播放器提供临时单视频地址，服务令牌不进入播放器。原图读取槽与预览槽独立有界；缓存、租约、取消及旧协议边界见[媒体实施记录](MEDIA_STREAMING_IMPLEMENTATION_2026-10-10.md)。

## 1. 系统边界与组件

Picer 是 Windows x64、.NET 8 WPF 照片和视频管理器，采用 MVVM、SQLite 和本地缓存，支持本地文件与 WebDAV。

| 组件 | 当前职责 |
| --- | --- |
| Picer.App | 界面、用户授权、任务编排、本地模式及远端索引的本地镜像 |
| Picer.Core | 索引、存储、检索、人物、视频、缓存、数据库及授权文件操作 |
| Picer.IndexService | 本地管道或 HTTPS 网关、权威索引、任务及分析请求中转 |
| Picer.MediaAgent | 源电脑上的媒体读取、扫描、抽帧等任务及所属缓存清理 |
| Picer.ModelServer | 独立部署的模型、训练与制品服务 |

“只读”约束针对原始媒体，不表示数据库、服务接口和缓存只读。服务提供经授权的索引更新、分析、同步和清除操作。App 仍负责界面和部分批次编排；关闭 GUI 不保证所有由 GUI 发起的批次继续执行。

## 2. 文件安全与授权

索引、搜索、描述、人物识别、重复检测及保留建议不修改原文件。删除原文件使用现有边界：

```csharp
public interface IUserAuthorizedFileOperation
{
    Task<FileOperationResult> MoveToRecycleBinAsync(
        DeletionPlan plan,
        CancellationToken cancellationToken = default);
}
```

破坏性文件操作遵循 `Detected -> Reviewed -> Confirmed -> Executing -> Verified -> Completed/PartiallyFailed`。执行前复核路径、大小、修改时间和内容哈希；只有核验回收成功的项才能清理索引。失败与未确认项不自动升级状态，保留规则不能代替人工确认。

`IndexEngine.RemoveIndexRecordAsync` 表示索引清理。用户明确选择“彻底清除索引”时走独立的索引清除流程，原文件保持不变；这与移到回收站不同。

## 3. 数据身份与多引用

文件路径是位置引用，SHA-256 是完整内容身份；文件名、大小和修改时间不能独立证明内容相同。照片保留 `images` 位置记录及 `image_contents` 内容投影；视频通过 `videos.content_id` 关联 `video_contents`，内容哈希唯一，旧的未知哈希记录不能凭弱特征合并。

视频摘要、转录、关键帧、人物等派生信息归属内容实体，相同视频分布在多个目录时保留多个位置和一份共享派生数据。视频文字文档以负的 content ID 区分媒体类型。兼容接口中的视频引用 ID 不等于派生表内部的内容键。

v45 将视频人工编辑绑定内容身份，同内容多个引用按字段选取最新操作。删除一个位置前把仍有效的共享编辑移交给存活引用；原路径换成不同内容后不重放旧内容的编辑。迁移保留人工决策冲突的历史信息，不把它们当作新检测的人脸。

源文件不可访问时保留索引和已有缩略图，标注“已删除或移动”。缺失不等于确认删除，也不触发自动清除。

## 4. 索引、目录扫描与移动修复

常规索引通过异步枚举、有限并发分析和短事务写入降低 UI 阻塞。路径、元信息与内容身份承担不同职责，失败或不完整枚举不能作为缺失对账依据。

目录媒体描述使用 `DirectoryMediaScanner` 和 `DirectoryMediaChangeTracker`。首次扫描建立持久目录清单；支持可靠 NTFS USN 读取时保存日志水位，后续仅重新枚举受影响目录并复核已知信息。日志断档、磁盘身份变化、非 NTFS 或不可靠通知时保守回退。完整内容校验是独立选项，扫描并非永远只做一次。

缓存不是数据库事实：持久清单可失效、可重建；手动清除会遗忘对应文件并轮换失效代际，阻止旧扫描结果晚到后重新发布。文件读取前后检查签名，变化中的文件不能发布为稳定扫描结果。扫描取消、失败或范围未完整核验时不执行缺失对账。

多根目录修复枚举新目标，以完整 SHA-256 重新关联位置并保留记录 ID、描述和人工标记。多个相同副本保留为多个引用。无法证明身份的候选保持未匹配；旧视频没有哈希且旧文件已经丢失时，无法安全自动修复，应在大规模移动前完成新版扫描。

## 5. 目录照片和视频描述

AI 菜单提供目录树选择，范围包含节点及其所有子目录。树使用数据库中去重的父目录构造，预览按 SQL 子树条件和批量描述状态读取；目录中的通配字符按字面量处理。预览表示扫描前已索引范围，开始扫描后才得到包含新文件的实际范围。

目录树构造和预览在后台运行，选择变化取消或丢弃过时结果。共享数据库操作经统一调度，独立查询使用独立连接，不能在裸 `Task.Run` 中并发使用同一连接。

已有且仍适用的描述会跳过。照片阶段结束后处理视频阶段；本地模型默认 2 路、可选 1～4 路，云端收费请求串行。视频缺少关键帧时先生成，再使用配置的视频总结模型结合已有转录分析。相同内容的视频采用数据库与内容级互斥，锁内再次检查有效摘要，避免多引用重复模型调用。

运行策略统一约束启用状态、数量、预算和精确 GPS。费用按请求记账并预留预算，复用共享内容不产生新调用费用，显示估算不代替服务商账单。用户取消释放未消耗预留，不能因旧表状态 CHECK 约束变成数据库异常。

结果逐项保存。失败包含阶段、可重试性及安全错误码；取消单独统计。“仅重试失败项”不重跑成功项。模型错误、预处理失败和保存失败应能区分，日志不保存凭据或模型原文。

## 6. 文字检索与 AI 问答

已实现的组件为 `MediaTextIndexRepository`、`MediaTextRanking`、`MediaSearchTool`、`AiMediaRetrievalService` 和 `PeopleService`。原早期方案中的独立 ai_text_documents、facets、完整证据取回服务不是当前数据库契约。

`media_text_documents` 和相关 FTS 投影承载可检索文字。`ChineseSearchTokens` 的 `han-bigram-v1` 使用规范化后的汉字单字及相邻双字、拉丁字母数字串；这是字符切分，不是中文词典分词。`media_text_rank_fts` 使用 SQLite FTS5 的 BM25 排序，分值越低排序越前。

问答流程为：

1. 从问题解析人物、时间、地点和关键词；显式本名或别名由已确认人物解析，采用最长合理边界匹配，多人按交集约束。
2. 以结构化条件、GPS/地点文字及 FTS/BM25 召回候选；模型不能创造人物 ID，召回回退不能移除用户明确的人物约束。
3. 用候选描述和转录等摘要进行模型 JSON 复核，返回 ID 必须属于候选；null 或不可用 JSON 安全回退。
4. 程序生成固定的“程序确认结果”，模型只生成单独的“AI 解释（非检索证据）”。流式更新仅影响解释区域；无候选时不请求模型编造命中。

当前召回具有数量与上下文上限：主要候选上限 200，供复核的照片和视频各最多 50；视频转录摘要截取最多 500 字符。不能声称模型总是读取完整原始记录，或保证开放语义查询穷尽全部相关媒体。程序确认表示候选及匹配条件经过程序约束，不保证模型内容判断没有误差。

Chinese-CLIP 中文语义检索是独立的照片向量检索入口，使用余弦相似度；不能把它描述成已自动融合到上述 BM25 问答的统一向量排序。

## 7. 人物、视觉及学习

`VisionRepository` 保存按模型版本隔离的检测与特征，`PeopleService` 管理已确认身份及别名，视频人物时间线关联共享内容。InsightFace 为当前主要人物流程；历史 SFace 等结果保留来源，不跨模型比较向量或阈值。

候选相似、上下文推荐和模型建议不能自动成为已确认身份。逐脸确认、纠错、拒绝、不分类等人工决定持久化；后续检测不得无条件重新生成已处理的待分类项。模型切换保留人工决定及必要历史。

人物特征属于敏感生物识别数据，不能声称不可逆从而无隐私风险。训练快照准备、远端提交、制品应用分别授权。原型、阈值及轻量度量适配器支持版本化评估、应用和回滚；这不等于已对基础人脸网络进行完整训练。质量门禁与外部数据验收独立于代码测试。

## 8. 视频处理与缓存

视频支持探测、抽帧、转录、人物时间线和摘要。Qwen ASR 服务与 Whisper 基线/回退依配置和运行组件可用性工作；不能把设计中的真实视频质量验收当作已经通过。

当前远程原文件接口仍完整缓冲，代理整文件资产上限为 64 MiB，视频下载完成后交给外部播放器。服务端已有 Range 响应不代表源代理按需读取；端到端分块、取消传播、短缓冲播放及拖动跳转属于[待实施性能方案](PERFORMANCE.md)。

本地抽帧使用实际内容 SHA-256 和独立 run 目录；源代理使用每次独立生成目录，成功后发布。较短的新结果不能混入旧尾帧，新内容也不能覆盖另一个引用仍使用的旧帧。海报按内容身份隔离，未知可信身份时不复用旧海报。

本地内容哈希缓存最多 128 项。复用须同时核验 Windows 卷、文件 ID、ChangeTime、长度、有效 NTFS 日志 ID 和同一打开句柄读取到的逐文件 USN，并在读取前后复核。仅靠 ChangeTime 仍可能漏掉极短间隔改写；日志不可读、重建、身份变化或 USN 不可信时完整计算哈希，不保留快路径结果。详见[视频哈希 USN 修复](VIDEO_HASH_USN_FIX_2026-10-09.md)。读取失败、取消和发布失败清理本次暂存，保留仍被引用的已发布缓存。

保存晚到结果前复核原引用及内容身份，已清除或换内容时不得回填。界面异步操作捕获开始时的视频，切换选中项后不把旧结果显示到新详情。

## 9. 手动彻底清除

照片与视频清除是用户授权的索引操作。删除所选位置的索引、编辑和任务相关记录以及所属缓存；末引用才删除共享内容与派生索引，其他存活引用仍能使用共享结果。

视频清除在本地、HTTP 和管道入口保持一致。操作生命周期先阻止新写入、取消并等待已有工作结束；服务任务结果及 journal、代理抽帧缓存、本地关键帧/海报及远端物化副本一并按归属清理。不能把 HTTP 请求结束当作源代理 FFmpeg 已退出。

本地库与远端镜像的数字 ID 可能重合，缓存必须按归属隔离，不能只凭 ID 清理另一库资产。源代理不可达或清理失败时保留可重试状态；批次中已经成功项不再次清除，只重试剩余项。

失效扫描清单及哈希缓存，清理本地 mirror_owned_media。同步删除协议可保留仅含类型、ID、水位的最小 tombstone，不保留路径、哈希、描述或可检索内容。原文件不删除；用户以后明确扫描该目录仍可重新建索引。

## 10. C/S、镜像与元数据一致性

`IIndexGateway` 的本地、HTTP、管道实现承载相同业务边界。认证、证书固定和独立远端授权不因“本地模型”称谓省略。远端索引服务可能接收转发媒体；本地推理不等于数据仅停留在 GUI 电脑。

ServiceMode 使用权威镜像变更流，按 epoch 和分页水位同步；完整成功的页才能推进 checkpoint。取消、分页窗口变化、重置未完成时保留可恢复进度，不能把部分列表当作完整远端集合删除本地记录。重置清理仅涉及本镜像拥有的记录，不能按重合 ID 删除独立本地媒体。

权威元数据同步包括场景、标签、相册和人物字典的删除；保留尚未确认的本地编辑后重放。已确认且远端已删除的旧操作不能反复复活字典。本地对等同步不导入未经映射的远端媒体 ID。旧协议回退完整分页核对，媒体总数相同不能证明镜像未变化。

## 11. UI、性能和可观测性

PhotoGrid 提供虚拟化、缩略图加载取消和稳定选择；主照片查询使用 keyset 分页。其他目录、字典和网关接口仍可能使用分页或完整集合，不能宣称全系统均为 keyset。

UI 先显示骨架，后台加载可取消，过时结果不得覆盖新选择。同步 SQL 与缓存工作不长期占用 Dispatcher。性能目标和测量方法见 [性能说明](PERFORMANCE.md)，功能测试通过不等于任意设备满足延迟目标。

日志记录阶段、计数、耗时、错误类型及安全诊断，不记录凭据、人物姓名/别名、特征向量或 AI 问题正文。诊断导出做脱敏；任务日志与收费流水不是原始媒体归档。

## 12. 数据库迁移、备份和回滚

所有模块共用 `PicerDatabase` 的连续 `PRAGMA user_version` 迁移，当前为 45，不存在人物模块另起的 schema 版本。v42 补视频哈希，v43 补费用/预算等表及查询索引，v44 引入视频内容和镜像变更，v45 修复内容绑定人工编辑。

升级要求关闭所有同库写入者，完整备份 DB/WAL/SHM，在暂存副本迁移、校验后可恢复地发布。发现活动写入者拒绝升级。不能通过 DROP 业务表或手动降低 user_version 来回滚；恢复使用经过验证的旧备份及相容程序。实际部署前单独核验运行库版本。

应用内用户备份采用一致性快照，恢复和目录迁移经过验证与重启；不将原媒体或 Windows 凭据视作数据库备份的一部分。
