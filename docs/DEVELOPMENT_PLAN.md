## 2. 当前发布与验证

最新正式版为 [v1.4.0](https://github.com/l17728/picer/releases/tag/v1.4.0)，schema 45；私有仓库下载需要访问权限。测试、安装及发布证据见[本版实施记录](PERFORMANCE_FOLLOWUP_IMPLEMENTATION_2026-10-10.md)，历史部署与本版发布分别记录。

GUI/独立 Agent 中文当前用户一键安装器已实现，包含自包含 .NET、app-local MSVC CRT，代理 tools/ffmpeg 目录同时提供 FFmpeg、FFprobe 及许可证并自动发现。纯远程 GUI 不需要 Python、CUDA 或模型 runtime，也不检查本地 runtime。首次从“文件 → 连接索引服务…”完成无凭据证书发现、指纹确认、固定公钥验证及 DPAPI 保存，无需编辑 JSON。模型端 setup-modelserver.py 默认 CPU 的实际验收已通过；GPU 和授权模型依然按服务端配置。详见[安装实现记录](INSTALLER_IMPLEMENTATION_2026-10-10.md)和[安装指南](RELEASE_GUIDE.md)。

v1.3.5 的部署、安装包校验和真实服务验收证据统一见[媒体实施记录](MEDIA_STREAMING_IMPLEMENTATION_2026-10-10.md)。

[v1.1.2](https://github.com/l17728/picer/releases/tag/v1.1.2) 仍是已发布的历史版本，旧 CI/发布历程见[发布部署记录](RELEASE_DEPLOYMENT_2026-10-09.md)。本轮安装器采用独立的 CI、安装与发布证据。

远程媒体性能改造已实现，测试和发布证据见[媒体实施记录](MEDIA_STREAMING_IMPLEMENTATION_2026-10-10.md)。四项历史 P2 仍暂停。
## 3. 仍暂停的四项外部 P2 验收

按用户指令保留暂停状态，不启动这些任务，也不标为代码缺陷：

| 验收 | 所需真实证据 |
| --- | --- |
| 人脸质量 | 独立标注数据、跨组划分及 FAR/FRR 等门禁 |
| 视频转录质量 | 至少 20 个真实标注视频与 Whisper 对照 |
| AEC3 全双工 | 真实房间连续 10 分钟体验和回声证据 |
| 低配置 | 16 GB RAM / 2 GB GPU 设备的响应、内存与回退验收 |

已有测试脚本、运行能力和曾经成功启动服务，不等于这些质量或硬件验收已通过。解除暂停须沿用用户后续指令。

## 5. 开发与验收规则

原始照片和视频保持只读，回收站操作必须用户明确确认并复核身份。自动修复仅凭强内容身份关联；旧视频无哈希且已丢失旧路径时如实保留未匹配。

功能变更同时更新用户指南、架构和针对性测试。数据库迁移进入同一连续版本链；功能测试使用隔离数据，不能读取或修改真实图库。测试临时目录由 PICER_TEST_TEMP 或 picer.paths.json 的 testTemp 决定，当前默认 artifacts/test-temp 下的项目子目录；PICER_DATA_ROOT 用于隔离应用数据。早期将 D:\PicerData 写成固定测试路径的说明已失效。

性能测试记录硬件、数据规模、冷暖缓存及分位数，见 [性能说明](PERFORMANCE.md)。外部模型、网络和设备门禁与代码完成分别记录。定位日志不得包含凭据、人物姓名、特征或问题正文。

## 6. 维护阶段

优先处理实际使用中可复现的错误、退出、索引一致性或性能退化；报告应包括版本、电脑角色、操作入口、时间及脱敏日志，不附令牌、人物特征或原始私人媒体。新增功能需重新确定范围，不把旧历史文档中的“待办”直接加入当前交付。

维护修复保留有意义的回归证据，按严格构建和 CI 验证，再以新版本标签发布；不覆盖 v1.3.5 标签和安装包。数据库更新遵守关闭写入者、整组备份与可恢复迁移。文档修订同步更新当前说明，原始失败和部署记录继续保留。
