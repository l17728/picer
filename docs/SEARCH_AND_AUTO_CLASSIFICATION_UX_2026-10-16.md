# 照片检索与自动分类 UX 规范（2026-10-16）

## 1. 目标与原则

本规范将“照片检索与自动分类设计定稿”落到用户入口和逐步操作。目标是用户无需先读技术说明即可开始后台整理、浏览分类、纠正结果和查找照片。普通浏览/搜索不因建立分类或模型分析而阻塞。

- 清楚区分“自动归类（机器结果）”“建议/待确认”和“用户已确认”；机器结果不是用户确认。
- 只有达到逐类别验证门槛的视觉标签才显示为“自动归类（机器结果）”。其他视觉推断保留为建议或未分类，不伪装成确定事实。
- 可核验元数据可自动形成筛选分组，并显示具体依据，例如“横向照片”“相机：Canon EOS …”“照片记录了 GPS”。显示 GPS 不等于断言地名正确。
- 待确认建议默认不进入普通搜索/AI 问答；高精度自动机器分类和用户确认标签默认可搜索。用户可以显式打开待确认建议参与搜索，结果上保留“待确认”徽标。
- 每个自动结果都能一键纠正或移除；纠正机器来源不得删除同一类别的独立人工标签/确认。
- 默认不为生成分类而触发新的云端图片分析。所有新云端/计费分析仍通过现有 AI 描述入口和确认/预算流程启动。

## 2. 导航与页面信息架构

主菜单增加唯一全库入口：

`AI 功能 → 照片分类与审核…`

打开独立的“照片分类与审核”窗口。它不要求先选择照片，也不替代现有“标签与相册”页。对单张或选中多张照片，可从照片右键菜单/详情窗进入相同审核面板；所选范围随进入上下文预先填好。

全库窗口顶部包含：

1. 当前处理范围：“全部已索引照片”或从照片选择上下文传入的数量。
2. 运行状态：未开始、排队/处理中、已完成、部分失败、已暂停、已取消、上次任务中断。
3. `开始后台整理` / `暂停` / `继续未完成分类` / `取消本次任务` 按钮；关闭窗口不取消任务，任务只在 Picer 进程运行期间继续。
4. 简短说明：“使用已有描述和可核验元数据；不会因此自动上传照片或产生新的云端分析费用。”
5. 若有未描述照片，显示“有 N 张照片尚无视觉描述”，并提供独立操作 `查看描述任务…`，跳转到现有 AI 描述工作流。该按钮不得直接启动付费调用。

窗口主体使用二级页签。审核对象是一个分类项 `(照片, concept_id, 来源)`，而不是互斥的照片状态；一张照片可同时出现在多个分类页签。每个页签显示“分类项 N 条，涉及照片 M 张”，不同页签的数量不能相加为照片总数。

| 页签 | 含义 | 默认排序 |
|---|---|---|
| 待确认 | 有视觉模型结果但尚未达到自动归类门槛，或需用户审阅的候选 | 最近生成优先 |
| 自动归类 | 达到该分类门槛、以机器来源生效的标签 | 最近处理优先 |
| 用户已确认 | 用户明确确认/修正的分类 | 最近确认优先 |
| 无分类 | 分类任务已完成、当前没有有效分类项的照片；“尚未处理”“无描述”“失败”不属于此状态 | 最近索引优先 |
| 已忽略 | 用户明确拒绝过的机器类别，查看后可恢复为待确认 | 最近拒绝优先 |

尚未处理、描述缺失、处理中、失败是照片处理状态，放在页签上方的处理状态筛选/计数区，不与分类项页签混用。失败项可点 `重试失败项`。

分类页签支持类别过滤、日期/目录过滤、排序、缩略图网格和键盘焦点。列表卡显示缩略图、文件名、分类词、来源徽标、状态、来源简述；模型/提示版本和原始描述在详情抽屉中展开，不在每张卡片堆砌技术信息。

## 3. 首次使用流程

1. 用户点击 `AI 功能 → 照片分类与审核…`。
2. 空状态显示“还没有自动分类结果”，解释分类会使用已有照片描述和文件元数据。明确告知本次不会自动上传图片或生成云端费用。
3. 用户点击 `开始后台整理`。首次执行若只包含可核验元数据与已存在描述，显示范围、未处理照片数和可跳过数；不要求用户先运行完整扫描。
4. 分类任务后台增量处理。用户可以关闭窗口并继续浏览照片；任务在 Picer 进程运行期间继续。若用户退出 Picer，当前批次安全提交后任务停止；下次打开后提示“上次任务已中断，已完成结果已保存”，用户点击 `继续未完成分类` 从剩余项恢复。启动时不自动运行。
5. 达标机器类别进入“自动归类”；未经质量门槛验证的视觉类别进入“待确认”。处理完成但没有有效分类项的照片进入“无分类”。无描述和失败照片在处理状态区显示。
6. 没有视觉描述的照片不触发新模型调用。窗口提供 `查看描述任务…`，用户自行前往已有目录描述入口；完成之后再返回分类页继续处理。

如果用户明确选择了需要云端分析的现有任务，沿用现有预算、许可和任务中心行为；分类审核不能绕过确认、预算或分析记录。

### 暂停与取消

- `暂停`：当前数据库批次提交后暂停；已完成项保留。点 `继续未完成分类` 从剩余项继续。
- `取消本次任务`：先说明“已提交批次保留；未处理项目仍可稍后继续”，然后停止领取新批次；不删除已完成分类或拒绝记录。取消后仍可继续未完成分类。
- 关闭窗口只隐藏窗口；退出 Picer 会在当前批次安全边界停止，启动后不会自动恢复。

## 4. 审核及纠错流程

### 单张

用户在“待确认”卡片选择一张照片，可执行：

- `确认分类`：把选中的一个或多个建议变为用户确认数据，并保留“用户确认”来源及确认时间。
- `改为…`：从受控视觉类别选择正确分类；必要时可同时保留其他合理的多标签。
- `不是此类`：拒绝该照片的该机器类别，记录持久抑制，后续同模型/新模型运行不得把它加回。该操作只影响这张照片及该类别，不创建全局规则。
- `暂不处理`：保持待确认，不改变搜索资格。

机器结果卡片提供 `纠正`、`不是此类`、`撤销机器归类`。撤销只移除与当前照片/类别匹配的机器来源；若另有同名人工确认，保留并明确提示“人工标签仍保留”。

“已忽略”页签提供 `恢复为待确认`，清除该照片/类别的拒绝记录并恢复为建议状态；恢复不会直接自动确认或加入搜索。

所有纠正后显示短暂状态条，例如“已移除这张照片的机器分类。撤销”。撤销恢复操作仅限当前事务及未被后续用户编辑覆盖的项目；数据库失败时不显示成功提示，并提供重试。

### 批量

- 多选只允许批量确认同一个类别；不同类别的候选不允许一次性混合确认。
- 批量操作前弹窗明确展示操作、分类名称、照片数量和若干缩略图，例如“确认将 24 张照片归为‘海边’？”。默认焦点为“返回检查”，确认按钮为显式二次操作。
- 批量 `不是此类` 同样显示数量与类别；确认后仅写入机器类别的拒绝记录。
- 提供一次操作后的 `撤销本次批量操作`。不支持跨批次、无限期的隐藏回滚；失败行列出并可重试，成功行不重复执行。

## 5. 搜索交互与命中含义

主搜索栏保持现有自然语言/文字入口，不改变普通搜索的即时行为。搜索结果来源的优先级：

1. 参数化结构化约束（用户指定的人物、日期、媒体类型、明确地图范围、状态）保持硬约束。
2. 用户确认标签和人物身份正常参与搜索。
3. 达到质量门槛的“自动归类（机器结果）”默认参与搜索，并在照片卡片/详情显示该徽标及纠错入口。
4. “建议/待确认”默认不参与普通搜索和 AI 问答。搜索页增加未勾选的 `包含待确认的 AI 建议` 选项；启用后每个相关命中必须显示“待确认”徽标，AI 问答不得将其表述为已确认事实。
5. RRF/CLIP 候选来源启用前，搜索页说明“文字匹配 / 视觉语义匹配”等依据；未建向量索引时自动退回文字搜索，不能显示“已完成语义搜索”的误导状态。

对用户明确选定的地图范围/精确坐标，以及可无歧义规范化的日期范围，按硬条件处理。AI 将自然语言地点或含糊的季节/时间解析为候选提示时，不得偷偷变成硬过滤；UI 显示“按地点文字和照片描述查找”或实际采用的具体条件。

## 6. 状态、空结果与错误文案

| 条件 | 用户可见状态/操作 |
|---|---|
| 空图库 | “还没有已索引照片。先点击‘文件 → 添加文件夹’并完成索引。”开始按钮禁用。 |
| 尚无分类 | 空状态介绍已有描述/元数据来源；按钮 `开始后台整理`。 |
| 处理中 | “正在整理：已处理 N / M；可以关闭窗口，继续使用 Picer。”显示 `暂停`。 |
| 暂停 | “任务已暂停；已完成结果已保存。”显示 `继续`。 |
| 完成，无待确认 | “已完成：自动归类 N 张，待确认 0 张，未分类 M 张。”可切到相应页签。 |
| 有待确认 | “有 N 张照片需要你确认。未确认的建议不会默认参与搜索。”打开待确认页签。 |
| 有已忽略项 | “有 N 条机器分类曾被你忽略。它们不会自动重新出现。”提供 `查看已忽略`。 |
| 没有视觉描述 | “N 张照片还没有视觉描述；本次没有为它们请求云端分析。”按钮 `查看描述任务…`。 |
| 部分失败 | “N 张失败，其他结果已保存。”按钮 `查看失败项`、`重试失败项`。失败详情不展示 token、密钥或原始查询。 |
| 模型/组件不可用 | 说明哪个能力不可用，保留元数据分类和现有文字搜索；提供 `打开组件检查`，不崩溃、不阻止浏览。 |
| 筛选无结果 | 显示当前筛选类别与来源状态，并提供 `清除筛选`；不自动放宽明确约束。 |
| 分类撤销成功 | “已撤销这张照片的机器分类。用户确认的同名标签仍保留。”提供 `撤销本次操作`。 |

低置信标签不展示百分比。分类卡以分类状态和来源解释可信度，避免把模型分值误读成校准后的概率。

## 7. 无障碍与测试可操作性

- 所有页签、筛选器、操作按钮、进度、错误和对话框具有中文 `AutomationProperties.Name` / `HelpText`。
- 支持 Tab、Shift+Tab、方向键和空格；多选支持 Ctrl/Shift。确认对话框默认焦点在安全返回按钮。
- UI 自动化断言中文按钮、状态及分类来源徽标；列表项使用稳定 automation id 或可访问名称，不依赖坐标点击。
- 屏幕阅读器能分辨状态和来源，例如“海边，自动归类，机器结果，可纠正”，而不是只读出类别名称。

## 8. UX 验收清单

1. 新用户从 AI 功能菜单进入全库分类页，在不选择照片的情况下能启动后台任务，明确知道不会自动产生云端费用。
2. 后台运行时可关闭窗口、浏览和搜索；重开后任务状态和部分完成结果一致。
3. 未经类别精度门槛验证的视觉标签只出现在待确认，不冒充自动归类。
4. 待确认标签默认不影响普通搜索/问答；显式开启时命中标记待确认。
5. 自动机器结果可从一张照片撤销；同一类别的用户确认标签不会被删除。
6. 用户拒绝的机器分类在同一照片/类别的后续处理及模型更新后仍不会复活。
7. 用户可从“已忽略”恢复单项或同类别项；恢复后只回到待确认。
8. 多选混合类别时阻止批量确认；同类别批量确认明确展示类别、数量和预览，并提供撤销。
9. 空图库、空分类、模型缺失、部分失败、取消、筛选无结果均有可操作提示；不自动放宽用户筛选。
10. 现有“用户标签与相册”和中文语义检索入口继续可用；当前交互不会要求用户迁移现有标签。

## 9. 最终交互契约补充（优先于前文简写）

- 分类项以 `(已验证内容 SHA-256, concept_id, 来源)` 去重；列表同时显示分类项数和涉及照片数。同一内容的多个路径引用合并为一张卡并显示引用数。没有已验证哈希时按当前 `image_id` 操作，不猜测其他副本；确认/拒绝记录一旦取得可信哈希，才事务性升级到内容级并应用于完全相同的内容。
- “无分类”只表示处理已完成且没有有效分类的照片。未处理、缺少描述、处理中和失败均只属于处理状态筛选器。类别允许多标签，所以各分类页签计数不能相加作为照片数。
- 自动分类仅用于可直接验证的元数据事实，且限于白名单：方向/尺寸、相机字段存在、GPS 字段存在等；界面必须描述事实边界（例如“包含 GPS 坐标”）。GPS 推断“户外”、宽高比推断“全景”、拍摄小时推断“黎明/黄昏”等语义启发式永远是待确认建议，即使分数高也不得标成自动归类。所有未经逐类别离线评测的视觉场景标签同样待确认。
- `确认分类`创建独立的用户断言；模型候选保留 `vision_model` 来源并标记已审阅/已接受，不能改写为用户来源。相同内容/类别的卡片聚合来源徽标，搜索不重复照片。`移除机器分类`只移除机器断言，用户断言保留；机器断言不存在时隐藏该动作。纠正类别在同一事务中确认新类别并拒绝旧机器候选；同类确认不创建拒绝记录。保留独立“不是此类”操作。移除反馈为“已移除机器分类。[撤销]”，明确不会删除人工标签。
- `已忽略`项提供“恢复为待确认”；恢复只清除拒绝并回到建议，不自动确认。撤销说明只针对本次操作和未被后续编辑覆盖的记录。
- 搜索栏的“包含待确认的 AI 建议”是一个请求级开关，普通搜索和 AI 问答共用同一个请求状态，默认关闭；清空搜索/问题后关闭。启用时所有建议命中都标“待确认”，AI 问答不得将其表述为已确认事实。
- 窗口关闭只隐藏界面，任务继续；退出 Picer 时保存已提交批次并标记中断，下次用户点击“继续未完成分类”才恢复。暂停在批次边界停止领取并保留可恢复进度；取消停止本次运行但保留结果，仍可手动继续剩余项。不得把暂停和取消使用同一状态或提示。
- UI 自动化为状态区域设 `AutomationProperties.LiveSetting=Polite`；卡片名称包含文件名、类别、来源、状态和引用数量，按钮使用稳定 `AutomationId`。键盘焦点可进入缩略图卡片、选择、确认、拒绝、撤销及恢复。视频标签界面不在本次改造范围内。



实现冲突、来源隔离、内容级拒绝、自动分类白名单及任务恢复契约以[最终实现裁定](SEARCH_AND_AUTO_CLASSIFICATION_DECISIONS_2026-10-16.md)为准。


计数口径：‘涉及照片数’按不同 content_identity 卡片计数；同一卡片的路径引用另显示为‘路径引用 N 个’。任务摘要、页签、UIA 播报和自动化断言使用相同定义。
