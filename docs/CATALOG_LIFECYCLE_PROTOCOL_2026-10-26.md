# 目录对象生命周期协议实施细化

状态：开发细化；关联执行和来源校验已有回归，以下生命周期封口与 UI 尚未全部实现。继承双向同步 SDD，不将“解除关联成功”解释成“目录对象已完整删除”。

## 需要封闭的两个竞态

1. 标签、相册或人物业务行删除后，旧字段版本也可能被清除。晚到的目录快照随后重建对象和关系，会使删除失效。应单独保存 publisher + kind + global identity 的最小退出标记，在目录、关系及人工字段导入时一起过滤已退出身份。
2. 来源人物合并先产生新归属，再退出旧人物。若退出消息先于新归属到达，可能把正常合并变成冲突。删除事务应封存其最终元数据 revision，只有已发布快照覆盖该 revision 后才发送对应退出消息；不能要求整个图库始终静止。

## 身份与新生命周期

- 退出标记只作用于指定 publisher 的稳定目录身份；同名共享标签的其他来源身份保持有效。
- 整数 ID 和同名不能作为旧身份复活的依据。显式创建的新对象使用新的 global identity；反向映射和身份认领需要排除已退出身份，不能把新对象的字段回传到旧的本地 ID。
- 新生命周期与旧业务行因标签名称规范化而复用时，仍需保留人工字段的并发检查。只有能够证明当前解除关联字段由已确认的退出操作产生，才可把重新创建视为该退出的后续操作；否则保留冲突。
- 已接受关联删除产生的字段操作身份需要随最小回执保存，用于上述证明；不保存人物姓名、别名或嵌入。
- 没有媒体关系的空对象仍有独立生命周期，不能因为按媒体分页返回空页而被永远忽略。

## 确认与恢复

逐媒体关联确认，未选目录保留待办。完成状态不能被过时的失败报告覆盖。视频同内容引用超出当前范围时暂缓，扩大授权后重新检查；不借内容哈希修改其他 owner 的索引。

旧库删除记录没有删除前依据时，不制造空基线。它需要明确恢复或审核。重建基线期间停止正常投递；恢复后仍按稳定身份和当前授权检查。明确媒体索引清除会同时清除其关系记录、基线和执行回执。

只有退出生命周期的关联均被确认、没有未处理冲突，且没有其他来源/本地私有引用时，才收尾移除目录业务对象。回执压缩必须晚于确认水位，不能按时间直接丢弃防复活标记。

## 冲突交互

沿用“处理同步冲突”入口，增加标签、相册、人物删除冲突。显示对象类型、可用的对象名称、受影响媒体预览和涉及的来源；对象名称已不存在时明确显示“已删除的标签/相册/人物”，不把内部 ID 作为主标题。

提供“保留当前关联”和“同步删除关联”两个明确操作。提交时带上审核时的当前指纹及空间 epoch；审核后又发生修改时刷新冲突，不执行旧决定。涉及范围外引用时显示需要补充授权的原因，不提供绕过授权的强制删除。

选择保留当前关联后，需把被本地提前删除的目录对象及已授权关系恢复到一致状态；不能仅把冲突状态改成已解决。选择同步删除后则生成新的显式决议，并把最终结果回传来源。离线来源显示待同步，其他来源的数据不复制到本机。

## 放行顺序

先完成退出标记与旧快照过滤、发布 revision 封存、空对象及目录收尾，再开放网络入口并接入来源自动同步。随后验证：中断重试、范围恢复、授权撤销、旧快照、同名重建、人物合并、多根来源隔离、用户审核期间再修改、永久清除，以及 A/B 来源加远程 GUI 的整体验收。当前未满足该放行条件，不发布完整双向删除能力。
