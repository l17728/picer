# 同步恢复与视频人脸向量保护

日期：2026-10-23。本文记录在 schema59 基础上的追加修复，不代表完整双向同步方案已经交付。

## 基线完成确认

来源端完成空间基线核对后，只有服务端返回相同发布者、相同 epoch、清零序号且没有剩余身份页的确认，才能将本机状态由 `rebaselining` 改为 `publishing`。本机更新还要匹配当前 epoch 与恢复状态，防止错误确认使客户端提前恢复上传。

服务端提交完成但网络响应丢失时，本机仍保存 `rebaselining`。下一次注册取得相同 epoch 和零序号后，使用已有恢复分支完成本机确认。测试另模拟 HTTP 200 中携带错误 epoch 的确认：拒绝该确认，保留恢复状态，并在重试时恢复。测试使用隔离账号和真实 HTTPS 服务，不操作生产账号或原照片。

## 视频人脸向量

镜像接收视频人脸时，模型变化、视频内容归属变化或关键帧变化，均不能继续保留原向量；对端未提供新向量则清空。模型和归属均未变化时，缺省向量仍保留有效本机缓存。该规则与照片人脸已有保护一致，不新增数据库迁移。
