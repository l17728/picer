## 根因

人物 UI 为重复照片去重，只呈现同源照片组的代表人脸；“标记不分类”后的复核错误地调用最多 5000 条且应用同样去重的展示查询，再把结果用于逐 face ID 的写入校验。重复照片组中的其他 face ID 已写为 `ignored`，却不在展示列表内，于是被误报为移动失败。失败恢复分支复用了同一展示查询，导致 UI 也无法可靠识别已经成功写入的状态。

## 修复

- 增加 `GetIgnoredFaceIds`：按本次操作的精确人脸 ID 查询 `face_review_states`，分批参数化查询，不受展示分页和重复照片折叠影响。
- 批量操作成功校验与异常恢复都改用精确 ID 查询。
- 已全部写入但异常路径触发时，仍将状态排队同步，并从当前集合移除，不强迫用户切换到“不分类”列表。

## 回归

用相同内容的重复照片生成两条人脸记录并批量标记不分类：数据库精确查询必须返回两条 face ID，而去重后的“不分类”展示仍只返回一张代表脸。
