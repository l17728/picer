# 分类树节点照片计数实现报告（2026-11-23）

## 需求

分类浏览器左侧"分类树"的每个节点显示该分类的照片数量，且**隐藏计数为 0 的节点**（用户确认的显示方案），解决"很多分类是空的、一眼看不出哪些有内容"的问题。

## 实现

### 服务端（`Picer.Core/Classification`）

`ClassificationBrowseResult.Counts` 原本已包含每个标签 id 的精确计数（同层级去重、尊重"包含待确认建议/包含历史分类"开关），本次补充树分组节点所需的聚合键（`ClassificationCountKeys`）：

- `dimension:<维度名>`：按维度去重——一张照片在同一维度下打了多个标签（例如多个已命名人物）只计一次；
- `group:named-people`：已命名人物聚合，同样去重。

`Counts` 不参与快照摘要与同步契约，加键不使已有快照失效。

### GUI（`ClassificationBrowserWindow.BuildLabelTree`）

- 叶子节点显示 `名称（N）`；维度根节点显示 `维度（N）`；"已命名人物"显示聚合计数；
- 计数为 0 的节点隐藏；**当前选中的节点除外**（选择不因计数归零而凭空消失）；
- 全部维度计数均为 0（尚无任何分类）时回退为显示完整分类体系并标 0，避免树整体消失造成"坏了"的观感；
- 计数随"包含待确认建议/包含历史分类"开关实时变化，刷新时树同步增减节点。

## 验证

- 严格构建 `--warnaserror` 0 警告；
- 新增单元测试 `BrowseCountsIncludeDeduplicatedDimensionAggregates`：`scene.forest` 与其子标签同时标注同一照片时维度聚合只计 1；未触及维度聚合为 0；关闭建议后全部计数归 0；既有计数断言（`BrowseCacheInvalidatesPublishedLabels…` 等）不受影响；
- E2E `ClassificationV2UiTests` 增加断言：树上节点必须带计数显示；
- 完整 E2E 套件：171/171 通过（6.6 分钟；首轮曾因套件并行负载下"增量扫描"反馈等待 20 秒不足而偶发失败，已将等待放宽至 45 秒并在失败信息中带出窗口实际反馈文本）。

## 边界

- 隐藏空节点后，无法直接看到"还有哪些分类可用"；需要向空分类归档时，先在照片详情/决策流程中选择分类（或临时关闭再打开筛选开关触发重算）。若后续觉得不便，可加"显示空分类"开关。
- 分组节点的计数是"该维度下有照片的数量"，不是子节点计数之和（去重语义）。
