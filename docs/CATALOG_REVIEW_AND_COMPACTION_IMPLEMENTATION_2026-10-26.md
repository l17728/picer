# 分类删除审核、确认后压缩与跨基线恢复

本记录对应开发中的 schema85–86、元数据协议 10。尚未发布或部署。

## 用户操作

从“处理同步冲突”打开“分类删除冲突…”。窗口按照片／视频关联显示分类名称、媒体路径和缩略图，可选择“保留当前关联”“同步删除关联”或“刷新列表”。删除须确认；缩略图缺失或没有媒体读取权限时显示原因，不能用远端整数 ID 访问本地图库。

审核请求携带 publisher epoch 及当前字段指纹。审核期间发生新修改、基线切换或权限变化时拒绝过时决定。保留结果通过新分类身份恢复到另一端；涉及未授权视频引用的删除不能强制执行。离线端续办期间，巡检保留待办状态。

## 恢复和并发

自动上传等已发布元数据覆盖删除事务后再发送退出操作；下载先接收普通元数据，再处理退出。已审核的关联在后续上传前优先确认，以免旧身份编辑先被发送。

schema86 增加收尾审核队列，覆盖原关联已删除后又增加关联，以及给另一张照片新增关联的情况。这类审核不改变原完成清单的媒体数量。已确认远端完成、但本地收尾遇到新编辑的操作仍进入持久完成收件箱，审核后可继续恢复。

已修复两个实测问题：

- 分类退出改变了可认领身份集合，却没有使“无新身份”的检查点失效，导致远程选择保留后来源端不恢复分类。退出事务现同时清除该 publisher 的认领检查点。
- 空间清除更新镜像 epoch 时，未同步更新剩余无哈希照片的内容身份映射，导致基线重传被拒绝。服务端现保留文件版本 UUID，并更新仍有效的照片操作绑定、来源映射及因果／审核 JSON 中的本地身份命名空间。视频审核完成回执也纳入更新。

基线重建只在核对同一 publisher、设备授权、空间及序号后迁移完成收件箱的 epoch；尚待完成的分类身份保留至其完成，不能先删掉恢复所需的映射。

## 压缩

schema85 增加最小前序操作证明及压缩标志。来源端只有在本地也保存了完成状态后才请求服务端压缩；服务端确认后来源端才清理自身回执。断线重试沿用原完成身份。

清理逐媒体锚点、基线和执行回执，但保留旧分类身份的退出标记，阻止旧快照复活。仍是当前字段的前序操作只保留操作 UUID；字段被替换或清除后自动移除该证明。不能仅按时间删除尚未确认的记录。
