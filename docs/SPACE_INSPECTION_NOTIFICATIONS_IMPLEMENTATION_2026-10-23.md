# 全空间巡检任务与同步通知

日期：2026-10-23。开发源码 schema61；尚未发布部署。本文不是完整字段因果协议已经交付的声明。

## 用户操作

1. 打开 GUI 的“索引巡检、同步与修复…”。远程浏览窗口也提供同名按钮。
2. 点击“巡检并同步用户空间”。各来源仍使用自身保存的授权目录、人物及精确位置范围；远程按钮不增加本机目录或扩大授权。
3. 查看来源列表：等待通知、已通知、执行中、已完成、离线等待、失败、撤权、来源未绑定或取消。列表显示设备名称及最近成功回执；只有所有目标确认完成才显示空间完成。
4. 离线来源上线后继续领取任务，不需重新发起。关闭窗口不取消服务端任务；重新打开后恢复任务状态。点击“取消”才取消未完成目标，已提交的同步页保留。
5. 全部结束或存在终止失败后，可再次点击按钮发起新巡检。连接失败时任务编号已先保存，重试沿用同一创建操作，避免重复任务。

没有连接账号空间时，入口显示“巡检当前索引”，只报告当前索引的核对结果，不假称检查了其他电脑。

## 持久状态与权限

schema61 增加空间任务、逐来源目标、来源在线记录及 publisher 通知水位。目标保存设备及 grant 引用，即使 publisher 被移除也不会从任务里消失、进而被误算为成功。未绑定 publisher 的历史媒体来源明确显示“来源未绑定”，不能把零个可通知设备当作所有历史数据已经同步。

创建、读取、取消及回执使用设备证明认证的账号空间端点。回执重新核对设备、grant、space、publisher、epoch；来源 A 不能提交来源 B 的回执。撤权/角色变化以控制平面当前状态为准。普通 agent 媒体权限不能借用 GUI 的同步通知权限。

创建操作以客户端持久操作 ID 幂等；回执重试不倒退终态。取消仅影响未完成目标。暂时网络中断或限流保留目标以便续办；明确的本机数据错误或未解决认领会报告失败，不显示完成。

## 自动同步通知

GUI 使用独立、受限流的长轮询通知通道；等待不占同步写入名额。来源通知只读取自己的持久水位和任务，不枚举照片文件。媒体/分类描述变更、有关目录实体及关系提交会更新相关 publisher 的水位；无关 publisher 不收到该媒体的业务载荷。远程只读 GUI 使用空间水位刷新镜像。

连接恢复进行退避重连；心跳和在线状态不触发全目录文件枚举。长同步期间仍维持来源在线记录。来源执行完成后检查本机 SQLite，并提交逐目标结果。正常令牌轮换可重新加载同设备的已保存凭据或续期；撤权不能继续读写。

冷启动先取得通知基线，再执行已有启动同步，后续只处理较新的水位和待执行任务；首次尚无注册 publisher 时先完成注册。通知触发的远程镜像刷新不会重推旧人工日志，避免反复产生通知回声。人物元数据及分类审核/整理也补齐提交后的同步队列触发。

RPC 遇到忙碌或短暂服务故障使用有界、可取消重试，并复用已配对客户端连接。任务创建沿用同一 ID，不能因重试生成新任务。JSON/任务身份不一致不会被当作成功。
