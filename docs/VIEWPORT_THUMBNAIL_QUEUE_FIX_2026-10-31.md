# 视口缩略图优先队列与本地缓存修复

## 范围与结论

最新状态：用户随后授权部署，GUI、本机及远程 IndexService 已更新，新 GUI 已启动，详见[部署记录](VIEWPORT_DEPLOYMENT_2026-10-31.md)。下文“不替换运行 GUI”描述修复阶段的约束。

修复目录照片网格及服务浏览窗口的缩略图加载。按用户要求先完成修复，暂不继续登录，不发布版本，不替换正在运行的 GUI。

代码中已确认的缺陷：

- PhotoGrid 只取消预取，没有追踪并取消离开视口的前台下载；旧下载仍占据并发槽。
- 虚拟化会实现视口外的缓冲行，其绑定及 Loaded 事件也会把请求提升为前台。取消后通过属性通知又可能启动下载。
- 服务浏览窗口在检查磁盘缓存前等待网络并发槽；慢网络能阻塞本地已有缩略图。
- ImageItemViewModel 的远程视频缩略图只进入内存，服务浏览窗口则跳过视频缩略图。
- 无效图片文件留在缓存中反复解码失败；PhotoGrid 失败重试没有退避。
- 新增故障恢复测试进一步复现：WPF URI 解码损坏图片时可能保留文件句柄，导致缓存删除失败。两条 GUI 路径改用共享 `ThumbnailBitmapLoader` 显式管理文件流，异常时也关闭句柄。
- 滚动事件只响应偏移变化，没有响应视口及内容范围变化。服务浏览旧页面在重试等待中取消时可能使新页面没有空闲工作线程。

上述是可从调用链及受控测试确认的客户端问题，不能据此断言当前服务端没有限流、授权或媒体读取问题。当前设备重新配对尚未完成，因此真实账户网络验收留待登录之后。

## 调度与缓存行为

1. 实际可见项立即进入前台队列；无需等待鼠标停止。停止滚动 750 ms 后补齐遗漏项并开始后台工作。
2. 离开视口的未完成请求取消，释放槽位，加入暂缓集合。顺序为当前视口、相邻视口、此前暂缓项。
3. 后台并发受现有共享调度器限制；新视口能取消本窗口旧工作。相同内容的其他消费者仍在读取时，不取消其共享下载。
4. 暂缓是取消当前 HTTP 请求后重新排队，不是 HTTP Range 断点续传；未完成的 `.part` 删除，已完成缓存保留。
5. 远程照片、视频先原子写入磁盘，再解码显示；再次进入或重新创建缓存实例直接读磁盘。视频无哈希时使用负数媒体 ID，与照片隔离；有哈希时按内容共享。
6. 本地缓存命中使用独立解码队列，不占网络请求槽。解码在后台执行，显示通知回到 UI 上下文；共享解码器确保文件流关闭，不依赖 WPF URI 内部缓存。
7. 空响应不发布为缓存；解码失败的远程缓存失效后按退避重试。网络超时从实际获得下载槽时开始，不包含低优先级排队时间。
8. 保留排队、获准、源响应、写入、解码、通知和取消分段日志；新增前台与暂缓数量。日志不记录凭据、人物姓名及 AI 问题。
