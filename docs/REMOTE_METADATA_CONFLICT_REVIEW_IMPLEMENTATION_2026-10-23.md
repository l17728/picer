# 照片空间人工字段冲突审核

日期：2026-10-23。schema64 开发中，代码正在构建与测试，未发布部署。

账号远程 GUI 从“索引巡检、同步与修复 → 处理同步冲突…”读取照片空间中的待处理冲突。来源电脑默认仍处理本机冲突，可点击“照片空间冲突…”切换到服务端记录。远程列表展示“待处理修改”和“当前版本”，避免将其他来源的修改称为本机用户的修改。

新增账号接口：`POST /api/sync/v2/metadata-conflicts` 返回一致读取事务中的空间 epoch、冲突和索引对象标题；`POST /api/sync/v2/metadata-conflicts/resolve` 提交选定版本。接口要求索引读取和编辑权限，并沿用设备证明、账号重新校验和空间写入锁。

服务端复核 epoch、当前字段版本和当前操作 ID。采用待处理修改时创建新的权威字段版本；保留当前值只结束该条冲突。schema64 为冲突记录增加处理请求回执，同一请求重试不再次应用，已经处理的记录不接受改变选择的重复请求。人工处理、字段更新和回执在同一事务提交；不涉及原媒体文件操作。

此入口只覆盖已接入因果字段协议的类别，不代表模型描述、所有分类事件、目录删除或账号偏好已全部完成同步。账号级分类设置在 schema65 接入开发验证；本记录中的回执覆盖已经采用因果字段协议的来源操作，不代表所有元数据同步已完成。

新增验证覆盖权威版本递增、保留当前值、重复请求、改变已处理选择、过期 epoch、只读设备拒绝及真实 HTTPS 调用。首轮 34/34 项通过，证据为 `artifacts/sync-verification-20261023/remote-conflict-review-schema64-20261023.trx`。追加的核心同步与巡检 40/40 项、实际 WPF 窗口 5/5 项通过，证据分别为 `remote-conflict-inspection-schema64.trx` 和 `remote-conflict-inspection-ui-schema64.trx`。WPF 远程窗口使用受控 HTTP 适配器，真实 TLS 与设备证明由独立 HTTPS 集成测试验证。

全空间巡检同时返回人工字段冲突数和旧视频归属待审核数；即使来源全部回报完成，任一队列尚未处理时仍为“待审核”。关闭冲突窗口后巡检窗口立即刷新任务状态。旧令牌连接没有账号接口时，继续使用本机镜像的冲突处理入口。

来源状态收敛已通过 43/43 项回归（`conflict-resolution-roundtrip-schema64.trx`），包含真实 HTTPS 的采用与保留两条路径：服务端保存处理结果的确切字段版本；来源仅能查询本来源操作 ID 对应的处理回执。本机先合并字段数据，再在已达到该版本且不存在尚待确认的新离线修改时关闭指定冲突；旧服务不支持回执接口时保留待处理状态。回执不携带人物内容或其他来源数据。
