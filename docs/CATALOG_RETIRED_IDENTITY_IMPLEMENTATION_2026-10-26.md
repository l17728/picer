# 已删除分类身份与旧快照防护

状态：schema82、协议 10 开发中，尚未接入 HTTP 自动投递，尚未发布部署。

分类身份退出与业务行是否可删除分开判断。标签、相册或人物的关联回执齐全后，再检查该来源是否出现新的关联；有新关联时保留冲突。其他来源的身份或本机私有关系仍存在时，保留业务行。满足条件后，在事务内保存 publisher、对象类型、稳定身份和操作身份等最小退出标记；不保存名称、人物嵌入或媒体路径。

退出标记独立于目录业务行，避免业务行及字段被清除后失去防重放依据。服务端旧分类导入、照片关联、人工字段、视频人物及人物训练策略导入开始过滤已退出身份；反向字段翻译使用有效身份视图，避免新对象的编辑回传到已经退出的旧本机 ID。

协议 9 阶段回归 `catalog-retired-identity-schema81.trx` 43/43：回执不齐不收尾、范围收缩、私有引用保留、删除回滚、并发新增关系，以及旧快照在单来源和共享同名标签场景下的重放。严格构建零警告、零错误。

协议 10 已通过 `catalog-frozen-references-protocol10.trx` 45/45，覆盖每批分类引用的稳定身份封存、本机整数 ID 重用后的新生命周期绑定，以及真实 HTTPS 发布器和服务端接收回归。没有身份依据的旧格式批次，在已发生身份换代后不能继续猜测对象；重复的已提交批次仍按原回执处理。可空新增字段在序列化时省略，以保留旧批次的哈希计算兼容性。

schema82 保存新旧分类身份的继承关系。新对象因同名规范化而使用原业务行时，只有当前解除关联操作确实来自已确认退出记录，才允许新的明确添加接续该操作；真正的后续人工修改仍进入冲突。继承原本机整数 ID、但服务端已创建新业务行时，新一代的首个明确操作可以建立新字段基线。`catalog-generation-causal-schema82.trx` 50/50，包含因果请求重试、后续真实修改不能被覆盖，以及真实 HTTPS 验证私有照片保留后重新加入已同步照片、身份换代与无重复上传。

仍需完成：新生命周期的全引用身份冻结与重新绑定、空对象的网络清单、上下行最终确认、冲突审核及恢复、确认水位和压缩。当前内部执行器不作为完整双向删除能力的交付依据。
