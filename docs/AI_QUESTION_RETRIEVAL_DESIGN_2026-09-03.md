## 目标

AI 问答使用所选 VL 模型理解自然语言，但事实与媒体只能来自 Picer 本地索引。典型问题“找一张在上海去年牟穿着红色裙子爬山的照片”必须拆解为人物、地点、时间和视觉语义条件，再检索、复核和回答。

## 检索流程

```text
用户问题 +“包含视频”开关
  → VL 结构化规划（人物、行政区划、时间范围、标签、活动、颜色、自由关键词）
  → 本地硬条件召回（人工人物、GPS/行政层级、时间、媒体类型）
  → BM25/结构化软条件召回（照片描述、视频转写/摘要、场景摘要、人工/视觉标签）
  → 按媒体类型合并、去重和初排
  → VL 查看候选缩略图/关键帧与索引证据并复核排序
  → Markdown 回答 + 分组的渐进媒体结果
```

## 媒体范围

- “包含视频”默认关闭；关闭时查询与回答只包含照片。
- 开启后，视频召回使用视频人物标签、拍摄时间/GPS、语音转写、视频摘要和关键帧描述。
- 回答必须分成“照片”和“视频”两节，禁止把视频关键帧当作照片结果。
- 视频卡片显示封面或关键帧、时长、命中时间点和命中证据；点击切换到视频页并定位原视频。

## 证据优先级

1. 人工确认的人物归属、人工地点和人工标签是硬事实，不允许模型覆盖。
2. EXIF 时间、GPS 及行政区划层级是结构化事实。
3. 已接受的照片描述、场景摘要、视频转写和视频摘要是可检索证据。
4. 自动视觉标签和模型建议只用于召回与排序，回答中需标明不确定性。
5. VL 不得返回候选集合之外的照片或视频 ID，也不得猜测人物身份。

## 响应与交互

- 回答采用 Markdown 语义，包括结论、命中依据、照片、视频和不确定项。
- 媒体不以内联 base64 塞入 Markdown；照片使用现有虚拟化缩略图网格，视频使用独立虚拟化卡片。
- 照片单击选择、双击打开原图；视频点击进入视频页并定位。右键沿用对应媒体菜单。
- 每项结果保留证据说明，例如“人物：人工确认；地点：GPS→上海；时间：2025；视觉：描述命中红色裙子/爬山”。
- 新问题立即取消上一轮规划、检索、缩略图/关键帧加载和 VL 复核。

## 模型与隐私

统一 AI 模型设置新增独立功能“AI 问答与媒体检索”，默认选择本地 Qwen3-VL 8B。问题、候选元数据和缩略图/关键帧仅发送到用户选择的模型；本地模式只访问 `127.0.0.1`。未来若允许云端模型，提交前必须明确显示将发送的候选数量和数据类型。

## 实施阶段

1. 结构化查询规划器及严格 JSON schema。
2. 人物、时间、地域、标签、描述、场景和视频文本的多路召回与证据合并。
3. VL 候选复核、媒体 ID 白名单校验和 Markdown 回答。
4. 照片/视频分组呈现、可点击渐进卡片、取消/进度和缓存。
5. 建立组合查询、同名地点、相对时间、无结果、非法媒体 ID、连续提问、模型离线及混合媒体回归集。

## 语音控制与全双工对话

语音输入和键盘输入必须共用同一个 `VoiceCommandAgent`，不得让语音识别文本绕过动作校验。代理在每轮收到当前目录中的真实行政区划路径、已命名人物和可打开模块，只能返回以下白名单动作：

- `open_module`：打开目录浏览、搜索、人物、标签与相册或视频。
- `open_location`：目标必须逐字匹配当前地理目录树中的完整路径。
- `search_media`：转入上述 AI 媒体检索管线，可携带“包含视频”。
- `clarify`：目标歧义或信息不足时继续询问，并只列出真实存在的候选项。

删除、移动、训练、修改设置等写操作不能由该协议执行。切换节点只改变选择和展开状态，不重建目录树。当前实现已经提供可打断的多轮文字动作窗口和上述严格动作协议；接入麦克风时使用配置中的 Qwen3-ASR 1.7B，并保留整段转写和宽松 VAD。真正的全双工还要求中文 TTS、回声消除、播放时继续监听及用户插话时立即取消 TTS/当前代理轮次；在统一模型平台注册中文 TTS 前，不得把仅有文字回复或英文系统语音称为全双工。

回归必须覆盖：虚构地点被拒绝、同名地点澄清、国家到城市追问、连续指令取消上一轮、模型离线、ASR 空结果、用户插话以及目录树结构不变。
