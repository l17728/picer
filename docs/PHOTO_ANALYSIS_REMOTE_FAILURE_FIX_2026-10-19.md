# 远程照片描述失败定位与修复（2026-10-19）

## 现象

远程 GUI 的照片描述任务连续失败并暂停；部分缩略图显示“已删除或移动”，但来源照片没有移动或删除。

## 根因

远程模式仍允许客户端运行本地扫描/缺失检查。客户端只枚举本机路径，结果为零，并把远程镜像中的 8,603 条照片记录标为缺失。原图与 IndexService 权威索引未变；修复时根据服务端状态恢复了本地镜像状态，并禁用远程 GUI 的本地索引和缺失检查入口。

描述链路随后暴露两个独立问题：GUI 原先用镜像里的来源路径直接读取照片；切换为授权媒体流后，旧版 MediaAgent/IndexService 组合可能不支持专用分析输入端点。GUI 现使用授权原图读取作为兼容回退，在客户端缩放并去除 EXIF 后再发送给模型，不会把原图直接发给模型。

图片读取和预处理已在实际 GUI 测试中通过。之后模型请求仍收到 HTTP 503，MediaAgent 没有收到请求。原因是账户空间使用严格代理路由，而 GUI 请求没有提供来源设备 ID；IndexService 因而没有选中该空间的模型代理。

## 修复

- 远程模式禁用客户端本地目录扫描、全量/增量索引和缺失检查，避免再次误标缓存。
- 分析器支持授权媒体流，缓冲不可 seek 的 HTTP 流后解码；图像只在客户端缩放和清理元数据。
- IndexService 在账户空间内仅有一个在线 `ai.proxy` 时自动路由到它；有多个候选代理时返回明确的选择错误，不猜测设备。
- 记录不包含路径、凭据或图片内容的分段日志，区分输入、预处理和模型代理故障。

## 验证

- `CompatibleAnalyzer_UsesAuthorizedImageStreamWhenConfigured`：通过，含不可 seek 输入流。
- `StrictSpaceRoutesAiToItsOnlyEligibleProxyWhenClientHasNoAgentId`：通过，覆盖严格账户空间的 AI 代理选择。
- IndexService Release 构建：`--warnaserror`，零警告、零错误。
- 本机实测：授权原图流 1,949,911 字节成功读取、缓冲和解码；本次测试使用的生产 IndexService 在该修复部署前仍返回 HTTP 503，因此不把它记为描述成功。

## 目录照片与视频批处理复查（2026-10-19）

GUI 现场日志显示照片在进入模型前收到 `InvalidDataException`，视频预处理请求收到 `HTTP_403`。照片失败是账号空间代理转发响应时漏掉 `X-Picer-Analysis-Input` 校验头：上游已返回有效 JPEG，但 GUI 无法验证而拒绝输入。视频失败是账号空间路由权限表未覆盖 `video-probe`、`video-keyframes` 和 `video-transcribe` 服务路由，远程设备因此被拒绝。

修复为代理转发校验头，并把视频探测映射到 `media.read`、关键帧提取和转录映射到 `analysis.run`。回归测试覆盖授权方法、路由和无效 ID；三个目标测试全部通过。部署后仍需在 GUI 中重试目录描述，确认照片与视频结果均能写回照片空间。

## GUI 端到端复测与严格代理路由修复（2026-10-19）

在当前照片空间中，`115APPLE` 子目录包含 2 张照片、没有视频。第一次复测确认授权原图回退仍失败：`PhotoInputAnalyzer` 已构造本地校验副本，但其内部 IndexService 分析器随后忽略该副本，再按远程 ID 请求一次准备图。现在分析器只对 `app-data/description-input` 下的副本打开本地流；路径位于缓存目录之外时仍走授权网关读取。针对缓存范围和校验失败回退的两个 E2E 回归测试通过。

重新构建并运行 GUI 后，同一目录显示“发现完成；已处理 2/2：成功或复用 2，失败 0”。日志确认两张照片均完成预处理，IndexService 模型响应 HTTP 200。描述写回后的增量同步遇到 503；原因是变更页请求未使用网关已有的 Retry-After 重试。现在 `GetChangesAsync` 复用有界重试实现，并增加“首次 503、随后 200”的回归测试。

随后检查包含视频的较大目录任务，发现关键帧预处理连续返回 HTTP 503；这些视频请求没有抵达已连接的 MediaAgent，而同一驻留程序刚刚成功处理了照片模型请求。根因是账号空间的严格路由下，视频任务请求没有显式 agent ID；`RequestTaskAsync` 对空 ID 没有 AI 流程已有的“唯一合格代理”回退，故把空会话误报为 `media_agent_offline`。现在视频任务和流式任务只在该账号空间内恰有一个具备所需能力的在线 Agent 时自动路由；多个候选时返回明确的选择错误，不猜测。新增严格路由测试覆盖唯一 `ffmpeg.keyframes` 代理；该测试与变更页重试测试均通过。

**验证边界：**照片端到端已通过；严格代理选择和 503 重试通过自动化测试。包含视频的生产端到端验收仍需部署 IndexService 修复后，用一个视频确认关键帧与摘要成功。未对整个 Apple 照片树启动描述任务。
