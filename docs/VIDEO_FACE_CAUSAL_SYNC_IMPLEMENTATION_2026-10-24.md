# 视频人物人工决定的因果同步补齐

状态：已接入开发源码 schema72 / 协议 8，正在扩大验证，尚未发布部署。本文不能作为已发布能力说明。

schema71 已隔离同内容视频的不同来源人物决定，但视频确认/忽略仍依赖快照时间戳，人物拒绝关系没有独立网络字段，无法充分表达拒绝的撤回。本段复用照片人脸已验证的服务端字段版本、基线版本、幂等操作与冲突审核，不新增第二套同步通道。

## 字段与约束

- `video-face-state`：实体为按来源隔离的视频人脸，字段为 `state`，值含 `PersonId`、`State`、`ModelVersion`。确认、忽略、移回待分类均为显式人工操作。
- `video-face-rejection`：实体为同一视频人脸，字段为人物身份，值含 `Rejected` 和 `ModelVersion`；撤回使用 `Rejected=false`，不能通过快照缺行推断。
- 外部身份使用 `video-face` 映射，服务端按来源解析；人物身份分别翻译。模型不匹配、无有效来源或历史待核对人脸不能直接应用字段。
- 本机确认、忽略、拒绝、历史恢复、明确的人物合并和特征回填迁移，应在原业务事务内记录对应人工变化。远端应用沿用抑制标记，不能再次成为新编辑。
- 有因果人工字段时，旧快照不得覆盖它；机器建议可更新，但必须服从拒绝和忽略。来源范围关闭人物/视频同步时暂停相关字段，恢复范围后重放，不能推进成永久丢失。
- 人脸或人物的显式永久清除同时清理所属字段、回执、冲突、导入归属及拒绝关系；其他来源的独立人物决定保留。
