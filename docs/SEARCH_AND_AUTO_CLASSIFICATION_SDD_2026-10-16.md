# 检索与自动分类设计定稿（2026-10-16）

## 状态与范围

本文件记录检索与自动分类两个需求的产品/架构决策。已完成检索、视觉分类及可靠性三个专家视角的独立审阅并收敛为一致意见。本文件是设计定稿，不代表本文件提出的后续增强已经开发、测试或发布。四项暂停的 P2 验收仍保持暂停。

## 决策摘要

1. 不引入 Elasticsearch、Milvus 等常驻重型服务。继续以本机 SQLite FTS5 倒排索引和 BM25 作为文字检索的默认实现。
2. VLM 描述继续提供可解释的文本检索材料。Chinese-CLIP 保持本地、独立、可选的图文语义召回；只有固定数据集评测证明有收益后，才考虑将其与 BM25 用 RRF 合并。不得直接相加 BM25 与余弦分数。
3. 自动分类要减少用户整理工作，但“分类结果必然正确”不能作为视觉模型的技术保证。采用分层结果、按类别校准、低证据拒绝分类、用户纠正及可撤销机制，以高精确率和可理解的覆盖率建立可靠体验。
4. 人工确认的人物身份和标签是权威数据。模型不得静默覆盖用户确认或拒绝；原始照片始终保持只读。

## 现状审计

### 文本检索和 VLM 描述

- `media_text_documents` 保存照片/视频可检索文本，SQLite FTS5 维护倒排索引；`media_text_rank_fts` 对归一化词项执行 BM25 排序。SQLite 官方文档确认 FTS5 维护“词项到文档及其位置”的映射，并内建 BM25；其 BM25 值越小越相关。
- `ChineseSearchTokens` 当前版本 `han-bigram-v1` 对中文使用单字与相邻双字，对拉丁字母/数字使用连续词项。这是字符切分，不是词典分词，也不提供同义词或语义理解。
- 云端视觉分析完成后，摘要、场景、活动、物体和搜索词会进入文本索引；`MediaTextRanking` 把 BM25 结果用于 AI 媒体问答候选召回。该流程由程序施加结构化条件，再由模型对候选复核。
- 当前媒体文本多数合并在单一 `content` 字段；因此尚不能按描述、人工标签、路径等字段分别加权。路径/GPS 等元数据与视觉描述混在同一文字召回中，也需要在后续评测中确认是否干扰语义排序。
- 本地 Florence 的输出保存在建议结果表中，接受后进入主搜索；它不能与已经自动进入云端视觉描述索引的内容混为一谈。

### CLIP 与视觉分类

- Chinese-CLIP 已能本地生成照片向量并保存在 SQLite，可独立执行文本到图片的语义搜索；目前没有与 BM25 或 AI 问答自动融合。当前搜索逐条读取该模型版本的向量并计算相似度，是线性扫描，不是 ANN 索引；覆盖照片，不覆盖视频语义向量。
- Picer 已有结构化筛选、人工标签、视觉概念建议/接受、Florence 建议审阅以及人物确认流程。人脸建议引擎不自动确认身份。
- 需注意现有部分视觉概念虽然状态为 `suggested`，仍参与概念筛选；UI、索引和状态语义必须一致，避免把建议显示成已经确认的事实。

## 检索设计

### 默认路径

默认维持单机、离线优先的 SQLite 架构。FTS5/BM25 负责描述、标签及其他文字中的词项召回；时间、人物、媒体类型、位置范围、文件状态等明确条件继续由参数化 SQL 作为结构化过滤。模型只能解释已经召回并经程序约束的候选，不能解除硬条件或创造人物身份。

当前单字段全文索引足以支持现有基线，不为引入复杂基础设施而重写。若标注查询集证明字段混合导致排序问题，再把描述、确认标签、元数据等拆为 FTS5 列并使用 FTS5 的列权重；通过 SQLite migration 和可重建投影维护，不能把派生 FTS 内容当成唯一数据源。

### 可选的混合召回

当产品确实需要处理“表述不同但视觉意思相近”的照片查询时，增加一个明确启用/可观测的第二路召回：

1. BM25 返回文字候选及名次。
2. 当前版本 Chinese-CLIP 返回图像语义候选及名次。
3. 先应用访问权限、用户明确选择的地图范围/精确坐标、明确人物/媒体类型和媒体状态等硬过滤，再按稳定媒体/内容身份去重。用户给出的绝对日期/范围或可依据明确参考时间无歧义规范化的日期表达（如“2024年5月1日至3日”“去年”）作为硬条件；模糊的季节、节日或无法可靠规范化的时间表达只作候选提示，并保留文字检索回退，不能由 RRF 悄悄变成硬过滤或放宽明确条件。AI 解析出的地点名称也只是候选提示，除非用户明确选择/确认地点筛选；问答结果应说明实际采用的是硬条件还是软地点提示。
4. 使用 RRF 按各路名次融合，初始常数可从 `k=60` 做实验；不直接相加原始 BM25 与余弦分数，不把相似度解释为概率或正确率。
5. 显示结果来源或匹配依据；向量索引未构建、模型不可用或取消时，退回现有 BM25/结构化路径，不阻断核心搜索，并说明语义覆盖范围。

先以影子评测比较 BM25-only、CLIP-only 和融合结果，再决定是否让混合候选进入 AI 问答。精确姓名、可无歧义规范化的日期、用户显式地图范围及否定/关系查询仍须依赖结构化条件、人工确认数据和文字证据；CLIP 不能覆盖这些约束。模糊时间或自然语言解析出的地点若不是用户显式确认的筛选条件，只能作为候选线索。视频暂不宣称由 CLIP 语义召回覆盖。

CLIP 当前全量向量扫描的扩展性需实测。先分块读取、流式 Top-K、减少每条向量的临时分配，并在批次间响应取消，以降低峰值内存并保证 UI 可取消；并发评分不能作为默认优化，只有基准确认 CPU 是瓶颈后才测试有界并发。索引构建进度和单次查询状态分别呈现。只有基准数据显示实际瓶颈后，才评估轻量 ANN。此证据不支持预先增加 ES/Milvus。

### 检索验收

建立按查询类型分层、媒体按事件/连拍/近重复隔离的固定标注集，至少覆盖精确词项、同义改写、宽泛场景、人物/时间/地点硬条件、否定/组合查询、无描述照片和视频。报告 Recall@20/50、Precision@10/20、nDCG@10、MRR、空结果率、p50/p95 延迟、CLIP 索引覆盖率、降级结果，以及融合新召回中的相关/误召比例。硬过滤违规必须为零。训练、调阈值和最终评测数据分离；CLIP 独立相关性标注默认仅本地保存，不上传查询、向量或原图。

评测方案在观察结果前登记主要指标、最小实际改善幅度和首屏精确率非劣界值；在相同的 photo-only 测试子集、相同查询、相同硬过滤条件下比较 BM25-only、CLIP-only 和融合。按查询类别报告，以 query 为重采样单位计算 bootstrap 置信区间；最小样本量及区间覆盖标准须在评测启动前冻结。视频单独报告，不混入 CLIP 的照片融合结果。

只有融合方案对预先登记的主要指标达到统计和实际意义上的改善，且首屏精确率没有越过预登记非劣界值、硬约束违规为零，才将其作为默认路径。没有达到门槛时保留为可选功能或不启用。交付前还须冻结代表性硬件、照片库规模、搜索与建索引 p50/p95 SLO；未达到 SLO 时不得默认开启融合，应保留 BM25 路径并报告覆盖状态。

## 自动分类设计

### 为什么不能承诺模型分类必然正确

日期、图像尺寸、相机型号等来自文件元数据的规则分类，通常可以说明其数据来源；但“海边”“旅行”“宠物”“某个人”等由像素推断的语义类别属于开放集合、多标签判断，边界会重叠，图片可能模糊、遮挡或超出训练分布。即使模型输出高分，也不等于该分数已经校准成真实正确概率。

行业产品提供自动识别和整理，但也保留纠正能力。Google Photos 官方帮助说明 Face Groups 建议并不完美，并支持 Same / Different / Not sure、移除错误结果及反馈。因此，用户需要的自动化目标应定义为“常见明确内容省事且可信”，而不是宣称每个机器推断都没有误报。

### 分类层级与状态

| 类别 | 示例 | 自动处理与显示 |
|---|---|---|
| 可核验元数据 | 拍摄时间、分辨率、文件类型、EXIF 中记录的 GPS/设备 | 可自动建立筛选/归档视图；显示来源。GPS 记录只证明文件含坐标，不自动证明地点名称正确。 |
| 机器语义推断 | 场景、物体、活动、风格、宠物等 | 后台自动产生多标签候选；对经过独立数据集验证、达到该类别高精度门槛的标签可展示为“自动归类（机器结果）”，明确可纠正，并与“用户已确认”视觉区分。低置信、类别冲突或未覆盖样本留在建议/未分类，不强行归类。 |
| 人工确认数据 | 用户添加/确认的标签、确认的人物身份 | 作为权威结果参与对应筛选和问答；模型重跑不得覆盖。错误只能由明确用户操作更改。 |

“自动归类（机器结果）”保留 `source=machine`、模型/提示版本、类别、源媒体身份、生成时间及复核/纠正状态；它与 `user_confirmed` 分开存储和显示。现有 `suggested` 概念不应被 UI 误称为已确认；搜索是否纳入机器建议需由明确产品策略决定，并让用户能关闭/排除建议。用户撤销/纠正机器归类时，只撤销对应机器来源记录及其搜索投影/问答候选，不触碰同标签的独立人工确认或其他来源；人工确认结果只由用户明确修改。被用户拒绝的类别要持久化抑制，避免后台任务或换模型后复活。机器结果与其 FTS 投影通过事务同步，投影损坏时可从来源记录重建。人工确认和明确拒绝都优先于后续模型输出。

分类采用多标签而不是强制单选；为不支持/无法判断的内容保留“未分类”。低置信时不显示假精确的百分比；状态统一使用“自动归类（机器结果）”“建议/待确认”“未确定”等术语，且这些都不等于“用户已确认”。提供简洁的纠正、忽略及批量确认入口。自动分类任务在后台增量运行，不阻塞浏览、搜索或导入；索引失败可重试，原图和既有用户元数据不受影响。

### 可信度门禁

每个自动发布的类别分别建立人工标注验证集和阈值，不以总体准确率或模型内部 confidence 替代。实现前为每类登记可接受误归上限、独立验收样本最低数量、置信区间判据和覆盖率下限；阈值校准集与最终验收集严格分离，按事件/连拍/近重复分组，避免同场景泄漏。门禁报告至少包括 precision、recall、覆盖率/拒识率、每类混淆、错误类型和置信区间，并按光线、遮挡、多人、模糊、设备来源等分层。用户能看到自动分类只覆盖达到门槛的样本；阈值提升而覆盖降低是预期取舍。

验收前先确定每类允许的误归上限。只有当冻结的独立样本达到预登记最小规模，且 precision 置信区间满足该类别门槛时，才能展示为自动归类；否则只作为建议，不得自动写成用户确认分类。人物身份、敏感语义和可能影响训练的数据始终沿用更严格的人工作业边界；普通场景标签也必须可撤销。任何分类都不移动、删除或修改原始媒体。

## 分阶段交付

1. **设计基线（本文件）**：确认不引入 ES；明确检索与分类状态语义、质量指标和边界。
2. **审计一致性**：核对机器建议参与搜索的实际 UI 标注；确保接受、拒绝、重跑和模型升级遵守人工确认/拒绝优先级。该阶段不改变任何照片。
3. **离线评估**：建立检索查询集和自动分类标注集；报告当前版本基线和按类别误归/覆盖率。未达门槛的类别继续以建议呈现。
4. **有限实现**：先修正建议/已确认状态混用和纠错持久性，再做可选 BM25+CLIP RRF；通过测试、性能及隐私审查后决定是否发布。
5. **默认启用门槛**：只对达到预先确定类别精度门槛的分类打开自动展示；只对查询集证明收益且满足已冻结硬件/库规模 SLO 的混合检索打开默认融合。没有证据就保持可选/建议状态。

本设计没有授权改动生产照片空间、删除索引、上传私有照片或启用云端模型。任何未来云端分析仍服从现有独立授权和用户 opt-in。

## 专家审阅共识

| 审阅视角 | 结论 |
|---|---|
| 检索与信息检索 | FTS5/BM25 对个人本地库是合适的轻量基线；CLIP 已存在但与 BM25/问答隔离。若融合，排名融合优于原始分数相加，硬约束不可被软召回削弱。 |
| 视觉分类与产品体验 | 自动化目标合理，但语义分类必须容许拒识和纠错；元数据事实、机器推断、用户确认需分层。行业产品也提供修正错误分组的路径。 |
| 健壮性、隐私与性能 | 本地服务边界、索引可重建、降级和可撤销应优先；CLIP 当前线性扫描须按真实规模测量；不把向量分数当置信概率，不上传本地评估数据。 |

**一致决定**：保留本地 FTS5/BM25；不引入重型搜索服务；CLIP 融合先评测后实施；自动分类以高精度、可拒识、可纠正为目标，不承诺零误差。实现评审必须核对 `suggested` 与 `accepted/user_confirmed` 对搜索及用户训练的影响。
