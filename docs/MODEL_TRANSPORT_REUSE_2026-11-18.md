# 模型传输复用与常驻推理记录（2026-11-18）

## 结论

模型侧已经按进程生命周期复用服务实例。`Picer.MediaAgent` 使用一个长期存活的 `HttpClient`，`Picer.ModelServer` 使用单例 `ModelInferenceRelay`，CLIP 使用单例 `InferenceSession`。请求处理只创建请求体和响应流，不会重新加载模型。

本次将两端的 HTTP 连接池参数显式收敛为：有限连接并发、10 分钟连接生命周期、2 分钟空闲保活回收、10 秒连接建立超时。连接池会复用现有 TCP/TLS 通道，服务进程不会因为单个请求反复初始化。

## 并发边界

模型推理入口继续使用共享 admission 队列和并发闸门（默认同时推理 2 个、最多排队 8 个）。排队不会阻塞 UI 数据库闸门；目录描述的远程请求可以并行进入模型服务，但不会无限制打满模型进程。

## 观测结果

2026-11-18 的目录描述日志中，两个 AI 请求能够重叠执行；响应头耗时约 8.7–12.9 秒，响应体传输约 0.1 秒。当前主要热点是模型推理本身，连接建立和 UI 数据库等待已从路径中移除。进一步缩短单张耗时需要模型运行时、GPU 或上游模型端点提供更快推理/批处理能力，单纯重新创建客户端不能改善。
