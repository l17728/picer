# 远程缩略图限流修复（2026-10-15）

## 问题

远程照片空间打开后，索引记录可以正常返回，但缩略图请求出现 HTTP 429/503。失败的可见缩略图会在预读循环中立即重新排队，持续重复请求；每个 GUI 原有最多并发 4 个可见缩略图，而设备授权网关对索引类请求实施并发准入限制。驻留 MediaAgent 日志显示原图读取、解码和预览生成成功，因此故障不是照片缺失或驻留程序离线。

## 修复

- 远程图库的缩略图并发从 4 降到 2，为索引同步和其他前台请求保留服务容量。
- 对每张失败缩略图增加独立指数退避：首次等待 5 秒，逐步增加，最长 60 秒；成功后重置。预读 worker 在冷却期结束后再尝试，不再形成每秒重试循环。
- 缩略图缓存成功后仍按内容身份持久复用，不改变原图、索引记录或照片空间内容。

## 验证

- `ThumbnailRetryTrackerTests`：2 项通过。
- `dotnet build src/Picer.App/Picer.App.csproj -c Release -r win-x64 --no-restore --warnaserror`：零警告、零错误。
- 更新本机安装目录的 `Picer.App.dll` 和 `Picer.Core.dll` 后重新启动 GUI；运行日志确认首批 200 条图片记录已加载，驻留程序持续生成预览。更新后的观察窗口内没有新的缩略图 429/503 或缩略图失败日志，缓存开始增长。

## 限制

首次从 MediaAgent 生成远程缩略图仍受源端读取、解码和网络速度影响；未缓存图片会随可见区域逐步填充。索引条目和原始照片均未被重建或修改。
