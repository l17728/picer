# 删除关系的事务执行与回执

状态：schema79 开发中，尚未接入生产网络流程。

本阶段实现照片标签/相册、视频标签及照片/视频人物关联执行器。执行前以 publisher、目录对象和媒体的稳定身份解析本端 ID，并核对当前照片/视频/人物范围、根目录范围，以及服务端来源绑定。请求携带的整数来源 ID 不作为授权依据。即使重复请求已有回执，也先重新验证当前范围。

已有关系的删除依据缺失或指纹变化时，保留关系并记录 `baseline_required` 或 `conflict`；已解除的关联可幂等确认。关系更新、人工字段和幂等回执使用同一调用方事务，写回执失败必须一并回滚。相同操作身份改变载荷不能再次执行。来源端应用产生的字段标记为已导入，避免作为新人工编辑上传。

执行器只解除授权关系，不删除原始媒体或整个目录对象；其他来源或未选择目录仍有引用时保留。视频标签与人脸按内容和 owner 共享，因此修改前额外核对同内容同 owner 的全部引用；存在范围外或未映射引用时记录 `scope_conflict`，不扩大授权。其他 owner 的同内容视频不受影响。显式清除媒体索引后，对应执行回执也清除。

后续仍须补齐：目录对象生命周期收尾、防旧快照复活、上下行投递、用户冲突选择、确认与保留水位。当前实现不能作为“所有删除已双向同步”的交付声明。

初始照片/基线专项 `catalog-retirement-application-initial-schema79.trx` 18/18，覆盖双向数据库身份解析、授权收缩后的重复请求、载荷变更拒绝、并发编辑保留、回执故障回滚与媒体索引清除。追加视频同内容跨 owner、部分范围、人物清除后保留其他来源等回归 36/36；服务端接收专项 27/27；分页投递与确认回执回归 `catalog-retirement-delivery-regression-schema79.trx` 70/70。随后 v2 操作身份校验回归 `catalog-fingerprint-v2-schema79.trx` 73/73。批次有重叠，未作独立数量相加。

服务端接收、分页读取和确认回执方法已实现，但 HTTP 路由和自动发送尚未启用。范围恢复后可重试 `scope_conflict`；确认成功的记录不重复进入投递队列，重复确认不增长通知序列，迟到的冲突响应不能覆盖成功确认。
