# 删除同步的关系基线

状态：开发中，schema78；网络投递和冲突审核尚未交付，不代表双向删除已完成。

标签、相册、人物删除或合并前，将已授权媒体关系的人工操作身份摘要与删除记录在同一事务提交。摘要不使用两端不同的 SQLite ID、不使用客户端时间，也不因服务端分配版本而改变。人物关系暂采用保守检查：同一媒体的其他人脸人工状态变化也会改变摘要，后续接收时宁可进入审核，不静默覆盖新操作。

摘要只保存 SHA-256，不保存人物姓名、别名、嵌入或路径。媒体索引明确清除时，基线随对应关系记录级联清除；操作失败则随业务事务回滚。每次读取捕获对象最多 400 条，尚未将此机制接入网络发送。

schema77 历史删除记录已丢失删除前字段，因此升级不自动补造摘要，读取返回缺失依据。后续协议必须将它交给明确的恢复/审核流程，不能把空值解释为“没有并发修改”。

schema79 的 v2 摘要将来源端尚未收到回执的本地操作转换到对应 publisher 的服务端操作身份后，再去重和排序。已确认或已导入操作保持原身份，因此上传回执前后可比较，真实重新编辑仍会改变摘要。旧 v1 摘要不能授权自动删除已有关系，必须保留并审核。

初始专项 `catalog-retirement-baseline-initial-schema78.trx` 11/11。随后限制基线只从本次新建的删除记录捕获，并按关系类型拆分索引查询；`catalog-retirement-baseline-hardened-schema78.trx` 63/63，包含两端整数 ID 不同、版本晋升、删除后重新添加同值、事务回滚、人物合并前捕获、媒体清除、旧库升级缺失依据，以及数据库迁移/视频归属/服务端接收回归。尚非整仓验收。

v2 追加验证：`catalog-fingerprint-v2-schema79.trx` 73/73，覆盖来源原操作身份与服务端命名空间身份、回执前后、真实新编辑、旧 v1 保守处理，以及关联执行、服务端范围与视频因果字段。各批次存在重叠，不合计为独立测试数量。
