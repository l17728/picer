# 剩余代码复查与修复（2026-10-09）

本轮承接已完成的[四项代码补齐](REMAINING_CODE_IMPLEMENTATION_2026-10-09.md)，复查功能之间的衔接。此前暂停的人脸质量、人工 ASR 对照、真人 AEC3、低显存四项 P2 验收继续暂停。

## 确认的问题

- 同一视频帧的多个模型人脸通过镜像同步时，插入阶段使用默认模型，可能撞唯一键；需要在首次写入时绑定真实模型空间。
- 视频副本共享内容后，人工标签/概念编辑仍按路径引用重放，旧事件可能覆盖另一引用的较新操作，或在文件换内容后作用于新内容；需要持久绑定内容身份并按内容字段决胜。
- 视频换内容后，远端抽帧可能混入旧帧；海报缓存只检查 ID 或修改时间，无法区分同大小、同时间的新内容。
- 手动清除索引可能漏掉旧引用的本机缓存；本地与远端同号 ID 的缓存应隔离。批量清除中途失败后，界面也应立即反映已成功项。
- 进程崩溃留下的扫描临时清单不参与普通清理，可能继续保留路径和哈希；在跨进程锁内按应用临时文件命名精确清理。
- 单视频摘要入口未传入配置的预算和位置策略；摘要服务也未检查启用/数量限制，且无条件拼入精确 GPS。
- 照片描述的内容锁原先属于服务实例；不同窗口的服务实例同时描述相同内容时，可能重复请求和计费。现在同一进程、同一图库按内容协调，取消等待不会阻塞后续任务，空闲后不保留内容锁键；不同内容仍可并发。

## 摘要请求策略

视频描述在预处理前检查启用状态和本次数量限制。精确 GPS 只有显式允许时进入模型上下文；单视频入口与目录入口使用相同的运行策略。预算预留失败时不调用模型，也不留下费用流水或预留。

新增测试覆盖禁用、零/负数量限制、精确 GPS 允许/拒绝，以及零预算阻止模型调用。单视频操作固定开始时的目标视频，等待期间切换选择不会把旧视频摘要写到新详情。

## 视频镜像与人工编辑

视频人脸插入时原子写入模型及向量；不同模型不混用向量，同模型的精简同步响应保留原有向量。

schema 45 新增编辑内容身份和首次操作绑定。完整有效 SHA-256 用作跨库身份；没有可靠哈希的编辑仅绑定本库 epoch 和内容 ID，补齐哈希后再升级身份。标签和概念按内容字段选取更新时间、操作 ID 决定的胜出事件，导出和同步确认使用一致的胜出操作。

删除或替换引用前，仍有副本的内容编辑移交到剩余引用；最后引用清除时删除相关编辑和首次绑定。迟到的旧内容事件不会占用新内容的编辑位置，已经见过的缺引用操作也不会在以后复用数字 ID 时重新绑定。详见[视频元数据一致性修复](VIDEO_METADATA_IDENTITY_FIX_2026-10-09.md)。

操作绑定清理同时匹配当前引用及内容身份：即使历史绑定仍指向已经换内容的原引用，也会随旧内容的最后引用清除；还有副本时统一转给存活引用，并保留新内容的编辑及绑定。

客户端与服务端需一起升级才能获得完整语义；旧服务虽能忽略新增 JSON 字段，但不具备内容身份保护。

没有可靠哈希的视频人工编辑暂留本库，不以本地身份发送到另一图库。接收方也不会固化无法解析的外库本地身份；原库补齐 SHA 后，同一操作可正常同步。已经验证的 SHA 绑定保持不可改绑，不能借“升级身份”把旧操作套到另一内容上。

## 缓存内容身份

本地海报采用实际内容哈希；为避免每次显示都重读整个视频，保留最多 128 条可信 NTFS 文件身份缓存。缓存复用同时验证文件句柄的卷、文件 ID、变更时间和长度，不能只凭可恢复的修改时间认定未变。无法取得可信签名时重新校验内容。显式清除会失效相应缓存并阻止在途哈希重新填回。

关键帧按内容及生成批次分目录保存，不原地覆盖此前共享帧。远端旧记录缺少可信哈希时不复用旧海报；有内容哈希的记录可复用。新增测试覆盖同大小、同修改时间替换，以及取消/失败后的临时缓存清理。

## 清除与故障恢复

本地与远端镜像按各自缓存范围清理，同号 ID 不再互删缓存。删除非末引用也清理其独立下载、海报和失败暂存；仍由其他内容使用的帧通过数据库引用保护。源端独立抽帧批次原子发布，长视频换成短视频后不会把上次剩余帧混入本次结果。

批量清除每完成一项就更新界面；后续项失败时只保留未完成项供重试。扫描清单加载、保存和清除都会在同一跨进程锁下移除精确命名的崩溃临时文件，不删除无关临时文件。
