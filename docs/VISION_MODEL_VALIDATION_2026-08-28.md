## 结论

- **YuNet 人脸检测：通过。** 可在当前最低配置机器上使用 CPU 后台批处理。
- **SFace 特征提取：基础推理通过。** 已为每张检测到的人脸生成 128 维特征；正式集成前仍需补做人脸关键点对齐、同人/异人阈值标定。
- **Florence-2-base 图片描述：8 GB CPU 实测通过。** FP32工作集约1.41 GB，缓存后每张约8–9秒，适合独立后台索引，不适合阻塞式交互。目标16 GB环境仍需比较FP16/INT8 ONNX与INT4权重量化候选。
- **CLIP ViT-B/32：保留为下一阶段候选。** 用于“夏天、裙子、山上”等开放词义检索；正式接入前需完成 ONNX 转换产物校验、中文查询模板和召回率测试。

## 产品集成约束

1. 人脸分析必须在后台低优先级队列运行，不能占用缩略图和搜索 UI 线程。
2. 缓存键使用 `文件稳定标识 + 文件大小 + 最后写入时间 + 模型版本`；模型版本不变时，重建索引不得重复推理。
3. 数据库只保存人脸框、关键点、128 维向量、聚类编号和用户名称；不修改、不移动、不删除原图。
4. 首次命名由用户确认；自动聚类只能提示“可能是同一人”，不能擅自把陌生人命名为家庭成员。
5. 图片描述模型必须使用独立进程，并设置内存、并发和取消限制；模型失败不能导致 GUI 黑屏。16 GB 环境默认并发数仍为 1。
6. 内存预算建议：GUI 与缩略图缓存不超过 2 GB；基础索引、人脸任务不超过 2 GB；图片描述工作进程软上限 6 GB；至少为系统保留 4 GB。
7. 2 GB 显存作为可选加速资源，而不是最低运行条件。启动时实测 DirectML 模型加载和一次推理；失败、超时或显存不足立即回退 CPU。
8. GPU 推理固定 batch=1、固定输入尺寸、单会话串行执行；保留一部分显存给桌面合成，不能把 2 GB 全部作为模型预算。
9. 量化按模型选择：YuNet/SFace 保持现有小模型；CLIP 优先比较 FP16 与 INT8；Florence-2 比较 FP16、INT8 和 INT4 权重量化的准确率、内存与耗时。
10. ONNX Runtime 的 INT4 是针对部分 `MatMul`/`Gather` 的分块权重量化，并不代表所有算子和激活都变为 4 位。INT4 会涉及 opset 21，而当前 DirectML 文档仅支持到 opset 20，因此 INT4 默认走 CPU，不能假设可由这块 GPU 加速。

## 仍需完成的验证

- 程序“人物 → 人脸精度验证”已提供 SFace 阈值标定与 YuNet 漏检评估 UI；SFace 推荐阈值可按模型版本确认应用并由人物自动匹配读取，人工确认、场景标签和 YuNet 真值会持久化。以下项目可直接在 UI 中执行和查看进度。

- 选取至少 5 位家庭成员、每人 20 张跨年龄/角度照片，标定 SFace 同人阈值和误识率。
- 在 500–1000 张照片上测 YuNet 漏检率，包括侧脸、儿童、合影、弱光和旧照片。
- 将 CLIP 固化为可再分发的 ONNX 产物，测中文复合查询 Top-20 召回率。
- 内存升级到 16 GB 后，在隔离进程中对 Florence-2 的 FP16/INT8/INT4 候选各做 50 张描述质量、峰值内存和耗时测试，再决定最终格式；默认仍按需下载。
- 对 GTX 750 Ti 2 GB 做 DirectML 探测，分别记录模型加载成功率、首张/热态耗时、GPU 专用内存峰值及 CPU 回退节点比例。
