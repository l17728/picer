# 启动账户恢复与分类现场修复

## 已确认原因

此前部署检查只确认了窗口存在和进程响应，没有区分初始化错误弹窗与图库主窗口。现场 `crash.log` 显示 10:30:31 的启动在 `AppPaths.LoadIndexBackend` 因未配对会话失败，不能将其认定为图库启动成功。

修复启动流程：账户模式缺少会话或设备凭据不可读时，先显示可恢复的连接窗口，不初始化本地索引、不默默切换模式、不清除原凭据；取消正常退出。完成连接后才继续初始化服务和图库。

用户随后明确授权后台完成连接。使用本机 DPAPI 保护的已保存账户凭据，经已有证书固定校验、正常 HTTPS 登录、CSRF 校验、设备指纹核对和原空间核对，批准并兑换本机 GUI 的授权。认证文件仅在内存中流转，没有要求用户下载、导入，没有绕过服务权限或改写账户数据库。临时网页登录会话已退出。

## 分类现场追加修复

1. 未配置分类模型、没有最新任务时，现有服务 `Results.Ok(null)` 返回 HTTP 200 空正文。客户端此前只把 204 视为可选资源不存在，导致 JSON 解析失败。现在 configuration、jobs/latest、clusters/latest 同时接受 200 空正文、204 和 JSON null；其他必需响应及损坏 JSON 仍报错。
2. 分类结果可正常读取，但保存本地副本绕过 GUI 数据库队列，和启动索引同步抢写 SQLite，30 秒后报 Error 5。分类副本、修改队列、回执及本地分类操作改为复用 `UiWork.RunDatabaseAsync`；等待支持取消，读取继续使用独立快照。没有把网络请求放进数据库队列。
3. 窗口区分正在读取、结果已显示但缓存同步中、完成加载三种状态，并记录安全异常类型，避免仅凭窗口存在就判断成功。
