# 人工标注驱动的人脸学习路线

版本：1.0  
状态：后续开发基线  
更新时间：2026-09-03

## 1. 目标与边界

用户在人物、候选人物和视频人物界面完成的“是 / 不是 / 移动到人物 / 新建人物”标注，应持续改善后续推荐和自动归类，同时保持可解释、可评测、可回滚。

当前实现优化的是 SFace 向量之上的决策层，并没有训练或修改 YuNet、SFace 模型权重：

- 每个人物最多维护 8 个外观原型，覆盖不同时间、姿态和成像质量。
- “不是此人”和移动纠错形成困难负样本，用于抑制相似人物误归类。
- 样本充足时按人物计算自适应边界，并结合检测质量、脸部相对面积和第一/第二候选差距控制建议。
- 用户确认结果始终高于模型建议；更新自动归类只更新建议，不覆盖人工归属。
- 过期建议会被清理，候选组支持批量审阅，进度与统计可见。

这套能力是可用基线，但不能称为“训练了新的人脸模型”。后续开发必须先建立可靠评测，再考虑轻量训练或替换底层模型。

## 2. 不可破坏的产品规则

1. 人工确认是事实来源，任何重算、升级和回滚均不得覆盖。
2. 自动处理只生成或撤销建议，不得自行确认身份。
3. 照片与视频共享人物身份、正负样本和决策策略；各业务页面按自己的展示逻辑即时刷新。
4. 同一原图的多种缩略图、关键帧衍生物和重复文件不得跨训练集与验证集泄漏。
5. 时间、地点、相册、场景和共同出现人物只能参与候选排序，不得单独作为身份确认依据。
6. 所有学习、评测和推理默认在本地进行，不记录人物姓名、向量或人脸裁剪到日志。
7. 长任务必须后台运行、可取消、显示阶段与进度；切换页面不得等待模型任务。

## 3. 后续任务

### FACE-EVAL-001（P0）：冻结训练集与验证集

建立版本化数据快照，避免一批样本既参与调参又参与验收。

- 只使用人工确认的正样本和明确拒绝的负样本。
- 按内容身份分组切分：相同 SHA-256、同一原图的人脸衍生物必须在同一侧。
- 同一视频的全部关键帧必须在同一侧；连拍和近重复照片按时间窗口与感知哈希归组后再切分。
- 按人物分层；样本不足的人物仅参与学习，不计入正式验证，并在报告中标明。
- 快照保存成员、标签版本、模型版本、特征版本、切分种子和创建时间，结果可复现。

验收：重复运行得到相同切分；零内容泄漏；可以追溯任一指标对应的快照与样本集合。

### FACE-EVAL-002（P0）：新旧标准影子评测与应用门禁

候选策略先只读运行，与当前生效策略在同一冻结验证集上比较，用户查看报告后才可应用。

必须报告：检测召回率、身份宏平均精确率/召回率、错误接受率、错误拒绝率、未知拒识率、候选组纯度，以及按侧脸、小脸、弱光、合影、儿童和旧照片拆分的指标。

默认门禁可由设置调整，但首版采用：

- 高置信建议精确率不低于 99%。
- 错误接受率相对当前版本不得增加超过 0.1 个百分点。
- 宏平均召回率不得下降超过 1 个百分点。
- 任一重点困难分组显著退化时阻止自动应用，并展示退化项。

应用只切换版本化决策策略。保留上一版本的一键回滚能力，不删除特征、不重写人工标注。

### FACE-REPORT-001（P1）：人物学习报告

为每个已命名人物展示：

- 正样本、负样本、自动建议和人工确认数量。
- 原型数量及其时间段、姿态和质量覆盖，不展示未经用户输入的敏感属性推断。
- 当前自适应阈值、最易混淆人物、被拒绝原因分布。
- 样本不足、覆盖单一或困难负样本不足等风险提示。
- 从报告直接进入对应待审阅样本，但报告本身不改变归属。

### FACE-EVAL-004（P1）：跨基模评测矩阵

统一模型平台可为每种人脸算法选择独立向量模型和不可变快照，在同一指标门禁下生成可复现比较结果；禁止混用不同向量空间，失败算法不得自动推荐。

### FACE-DETECT-001（P1）：提升 YuNet 漏检召回

在现有快速检测后增加受控的多尺度或分块兜底，只对低检测数、合影或疑似小脸图片启用。重点覆盖侧脸、小脸、背光、弱光、儿童、旧照片和大合影。

验收同时约束召回、误检、单图 p50/p95 延迟和峰值内存。前台可见缩略图优先，兜底扫描低优先级、可取消，结果沿用版本化缓存。

### FACE-CONTEXT-001（P1）：辅助证据排序

使用时间接近度、地点、相册、场景和共同出现人物调整候选顺序。UI 必须说明哪些证据影响了推荐；仅靠上下文不得跨过身份确认门槛。上下文缺失或冲突时回退到纯人脸向量结果。

### FACE-ADAPTER-001（P2）：轻量度量适配器

评测体系稳定且人工样本充足后，优先训练冻结 SFace 主干之上的本地轻量适配器或校准器，而不是直接微调整个模型。

- 使用对比/三元组目标和困难负样本；训练集、验证集严格隔离。
- 训练产物包含数据快照、基础模型、参数、指标和哈希版本。
- 新产物先通过影子评测门禁，再由用户应用。
- 训练失败、断电或指标退化不影响当前策略，可立即回滚。

### FACE-MODEL-001（P3）：底层模型评审

只有轻量适配器仍无法达到目标时，才评估替换或微调人脸特征模型。评审必须比较授权、包体、CPU/DirectML 延迟、内存、检测召回、身份误归率、量化影响和迁移成本；不得仅凭单一公开榜单更换模型。

## 4. 数据与服务设计

建议新增以下版本化实体，实施时通过正常数据库迁移建立，不在读取旧库时隐式重建目录或索引：

| 实体 | 用途 |
|---|---|
| `face_dataset_snapshots` | 冻结样本集合、切分规则和随机种子 |
| `face_dataset_members` | 样本、人物、正负标签、分区和防泄漏组 |
| `face_evaluation_runs` | 候选策略、模型版本、运行状态与错误 |
| `face_evaluation_metrics` | 总体、人物级和困难分组指标 |
| `face_policy_versions` | 阈值、原型、适配器引用、生效状态和回滚链 |
| `face_person_learning_stats` | 人物覆盖度、混淆与样本健康度缓存 |

核心对象建议为 `FaceTrainingSnapshot`、`FaceEvaluationRun`、`FaceDecisionPolicy` 和 `FaceModelArtifact`。所有后台服务接受 `CancellationToken`，进度以“准备快照 / 提取特征 / 训练候选 / 影子评测 / 等待应用”阶段上报。

## 5. 标准工作流

```text
人工标注
   ↓
增量更新正负样本与建议（当前能力）
   ↓
冻结训练/验证快照
   ↓
生成候选策略或适配器
   ↓
在冻结验证集影子评测
   ↓
门禁通过 + 用户明确应用
   ↓
仅重算自动建议 ── 可回滚到上一策略
```

新照片和视频入库继续使用当前生效版本增量分析，不等待训练。切换新版本后，优先处理可见项和新入库项，全库建议重算在后台渐进执行。

## 6. 回归测试集合

- 人工确认、拒绝、移动和新建人物在重算前后保持不变。
- 照片端标注可被视频端使用，视频端标注也可被人物页立即使用。
- 相同照片、相同人脸实例、同一视频帧不跨训练/验证分区。
- 连续切换目录或人物时，旧加载任务被取消，目录树基本结构和已有节点不消失。
- 应用候选策略只改变建议；回滚后建议恢复，原图、索引、标签和人工归属不变。
- 指标退化时门禁阻止应用，并能定位到具体人物或困难分组。
- 取消、异常、进程退出和低磁盘空间不会留下“正在更新”假状态或半生效策略。
- 1 万、10 万人脸规模记录耗时、峰值内存、取消延迟与 UI 帧响应；前台操作不得被训练或重算阻塞。

## 7. 实施顺序与完成定义

推荐顺序：`FACE-EVAL-001` → `FACE-EVAL-002` → `FACE-REPORT-001` → `FACE-DETECT-001` → `FACE-CONTEXT-001` → `FACE-ADAPTER-001` → `FACE-MODEL-001`。

每个任务只有同时满足以下条件才算完成：

- 用户可观察的 UI、进度、错误和取消路径完整。
- 自动化单元、集成和桌面回归测试通过。
- 有应用前后性能与精度报告，且达到门禁。
- 数据迁移可回滚，不改变目录树基本结构，不删除原图或人工标签。
- 文档、设置说明和版本记录同步更新。

## 8. 训练部署架构决策（统一模型平台）

结论：训练执行与 GPU 资源管理放入统一模型平台；Picer 不内嵌训练框架，只负责数据治理、任务提交、结果审核和模型激活。两者通过版本化的本地 API 解耦。默认端点仅允许 `127.0.0.1`，任何远程端点都必须由用户显式启用并再次确认数据范围。

### 8.1 Picer 的职责

- 从人工确认、人工否定、移动纠错及视频人脸标注生成不可变的数据集快照。
- 只提交样本句柄和脱敏元数据；人物显示名称不作为训练特征，也不写入训练日志。
- 建立泄漏分组：同一原图、连拍组、近重复图和同一视频的全部帧只能落在同一数据分区。
- 展示任务阶段、进度、指标、错误和取消入口；训练期间 UI 与日常索引不被阻塞。
- 对候选产物执行影子评估；只有指标门禁通过且用户点击“应用”后才切换生效版本。
- 保存当前版本与上一版本，支持即时回滚；人工确认归属永远不被模型产物覆盖。

### 8.2 统一模型平台的职责

- GPU/CPU 排队、显存预算、并发限制、断点续训、失败恢复和进程隔离。
- 数据快照校验、训练/验证执行、指标计算、模型或轻量适配器的制品登记。
- 返回可验证的制品哈希、基础模型版本、训练参数、随机种子、数据快照 ID 和完整指标。
- 管理模型状态：`queued → preparing → training → evaluating → ready/failed/canceled`。
- 提供取消、状态查询、事件/进度流、制品下载或本地路径授权接口。

### 8.3 建议 API 契约

```text
POST   /api/face-training/datasets        创建并校验数据快照
POST   /api/face-training/jobs            提交训练或校准任务
GET    /api/face-training/jobs/{id}       查询状态、阶段、进度和指标
POST   /api/face-training/jobs/{id}/cancel
GET    /api/face-training/artifacts/{id}  获取制品清单、哈希和兼容信息
```

首期任务类型应是 `prototype-calibration` 和 `embedding-adapter`，而不是直接微调完整 SFace 主干。只有轻量适配器在冻结验证集上仍无法达到目标时，才进入基础模型替换或微调评审。

### 8.4 科学可行性与顺序

1. 先做现有 SFace 向量上的多原型、人物自适应阈值和困难负样本校准；数据需求低、可解释且容易回滚。
2. 样本充足后训练冻结主干上的小型度量适配器，使用对比损失或角度间隔目标；按人物和内容组严格拆分训练/验证集。
3. 不建议直接用少量家庭照片微调整个识别主干：容易记忆背景、年龄段或拍摄设备，造成过拟合和灾难性遗忘。
4. 评估必须同时报告宏平均召回、错误接受率、错误拒绝率、未知人物拒识率及困难分组指标，不能只看总体准确率。

## 9. 路线图启动前提核对（2026-09-04）

### 9.1 已具备的基础

- Picer 已记录人工确认、拒绝、移动、新建人物以及视频人物标注。
- 已具备正样本、排他负样本、训练快照提交和本地统一模型平台的基础接口。
- 已实现 embedding adapter 原型训练、制品保存、应用、版本切换和回滚。
- 人脸推荐引擎能够读取当前生效的 adapter；人工归属不会被自动重算覆盖。
- 已有训练、构建和部分人脸/视频回归测试，数据目录和模型目录按 D 盘规划。

### 9.2 启动第一阶段前必须补齐

1. **不可变评测快照**：增加训练集/验证集快照，保存随机种子、数据版本、SFace 版本、adapter 版本和防泄漏分组。相同原图、连拍组、近重复文件及同一视频的关键帧必须落在同一分区。
2. **评测指标与门禁**：实现人物级 Precision、Recall、FAR、FRR、未知人物拒识率，以及侧脸、小脸、逆光、儿童、旧照片等困难分组指标；新策略劣化时自动阻止应用。
3. **平台正式化**：完成 `/datasets`、`/jobs`、`/artifacts` 的正式部署、鉴权、进度、取消、失败恢复、版本兼容和制品哈希校验，并完成 Picer 联调。
4. **运行时确认**：确认 SFace/YuNet 模型文件版本哈希、GPU/CPU 和显存预算；确认 Qwen3-VL、Qwen3-ASR-1.7B 和中文 TTS 实际可启动，不能只存在配置项。
5. **音频与全双工验收**：Qwen3-ASR-1.7B 需与 Whisper 完成真实视频对照；中文 TTS、播放时持续监听、用户插话取消和当前 Agent 轮次取消已有基础实现；WebRTC AEC3、真实设备验收和抗回声质量属于外部环境验收。
6. **数据规模与独立验证集**：每个主要人物应具备足量正样本和排他负样本，并保留未参与调参的独立验证数据。

### 9.3 当前阶段边界

当前可以启动“评测快照和新旧策略对比”阶段；在评测门禁、独立验证集和平台正式化完成前，不得直接进行完整 SFace 主干训练或替换 YuNet/SFace 权重。现有 adapter 仅作为可解释、可回滚的过渡方案。

### 9.4 推荐实施顺序

`FACE-EVAL-001 → FACE-EVAL-002 → FACE-REPORT-001 → FACE-ADAPTER-001 → FACE-DETECT-001 → FACE-MODEL-001`

设计依据包括 ArcFace 的角度间隔度量学习、AdaFace 对低质量人脸的质量自适应思想，以及当前 SFace 向量接口。它们支持“先优化决策层和轻量适配器，再考虑完整主干训练”的路线。

### 8.5 2026-09-03 首期实现状态

- 统一模型平台已实现上述数据集、任务、取消和制品 API，以及持久化队列状态和原型/阈值校准器。
- Picer 已实现脱敏快照、后台提交/轮询/取消、指标门禁、自动应用和上一版本回滚；设置页可配置训练 API 根地址。
- 提交内容不含人物姓名和文件路径，仅含数值人物/人脸标识、SFace 模型版本、向量、正负标签与泄漏组。
- 训练制品按版本写入 `face_training_artifacts`，人物策略写入 `face_person_policies`；建议引擎只读取当前已应用策略，人工归属不被重写。
- 首期制品是冻结 SFace 上的原型与阈值策略，不宣称更新 SFace 权重。更严格的连拍/近重复/整段视频泄漏分组和独立影子验证仍是进入度量适配器训练前的强制门槛。
