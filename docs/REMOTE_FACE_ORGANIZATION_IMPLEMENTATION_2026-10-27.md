# 远程人物整理与候选组身份回传

## 问题

远程 GUI 的“自动归类”“候选分组”原来直接修改 GUI 镜像。队列触发同步并不等于这些派生分组已经上传到权威索引；镜像刷新后结果可能丢失。已有来源创建的候选组可以回传，但服务端新建的候选组没有本地身份，来源端无法接收成员。

## 实现

- 远程 GUI 的推荐、候选分组和自动归类调用 `POST /api/service/v1/faces/organize`，在照片空间数据库执行，成功后刷新镜像。本地模式继续使用本机索引。只在明确选中的向量模型空间内计算，保持人工确认身份。
- 远程“拆出候选人脸”调用服务端接口，校验当前组和镜像 epoch，成功后刷新镜像；重复请求保持幂等，本地操作触发同步。不同来源的自动候选组保持隔离，同一模型的重复照片去重也按来源进行。
- 请求携带镜像 epoch；旧镜像返回冲突。服务端按空间限制同一时间只执行一个人物整理请求，避免重复计算。执行中取消不会撤销已保存的派生结果，人工决定保持不变。
- 元数据协议 14 增加远程候选组身份接纳。服务端只提供与授权来源照片有关的组信息；本机分配自己的 ID，通过既有持久化接纳回执确认，随后按来源映射成员。分组名称、模型及成员没有跨来源复制授权的扩张。
- 新增 schema90：候选成员变化使身份发现检查点失效。旧客户端未声明协议 14 时，不会收到新身份类型。
- 推荐匹配和视频匹配也按来源筛选确认样本、拒绝样本与人物训练数据，来源专属适配器不进入其他来源；用户明确应用的空间级模型仍是空间运行配置。归属存在歧义的照片暂缓自动分组。
- 推荐写入将拒绝、人工确认及同照片检查与赋值放在同一事务内。远程推荐和候选组提交在写入事务中再次核对 epoch，索引清除或空间重置后的旧计算不能写回。长计算支持取消，不提前释放仍可能被请求使用的并发门。
